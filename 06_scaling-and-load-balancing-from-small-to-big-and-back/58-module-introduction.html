1) Big picture: Why this module exists 🧠

You already learned EC2 (virtual servers) and VPCs (networking + subnets). Those topics become much more practical when you run more than one EC2 instance.

This section introduces two common real-world problems:

  • 📈 Traffic changes: sometimes you have few users, sometimes many (peaks and drops).
  • 🧯 Instance failure: one server can crash or become slow, but your app should keep working.

The solution patterns are: dynamic scaling (add/remove instances) and load balancing (spread traffic).

2) Core ideas you must understand ✅

Key mindset: Build architectures that can go “from small to big and back” without manual babysitting. 🔁

2.1 Dynamic Scaling (Auto Scaling) 📊

Meaning: Automatically increase the number of instances when demand is high and decrease them when demand is low.

  • 🙂 Low traffic → fewer instances → lower cost
  • 🚀 High traffic → more instances → better performance

Beginner analogy: Think of adding cashiers when the line is long, and closing extra counters when it’s quiet.

2.2 Load Balancing ⚖️

Meaning: Put a “traffic distributor” in front of multiple instances so requests are shared.

  • 🧭 Routes user requests to healthy instances
  • 🛡️ Helps with fault tolerance (if one instance fails, others still serve)
  • 📉 Smooths spikes (no single instance gets overwhelmed)

Beginner analogy: A receptionist assigning customers to available staff instead of everyone crowding one person.

3) Simple examples (beginner-friendly) 🧩

Example A: One instance website (problem) 😬

  • You host a website on 1 EC2 instance.
  • If traffic spikes → site becomes slow or crashes.
  • If the instance fails → website is down.

Example B: Multiple instances + Load Balancer (better) ✅

  • Run 2–10 EC2 instances with the same app.
  • Put a load balancer in front.
  • Users talk to the load balancer, not directly to instances.

Example C: Dynamic scaling (best for variable traffic) 🌊

  • During peak hours, automatically scale out (add instances).
  • During off-peak, automatically scale in (remove instances).
  • This keeps performance stable while controlling costs.
Important idea: Load balancing and scaling are usually used together. 🤝
Load balancer = distributes traffic, auto scaling = changes how many targets exist.

4) AWS features you’ll see next (names to remember) 🧷

  • 🧱 EC2 Auto Scaling — automatically adds/removes EC2 instances based on demand
  • ⚖️ Elastic Load Balancing (ELB) — distributes incoming traffic across multiple targets

In the next lessons, you’ll focus on what these are and what problems they solve (you don’t need deep hands-on skills for CLF-C02).

5) Exam-ready notes (CLF-C02) 📝

  • ✅ Know the purpose of scaling: performance + cost optimization.
  • ✅ Know the purpose of load balancing: distribute traffic + improve availability.
  • ✅ Recognize service names: EC2 Auto Scaling and Elastic Load Balancing.
  • ✅ Understand the “multiple instances” motivation: one server is a single point of failure.
