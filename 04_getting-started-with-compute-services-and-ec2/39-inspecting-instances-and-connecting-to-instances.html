39 — Inspecting Instances & Connecting to Instances 🔍🔌

Reviewer / Study Guide (single-column, A4 print-ready)

🎯 Goal of This Lecture

After launching an EC2 instance, you should know how to: (1) inspect its status and details, (2) connect to it (SSH / EC2 Instance Connect / Session Manager), and (3) stop vs terminate (and optionally hibernate).

📍 Where to Inspect an Instance

In the EC2 console, open the Instances dashboard:

  • Go to the EC2 Service page → click Instances (either on the page or in the left sidebar)
  • Select an instance to view details

What you can see there 🧾

  • Status (running / stopped / terminated, etc.)
  • Monitoring (e.g., CPU utilization) 📈
  • Public DNS (auto-assigned in many setups) 🌐
  • Public IPv4 address (often auto-assigned) 🧭

Practical note ✅ Public DNS / Public IP are used to reach the instance from the internet (e.g., HTTP requests) only if the network rules allow it and your workload (like a web server) is actually running.

🔌 How to Connect to an EC2 Instance

Select the instance and click Connect. AWS shows multiple connection options.

  1. Option A: Local SSH Client (classic) 💻🔑

    You connect from your computer using SSH. This typically requires a key pair created during launch. AWS provides step-by-step instructions for your OS in the documentation.

    Requirement ⚠️ No key pair = SSH auth won’t work (you need the private key file to authenticate).

  2. Option B: EC2 Instance Connect (browser-based) 🌐🧑‍💻

    A convenient approach: connect directly from the browser without managing a key pair. You get a terminal session inside the console.

    Typical setup ✅ Ensure SSH traffic is allowed by the instance’s Security Group. Then you can click Connect and get a shell session in the browser.

  3. Option C: Session Manager (advanced) 🛠️

    Session Manager is a more advanced AWS option for managing fleets of instances. At Cloud Practitioner level, you mainly need to know it exists as a managed way to connect/manage.

What you do after connecting 🧰

Once connected, you run commands on the remote machine: install software, start services (e.g., a web server), download code, run scripts, and so on.

🧯 Stop vs Terminate vs Hibernate

When you’re done with an instance, select it → Instance state.

Key differences (exam-friendly) ✅

  • Stop ⏸️ — Instance is not running (typically no compute charges), but it still exists and can be restarted. Installed software remains.
  • Terminate 🗑️ — Instance is deleted and cannot be restarted. Use this when you’re sure you don’t need it anymore.
  • Hibernate 💤 — Like stop, but also saves the in-memory state (RAM). Must be enabled during instance launch.

Cost & hygiene ⚠️ Don’t accumulate many stopped instances without a reason. Typically, terminate what you no longer need.
