✅ Big Picture Recap

This section introduced AWS compute services and focused heavily on EC2 (Elastic Compute Cloud). You should now understand what EC2 is, how instances work at a high level, and which supporting concepts (AMI, instance type, security groups, connectivity, pricing models) matter.

Exam mindset 🎯 Know what each compute option is for, and when to choose it.

☁️ Compute Services You Met

EC2 — Elastic Compute Cloud 🖥️

Fully customizable virtual servers (instances). You choose OS, size, networking, and what software runs.

ECS / EKS — Containers 📦

For running containerized workloads. Think “deploy container packages” instead of managing a full VM. (EKS is Kubernetes-based; details are not required at CLF level.)

Lambda — Serverless ⚡

Run code without managing servers. You provide code + trigger conditions; AWS manages infrastructure and scaling.

Simple memory aid ✅ EC2 = server you manage • ECS/EKS = containers • Lambda = code-only execution.

🧩 EC2 Core Concepts (Must-Know)

  • Instance = a virtual server (AWS calls it an “EC2 instance”).
  • Virtualization: An instance is typically a slice of a powerful physical machine.
  • Isolation: Instances are isolated from each other; you get dedicated allocated resources.
  • Region: EC2 is a regional service — you choose where it runs (affects price, latency, compliance).

🧱 Launch Configuration Checklist

When launching an EC2 instance, you made choices like these:

  • AMI (Amazon Machine Image) 🧰 — base OS + preinstalled software
  • Instance type 🧠 — hardware profile (CPU, RAM, network, etc.)
  • Storage 💾 — disk size/type attached to the instance
  • Security group 🧱 — firewall rules (e.g., allow SSH, allow HTTP/HTTPS)

Beginner example 👶 If you want a simple website server: allow HTTP (80) and maybe HTTPS (443). If you need remote admin: allow SSH (22).

🔑 Connecting & Managing Instances

  • SSH 🔐 — standard way to connect from your computer (usually needs a key pair).
  • EC2 Instance Connect 🌐 — browser-based terminal option (convenient for quick demos).
  • User Data 🧾 — startup script that runs on first boot (e.g., auto-install a web server).

Why User Data matters ✅ You can automate setup so you don’t need to log in just to install packages and start services.

🛑 Stop vs Terminate (Cost + Lifecycle)

  • Stop ⏸️ — instance is powered off; you can restart later (compute charges stop; other charges may still apply depending on resources).
  • Terminate 🗑️ — instance is deleted; use when you’re done for good.
  • Hibernate 💤 — advanced option (like stop, but preserves memory state) if enabled.

Cost habit ⚠️ Don’t leave demo instances running. Always stop/terminate after labs.

💸 EC2 Pricing Models You Learned

On-Demand ⏱️

Default. Pay for what you use. Flexible, no commitment.

Spot ⚡

Discounted spare capacity, but can be interrupted. Best for restartable jobs.

Savings Plans 📉

Discount for committing to compute usage (often 1–3 years). More predictable workloads.

Reserved Instances 🧾

Commit to specific instance attributes for discount (less flexible than Savings Plans).

Exam phrase ✅ “Trade flexibility for discount.”
