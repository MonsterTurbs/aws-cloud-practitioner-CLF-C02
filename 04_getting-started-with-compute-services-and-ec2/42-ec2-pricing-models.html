42 — EC2 Pricing Models 💸🖥️

Reviewer / Study Guide (single-column, A4 print-ready)

🎯 What You Need to Know (Exam-Level)

AWS EC2 offers multiple pricing / purchasing options. For the Cloud Practitioner exam, focus on the purpose of each model, the trade-offs, and which workloads fit each option.

Rule of thumb ✅ More flexibility usually means less discount. More commitment usually means more discount.

🧠 Model #1: On-Demand Instances (Default) ⏱️

On-Demand is the default option when you launch an instance normally. You pay for usage (commonly per second/minute/hour depending on instance + OS), and you stop paying when you stop/terminate.

Why it’s popular 👍

  • Highest flexibility — start/stop anytime
  • No long-term commitment
  • Great for short-term, unknown, or spiky workloads

Reminder ⚠️ Pricing depends on Region, instance type, OS, and other factors. Always check the EC2 pricing page for exact numbers.

🧠 Model #2: Spot Instances ⚡💰

Spot Instances let you use AWS spare capacity at a discount. The trade-off: AWS can reclaim / interrupt the instance when capacity is needed.

Best fit ✅

  • Batch jobs / short utility tasks
  • Workloads that are interruptible and can be restarted
  • Big cost savings when you can tolerate interruptions

Not ideal ⚠️ for always-on workloads (e.g., typical web servers) because interruptions can cause downtime.

Exam phrase ✅ “Spare capacity, discounted, but can be interrupted.”

🧠 Model #3: Savings Plans 📉📅

Savings Plans provide discounts when you commit to a certain amount of compute usage over time (commonly 1 year or 3 years). You buy these via the Billing / Cost Management area.

Key idea 🔒➡️💰

  • You commit to a steady level of compute usage (a “spend/usage commitment”)
  • You get a discount because you commit long-term
  • You can still use more (extra usage can be On-Demand), but the committed part is paid anyway

Best fit ✅ Predictable, long-running workloads where you know you’ll keep using compute for months/years.

🧠 Model #4: Reserved Instances (RIs) 🧾🗓️

Reserved Instances are similar to Savings Plans in that they trade commitment for discount, but the commitment is tied more directly to specific instance attributes (like instance type/config).

How to think about it 🧩

  • RIs: commit to a more specific instance configuration
  • Savings Plans: usually more flexible than RIs (commitment is less tied to a single type)

Exam takeaway ✅ Both are “commitment for discount,” but Savings Plans are often described as more flexible.

📌 Quick Comparison Cheat Sheet

On-Demand ⏱️

  • Most flexible
  • No commitment
  • No special discount
  • Good for unknown / short-term usage

Spot ⚡

  • Cheaper (discounted spare capacity)
  • Can be interrupted
  • Good for batch/interruptible workloads

Savings Plans 📉

  • Discount for 1–3 year commitment
  • Often more flexible than RIs
  • Good for steady usage

Reserved Instances 🧾

  • Discount for 1–3 year commitment
  • More tied to specific instance attributes
  • Good for predictable instance needs

🗂️ Key Terms to Remember

On-Demand Spot (interruptible) Savings Plans Reserved Instances Region-based pricing Instance type
