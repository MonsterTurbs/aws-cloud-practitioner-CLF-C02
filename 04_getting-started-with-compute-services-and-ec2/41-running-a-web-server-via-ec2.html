41 — Running a Web Server via EC2 🌐🖥️

Reviewer / Study Guide (single-column, A4 print-ready)

🎯 Goal of This Lecture

This is a hands-on style example showing how an EC2 instance can host a simple website. The key idea is: launch an instance, allow HTTP traffic, and use User Data to automatically install & start a web server at boot.

🧱 Setup Overview (What the Instructor Does)

Instance configuration summary 🧾

  • Name: none (optional)
  • AMI: default Amazon Linux (beginner-friendly starting point) 🐧
  • Instance type: t2.micro (Free Tier eligible in many setups) 🆓
  • Key pair: none (because SSH won’t be used for setup) 🔑🚫
  • Network / Security Group: allow SSH (optional here) + allow HTTP from the internet 🌍➡️🖥️
  • Storage: keep defaults ✅
  • Advanced details: add User Data script ⚙️

Main learning ✅ A Security Group acts like a firewall. If you want the public internet to access your web server, you must allow inbound HTTP (port 80).

⚙️ User Data: The “Auto-Setup at Startup” Feature

User Data is a place where you can paste commands that run automatically after the instance finishes starting. This is useful because you can set up your workload without manually connecting via SSH.

What the User Data script typically does 🧰

  • Installs a web server (e.g., Apache / NGINX) 📦
  • Starts the web server service ▶️
  • Creates a basic web page file (HTML) 📝
  • The web server serves that file to anyone who visits the instance over HTTP 🌐

Important ⚠️ User Data commands may take a short time to finish. The website might not load immediately after the instance becomes “running”.

🌐 How You Access the Website

After the instance is running and the User Data script has completed, you can use the instance’s: Public DNS or Public IPv4 to open the website in a browser.

What you do (conceptually) 🔎

  • Go to EC2 → Instances → select your instance
  • Copy Public IPv4 or Public DNS
  • Open it in a browser using HTTP (e.g., http://<public-ip>)

Success indicator ✅ You see a simple webpage (generated by the User Data script). That’s a website hosted by your EC2 instance.

🧹 Clean Up: Stop vs Terminate

Since this is a demo, the instructor terminates the instance after testing.

  • Stop ⏸️ — can be started again later
  • Terminate 🗑️ — deletes the instance (common for demos you no longer need)

Cost reminder ⚠️ Leaving instances running can incur costs. For practice, terminate what you don’t need.

🧠 IP Address & DNS Notes (High Level)

By default, public IP addresses can change when you stop/start or recreate an instance. You can later add your own domain name and also use features that provide more stable addressing.

Keep in mind ✅ For now, it’s enough to remember: Public DNS / Public IP can be used to reach a public workload like a website (when allowed by security rules).
