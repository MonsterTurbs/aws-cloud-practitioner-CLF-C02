38 — Configuring & Launching EC2 Instances 🚀🖥️

Reviewer / Study Guide (single-column, A4 print-ready)

🎯 Goal of This Lecture

EC2 can look overwhelming at first because the console shows many options. The good news: launching an instance is mostly a simple wizard. Your job is to pick a few key settings: Region, AMI, Instance Type, Key Pair, Security Group, and Storage.

Key idea ✅ EC2 is a regional service — you choose where (which Region) your instance runs.

🧭 Where to Launch an Instance in the Console

You can start the wizard from the EC2 console in a few common ways:

  • Click Launch instance on the EC2 dashboard
  • Go to Instances → click Launch instances

Beginner tip 💡

If the page feels overwhelming, focus only on the wizard fields that affect where, what OS/software, how powerful, and who can connect.

🧩 The Launch Wizard: What You Configure

  1. 1) Choose a Region 🌍

    Region selection affects pricing, latency (distance to users), legal requirements (data residency), and service availability. EC2 is regional, so your instance physically runs in the Region you pick.

    Example ✅ Many demos use us-east-1 (N. Virginia) since it’s commonly cost-effective, but your best Region depends on your use case.

  2. 2) Name (Optional) 🏷️

    Naming helps identify instances (e.g., in the console and sometimes when reviewing costs). Even if optional, it’s a good habit.

  3. 3) Choose an AMI (Amazon Machine Image) 🧰

    An AMI is a base image: it includes the operating system and may include pre-installed tools/software.

    • Examples: Amazon Linux, Ubuntu, Windows Server 🐧🪟
    • Some AMIs are Free Tier eligible (good for practice)
    • Marketplace/Community AMIs may be free or paid 🛒

    Custom AMIs (extra) 🧱

    You can create your own AMIs (e.g., snapshot a configured instance) or use EC2 Image Builder to automate building/updating images. Cloud Practitioner note: you don’t need to build AMIs for the exam, but knowing they exist is helpful.

  4. 4) Choose an Instance Type (Hardware Profile) ⚙️

    Instance type defines the compute capacity: CPU, memory, sometimes storage options, and network performance.

    • Different types are optimized for different workloads (compute-heavy vs memory-heavy, etc.)
    • Free Tier practice often uses t2.micro or similar 🆓

    Exam mindset ✅ You don’t memorize all instance types—just know that different types/families exist and they’re optimized for different workloads.

  5. 5) Key Pair (for SSH access) 🔑

    If you want to connect to the instance from your machine (commonly via SSH), you use a key pair. AWS will download a key file that you keep safely.

    • Create a new key pair or choose an existing one
    • You can proceed without a key pair if you won’t connect directly (not recommended for most real use cases)

    Security ⚠️ Treat your private key file like a password. Don’t share it and don’t commit it to Git.

  6. 6) Network Settings + Security Group (Firewall) 🧱🔥

    Network settings include your instance’s firewall rules. In EC2, firewall rules are managed via a Security Group.

    • Allow SSH (port 22) if you need command-line access
    • Allow HTTP (80) / HTTPS (443) if hosting a web server 🌐
    • Security groups can be reused across multiple instances ♻️

    Best practice ✅ Only open the ports you truly need (least exposure). Reuse a good Security Group setup when launching similar instances.

  7. 7) Storage 💾

    You can attach storage to the instance (often the defaults are fine for learning and may be Free Tier eligible). Advanced options give more control over size and type.

  8. 8) Advanced Settings (Optional) 🧠

    Many additional settings exist for specific use cases. For Cloud Practitioner level, you usually don’t need these details.

  9. 9) Review & Launch ✅

    After reviewing settings, click Launch instance. AWS allocates capacity in your chosen Region and applies the AMI + configuration. When it’s ready, you can connect and run your workload.

💡 Mini Scenario (Putting It Together)

Example: Simple practice web server 🌐

  • Region: closest to users (or cheap for practice) 🌍
  • AMI: Amazon Linux (Free Tier eligible) 🐧
  • Instance Type: t2.micro (practice) ⚙️
  • Security Group: allow HTTP/HTTPS + optionally SSH 🔥
  • Storage: default (practice) 💾

🧾 Cost & Safety Reminders

Even when using Free Tier, always double-check limits and pricing per Region.

Cost safety ⚠️ Running instances can generate charges if you exceed Free Tier quotas or pick non-free resources. Regularly check Billing / Budgets.

Practice habit ✅ After testing, stop/terminate resources you don’t need so you don’t pay for idle usage.
