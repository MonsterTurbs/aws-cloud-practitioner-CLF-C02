🎯 What are Security Groups?

When you launch an EC2 instance, you choose the VPC and subnet it belongs to (this affects connectivity), and you also choose a Security Group (this affects what traffic is allowed once it reaches the instance).

💡 Quick mental model

  • VPC/Subnet = “Can the instance be connected to the internet at all?” 🌐
  • Security Group = “If traffic reaches the instance, is it allowed?” 🚪

Even if you allow HTTP in the Security Group, a private subnet can still prevent internet users from reaching the instance.

🧱 Inbound vs Outbound Rules

⬇️ Inbound traffic (incoming)

These rules control what requests are allowed to reach your instance. Example: allow HTTP so users can open your website.

⬆️ Outbound traffic (outgoing)

These rules control what requests your instance is allowed to send out. By default, outbound traffic is typically open so the instance can download updates, packages, etc.

In practice, you usually tighten inbound rules more than outbound rules, because you do not want random, unexpected internet traffic hitting your server. 🔒

🔌 Ports, Protocols, and “Traffic Type”

In the launch wizard, when you pick a “traffic type” (like SSH or HTTP), you are effectively selecting a port to control. Different network requests go to different ports.

  • 🧑‍💻 SSH = remote command-line access (commonly port 22)
  • 🌍 HTTP = website traffic (commonly port 80)
  • 🔐 HTTPS = secure website traffic (commonly port 443)
  • ⚙️ Custom = you manually type the port (useful for special apps)

You do not need to memorize port numbers for the exam unless your course explicitly requires it—focus on the concept: “traffic type” maps to “port control.”

🧭 Source IPs and CIDR (Who is allowed?)

Security group rules also define where the traffic can come from (source IP addresses). This is where CIDR notation appears.

🧠 Example: Allow SSH from your laptop only

Instead of allowing SSH “from anywhere”, choose My IP so only your current public IP is allowed. That means: SSH requests from other places will be blocked. ✅

If the CIDR ends with /32, it usually represents a single IP address (all bits locked).

🧩 Why is this important?

Because opening admin access (like SSH) to the whole internet is risky. Best practice is to allow it only from trusted IPs (your office/VPN/your machine). 🔐

♻️ Reusing and Managing Security Groups

You do not need to create a new security group every time. You can reuse an existing one when launching new instances.

  • ✅ In the EC2 launch wizard, select an existing security group.
  • 🧰 Or manage them directly in the EC2 console: scroll to Security Groups → view, create, or delete.

🧯 Practical tip

Create “standard” security groups for common roles:

  • 🌐 Web Server SG: allow HTTP/HTTPS inbound
  • 🧑‍💻 Admin SG: allow SSH inbound from trusted IP(s) only
  • 🗄️ Database SG: allow database port inbound only from your web server SG (not from the internet)

🧪 Reachability Analyzer

AWS also provides a Reachability Analyzer tool. It is useful when you have more complex networking/security group rules and want to verify whether certain requests could reach an instance.

🧭 What it helps with

  • 🔎 “Can traffic from source X reach instance Y?”
  • 🧩 Debugging why a connection fails (misconfigured rules, wrong source, etc.)

📝 Mini Reviewer (Exam-Style Reminders)

  • ✅ Security groups are attached to EC2 instances and act like a firewall.
  • ⬇️ Inbound rules are usually stricter than outbound.
  • 🔌 Picking SSH/HTTP in the wizard is mainly selecting a port to control.
  • 🧾 CIDR controls the source range. /32 commonly means a single IP.
  • ♻️ You can reuse security groups and manage them in the EC2 console.
  • 🧪 Reachability Analyzer helps validate whether a request can reach a target instance.

✅ Quick Self-Test

1) If you want SSH access for yourself only, what should you set as the source?

Use My IP (or a trusted CIDR range), not “Anywhere.” 🧑‍💻

2) What’s the difference between subnet type and security group rules?

Subnet affects connectivity to the internet; security groups affect which traffic is allowed once it reaches the instance. 🌐🚪

3) What is the default trend for outbound traffic?

Outbound is commonly allowed broadly so instances can send requests (updates/downloads), while inbound is restricted. ⬆️✅
