Big Picture: Why VPC exists 🌍

A VPC (Virtual Private Cloud) is AWS’s way of letting you build a private network in the cloud. It’s not just “organization” for EC2 instances — it’s how you control networking at a higher level.

Easy mental model 🧩:

  • VPC = your private “network boundary” inside a region
  • Subnets = smaller network segments inside the VPC
  • Route tables = “where should traffic go?” rules
  • IGW / NAT = connectivity to the internet (public vs private behavior)

⚠️ Real-world note: Many AWS services can live inside a VPC (not only EC2). EC2 is just the most common first example.

Core Terms You Must Recognize ✅

VPC = a regional private network (one default VPC per region; you can create more)
Subnet = a portion of the VPC network, placed in a single Availability Zone
Route Table = routing rules that decide where packets go (to IGW, NAT, local, etc.)
Internet Gateway (IGW) = enables two-way internet connectivity for subnets that route to it
NAT Gateway = enables outbound-only internet access for private subnets (no inbound from internet)
🧭 VPC is per region 🏢 Subnet is per AZ 🛣️ Route tables decide connectivity 🌐 IGW = inbound + outbound 🚪 NAT = outbound only

Public vs Private Subnets (Connectivity) ⛓️

The key idea: Public vs private subnet is about technical connectivity — not about “allow SSH but block HTTP.”

Rule of thumb ✅:

  • Public Subnet = has a route to an Internet Gateway (instances can be reachable from the internet if other settings allow it)
  • Private Subnet = no route to the Internet Gateway (internet cannot reach those instances)
  • Private subnet with NAT = instances can download updates (outbound) but still cannot be reached inbound from the internet

Beginner Example 🧪

  • EC2 #1 (Web Server) in a public subnet → users on the internet can access it (if Security Group allows).
  • EC2 #2 (Database) in a private subnet → only the web server can talk to it (you restrict via Security Group rules).

⛔ Common confusion: Security Groups decide what traffic is allowed once traffic can reach the instance. Subnets decide whether the internet can reach the subnet at all.

CIDR & Private IP Ranges (Beginner view) ✅

A VPC is assigned a CIDR block (sometimes spelled “CIDR,” pronounced like “cider” 🍎), which is a range of IP addresses used inside that VPC.

What “/16” means (simple) 🧠:

  • “/16” means 16 bits are fixed → you get a large range (about ~65k addresses).
  • Higher number after “/” = smaller range (e.g., /24 ≈ 256 addresses).
  • 0.0.0.0/0 means “everyone on the internet” (all IP addresses).

Subnet allocation idea 🧩

Subnets get “slices” of the VPC CIDR block. Example: if the VPC range is limited, you must allocate enough addresses per subnet.

✅ For CLF-C02: You typically just need to recognize that CIDR defines a range used for private networking inside a VPC.

Public IP vs Elastic IP ✅

Two IP types you’ll see often

  • Private IP 🏠: used inside the VPC for instance-to-instance communication.
  • Public IP 🌐: used from the internet to reach an instance (only meaningful in a public subnet + allowed by Security Group).

Elastic IP (EIP) 📍 = a stable public IP you allocate to your account and then assign to an instance.

  • Auto-assigned public IPs can change when you stop/start instances.
  • Elastic IPs are limited (scarce) and may incur charges when unused.
  • Often, you use DNS / domain names instead of relying on IP stability for websites.

✅ Exam takeaway: Know that Elastic IP = stable public IP (manual allocation/assignment), but use with care.

Traffic Controls: Security Groups vs NACLs vs Subnets ✅

One-liner differences (memorize-friendly) 🧾

Security Group 🧱 = instance-level firewall (recommended). Stateful: if request allowed, response allowed.
NACL 🧾 = subnet-level rules. Stateless: must allow both request and response explicitly.
Public/Private Subnet 🔌 = connectivity decision (can the internet reach the subnet at all?).

Beginner example: “Only my laptop can SSH” 🔐

  • Put the instance in a public subnet (so it can be reached).
  • In the Security Group, allow SSH (port 22) from My IP only.
  • Everything else inbound stays blocked.

⛔ Common confusion: “Public subnet” does not automatically mean “open to the world.” You still need Security Group rules.

Connecting VPCs: Peering vs Transit Gateway ⚠️

If you end up with multiple VPCs (different teams, acquisitions, separation of environments), you may need them to communicate.

VPC Peering 🔗 = connect two VPCs directly (point-to-point).
Transit Gateway 🚉 = hub to connect many VPCs (more scalable for multi-VPC setups).

✅ For CLF-C02: Recognize the names and the high-level purpose. Setup details are not required.

VPC Endpoints & AWS PrivateLink ✅

Problem: your EC2 app in a VPC needs to talk to an AWS service (e.g., S3). By default, that can go over the public internet, which may require IGW/NAT even if you don’t want general internet access.

Solution 🛡️: Use AWS PrivateLink via VPC Endpoints so traffic can go over the AWS private network instead of the public internet.

  • Less need for internet connectivity just to use AWS services.
  • Common example mentioned in courses: S3 endpoint for private access to S3.

Simple flow (S3 example) 📦

  • Without endpoint: EC2 → internet route (IGW/NAT) → S3
  • With endpoint: EC2 → VPC endpoint → AWS private network → S3

✅ Exam takeaway: PrivateLink + VPC Endpoints = private connectivity to AWS services without using the public internet.

Quick Quiz 🧠

  1. What makes a subnet “public”?
    Answer: It has a route to an Internet Gateway (IGW) via route tables.
  2. Security group vs NACL — what’s the easiest difference?
    Answer: SG = instance-level + stateful; NACL = subnet-level + stateless.
  3. What does 0.0.0.0/0 mean?
    Answer: All IP addresses (anyone on the internet).
  4. Why not always use Elastic IP?
    Answer: Limited/scarce; can cost when unused; DNS is often better for websites.
  5. How can a private subnet get outbound internet without becoming public?
    Answer: Use a NAT Gateway (outbound-only).
  6. What feature lets your VPC talk to AWS services without public internet?
    Answer: VPC Endpoints / AWS PrivateLink.

Exam Checklist ✅

  • ✅ VPC is a regional networking construct; you can have a default VPC per region.
  • ✅ Subnets live inside a VPC and are tied to a single Availability Zone.
  • ✅ Public vs Private subnet = internet connectivity (IGW route vs no IGW route).
  • ✅ Route tables decide where traffic goes (local, IGW, NAT, etc.).
  • ✅ CIDR notation describes a range of IP addresses for private networking.
  • ✅ Private IP for internal traffic; Public IP for internet reachability.
  • ✅ Elastic IP = stable public IP (manual allocation; limited; may cost when idle).
  • ✅ Security Groups (recommended): instance-level firewall, stateful.
  • ✅ NACLs: subnet-level controls, stateless.
  • ✅ VPC Peering connects two VPCs; Transit Gateway connects many VPCs (hub).
  • ✅ VPC Endpoints / PrivateLink enable private access to AWS services (e.g., S3) without public internet.

Tip: When you’re unsure in questions, ask yourself: is the question about connectivity (subnet/IGW/NAT/routes), or about allow/deny rules (security groups/NACL)? That usually reveals the correct answer.
