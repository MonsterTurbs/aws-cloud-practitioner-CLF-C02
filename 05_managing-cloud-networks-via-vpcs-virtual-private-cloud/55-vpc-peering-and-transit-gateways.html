🎯 Big Picture (Exam‑Level)

Problem: You may end up with multiple VPCs and need them to communicate.

Solution options you should recognize:

  • VPC Peering → connect two VPCs directly (1‑to‑1). ✅
  • Transit Gateway → connect many VPCs through a central hub (hub‑and‑spoke). 🕸️

Exam mindset: you usually won’t configure these in questions, but you should identify which feature fits a scenario.

🧩 Why would you have multiple VPCs?

  • 🏢 Organization / team separation (different departments, different environments: dev/test/prod)
  • 🕰️ Historic reasons (older architecture that grew over time)
  • 🤝 Mergers / acquisitions (you bought a company and need to connect networks)

Tip: The “why not just use one VPC?” question often appears as context in explanations and scenario questions.

🔗 VPC Peering (Connect 2 VPCs)

Definition (simple): VPC Peering creates a direct network connection between two VPCs so resources can communicate (as permitted). 🙂

✅ When VPC Peering fits

  • You have exactly two VPCs that need connectivity.
  • You want a simple connection path: VPC A ↔ VPC B.
  • You want to avoid “extra infrastructure” when the setup is small.

⚠️ Common gotcha (conceptual)

  • If your environment grows to many VPCs, managing many peerings can get messy (spaghetti network 😵‍💫).

Hint: This is the exact motivation for Transit Gateway (central hub).

🕸️ Transit Gateway (Connect Many VPCs)

Definition (simple): Transit Gateway is a network hub you can attach multiple VPCs to, so they can route traffic through a central point. 🏛️

✅ When Transit Gateway fits

  • You have more than two VPCs that need to communicate.
  • You want a hub‑and‑spoke architecture (cleaner than many peerings).
  • You want to scale network connectivity as your cloud footprint grows.

🧠 Memory cue

  • Peering = “pair” (2) 👯
  • Transit Gateway = “terminal / hub” (many) 🚉

📌 Quick Comparison

Feature Best for Easy mental model
VPC Peering Connecting two VPCs Direct bridge: A ↔ B 🔗
Transit Gateway Connecting multiple VPCs Central hub: A/B/C/D → Hub → others 🕸️

Exam note: if the prompt mentions “many VPCs” or “growing network complexity,” Transit Gateway is the likely keyword.

🧪 Beginner Examples (Scenarios)

Example 1: Two VPCs (simple)

Company has:

  • VPC‑A: Web app servers
  • VPC‑B: Shared internal tools

Need: Web app reads from a tool service in VPC‑B.

Likely answer: Use VPC Peering (two VPCs). ✅

Example 2: Many VPCs (growing org)

Enterprise has separate VPCs for:

  • VPC‑Dev, VPC‑Test, VPC‑Prod
  • VPC‑SharedServices
  • VPC‑Security

Need: Controlled connectivity across many VPCs without dozens of direct peerings.

Likely answer: Use a Transit Gateway as a hub. 🕸️

🧠 Exam Tips & Keywords

  • ✅ If the question says “connect two VPCs” → think VPC Peering.
  • 🕸️ If it says “connect multiple VPCs” / “hub” / “scale connectivity” → think Transit Gateway.
  • 🙂 If it says “you don’t need the setup details” → focus on identifying the right tool, not the steps.
