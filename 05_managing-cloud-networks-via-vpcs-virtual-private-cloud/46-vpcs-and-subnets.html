46 — VPCs & Subnets 🧱🌐

Print-ready reviewer (single column, A4) • beginner-friendly notes + examples

🎯 Core idea

An AWS VPC (Virtual Private Cloud) lets you build your own virtual network in the cloud. You can place multiple resources (e.g., EC2 instances) inside it and control networking in a structured way.

Not just organization 🗂️ — VPC is not only “grouping” instances. It’s about network control (connectivity, routing, IP assignment, internet exposure).

🏗️ VPC structure: VPC → Subnets → Instances

Inside a VPC, you group resources into subnets. Subnets are where you control whether instances are public or private, and you also tie placement to Availability Zones (AZs).

VPC 🧱 (your private network in AWS)
⬇️ contains
Subnet A (in AZ-1) Public or Private
EC2 instances live here
Subnet B (in AZ-2) Public or Private
EC2 instances live here

Exam-friendly fact ✅ A subnet belongs to one Availability Zone. Instances in that subnet are launched in that AZ.

🌐 Public vs Private subnets (simple meaning)

Type What it’s for Internet connectivity
Public Subnet 🌍 Resources that must be reachable from the internet (e.g., web server) Has a route to the internet (via Internet Gateway)
Private Subnet 🔒 Resources that should not be directly reachable from the internet (e.g., database) No direct internet route (unless you add controlled outbound via NAT)

Important nuance 👇

Instances inside the same VPC can communicate with each other even if they are in different subnets. Subnets mainly control internet exposure and AZ placement.

🔌 Internet Gateway (IGW) — what it does

A public subnet becomes “public” when it can route internet traffic via an Internet Gateway. In practice, you attach an IGW to the VPC and connect specific subnets to it via routing.

Remember ✅ If you want public subnets, an Internet Gateway is required.

🕳️ NAT Gateway — private subnet outbound access

Sometimes private instances still need to download updates/patches (outbound internet). A NAT Gateway enables outgoing internet access for private subnets, without making those instances publicly reachable.

  • ✅ Private instances can send outbound requests (e.g., yum update, download packages)
  • ❌ Internet cannot initiate inbound connections to those private instances (no public IP exposure)

NAT is like: “You can go out to the internet, but the internet can’t come straight in.” 🚪➡️🌐 / 🌐🚫➡️🔒

Note ⚠️ NAT Gateway is optional. Use it only if private instances need outbound internet access.

🧠 Example scenario (classic architecture)

Public Subnet 🌍
EC2 Web Server 🖥️ (HTTP/HTTPS from Internet)
⬇️ internal DB traffic
Private Subnet 🔒
EC2 Database 🗄️ (no inbound from Internet)
⬇️ optional outbound
NAT Gateway 🕳️ (optional: patches/updates outbound)
