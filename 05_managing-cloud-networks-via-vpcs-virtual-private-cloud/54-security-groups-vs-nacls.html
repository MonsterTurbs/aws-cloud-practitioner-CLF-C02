🎯 Big Idea (What you must remember)

Think in layers:
  • 🌐 Public vs Private Subnet = Connectivity (can the internet reach it at all?)
  • 🧱 NACL = Subnet-level rules (traffic filtering for the whole subnet)
  • 🛡️ Security Group = Instance-level rules (fine-grained firewall per EC2 instance)

In the exam, you typically identify which control belongs where: instance, subnet, or connectivity design.

🛡️ Security Groups (SG) — Firewall for a single EC2 instance

Definition: Security groups are the main firewall mechanism for EC2 instances. They decide whether inbound/outbound traffic is allowed based on rules.

📌 Scope
Applies to an instance (but you can reuse one SG across multiple instances).
🧠 Stateful
If a request is allowed, the response is automatically allowed. No extra “return traffic” rule needed. 🙂
🎛️ Granularity
More fine-grained. Typical: allow SSH (22) from “My IP”, allow HTTP (80) from anywhere, etc.
Example (simple):
  • ✅ Allow HTTP (80) from 0.0.0.0/0 to serve a public website
  • ✅ Allow SSH (22) from your IP only (safer than “anywhere”)
  • ✅ Outbound: usually allow all so the server can download updates/packages
Exam cue: If the question says “instance firewall” or “stateful”, that is almost always Security Groups.

🧱 Network ACLs (NACLs) — Firewall for an entire subnet

Definition: NACLs control traffic at the subnet level. All instances inside the subnet are affected by the subnet’s NACL rules.

📌 Scope
Applies to a subnet. One NACL can be linked to multiple subnets, but one subnet can only have one NACL.
🧠 Stateless
You must allow both directions explicitly: request and response. If you allow outbound but don’t allow inbound return traffic, it breaks. 😅
🎛️ Granularity
Less fine-grained than SGs in practice; commonly used as an additional guardrail, but SGs are typically preferred.
Example (why stateless matters):
  • You allow outbound web traffic so instances can download updates. ✅
  • If you forget inbound return rules, responses may be blocked. ❌
  • Fix: add inbound rules for the expected return traffic. ✅
Exam cue: If the question says “subnet rules” or “stateless”, think NACL.

🌐 Public vs Private Subnets — Connectivity (not rule filtering)

Core difference: This is not about “allow SSH but deny HTTP”. This is about whether the internet can reach the subnet at all.

🏙️ Public Subnet
Has a route to an Internet Gateway (IGW). Instances can be internet-reachable (usually with a public IP + SG rules).
🏡 Private Subnet
No direct IGW route. Internet cannot directly reach instances. Great for databases.
🚪 NAT Gateway (optional)
Lets private-subnet instances make outgoing internet requests (e.g., updates) while still preventing direct inbound internet access.
Beginner mental model:
  • Public/Private subnet decides whether the “street” connects to your building. 🚦
  • SG/NACL decide which “doors/ports” are open once traffic arrives. 🚪

✅ Quick Check (fast recall for exams)

1) What does each one protect?

  • 🛡️ Security Group → EC2 instance (fine-grained)
  • 🧱 NACL → Subnet (broad guardrail)
  • 🌐 Public/Private subnet → Connectivity (internet reachable or not)

2) Stateful vs Stateless

  • 🙂 SG = Stateful (responses auto-allowed)
  • 😅 NACL = Stateless (must allow both request + response)

3) Typical best practice

  • ⭐ Prefer Security Groups for most instance-level control
  • 🧱 Use NACLs when you need subnet-wide rules/guardrails
  • 🏡 Put databases in private subnets (no direct internet access)

🧪 Mini Scenario (common real-world pattern)

Scenario: A web app with a public web server and a private database.

  • 🌐 Web server → Public subnet + public IP + SG allows HTTP (80)/HTTPS (443)
  • 🏡 Database → Private subnet + SG allows DB port only from the web server’s SG
  • 🚪 Optional: NAT Gateway so the database server can download patches (outbound only)
Reminder: Even if you allow HTTP in the SG, an instance in a private subnet is still not directly reachable from the internet.

📝 Key Terms to Memorize

  • Security Group = instance firewall, stateful 🛡️
  • NACL = subnet firewall, stateless 🧱
  • Public subnet = route to Internet Gateway 🌐
  • Private subnet = no direct internet route (use NAT for outbound-only) 🏡

📌 Clean One-Liner Summary

Public/Private subnet decides if traffic can reach you; SG/NACL decide what happens when it tries.
