Single-column, A4 print-ready study guide (Beginner-friendly) — VPC, subnets, security groups, and public IP assignment 🙂

🧱 Topic: VPC Networking 🖥️ Service: EC2 + VPC 🎯 Exam: AWS Cloud Practitioner (CLF-C02)

✅ What this lecture is saying (in plain words)

EC2 instances must be launched inside a VPC, and specifically inside a subnet of that VPC. When you launch an instance (EC2 Launch Wizard → Network settings), you’re not only choosing firewall rules (Security Group). You’re also choosing which VPC and which subnet will hold your instance.

Key idea 🔑
  • Subnet (Public vs Private) controls internet connectivity (can the internet reach it?).
  • Security Group controls traffic rules (what is allowed/blocked if traffic reaches it?).

🧩 Core Terms you must remember

🏠 VPC (Virtual Private Cloud)

A virtual network in AWS (regional). Your subnets and instances live inside a VPC.

Exam tip: Many resources are launched “into a VPC” even beyond EC2.

🧱 Subnet

A smaller network inside a VPC, tied to a specific Availability Zone (AZ).

  • Public subnet → has a route to the Internet Gateway (IGW).
  • Private subnet → no direct route to IGW.

🛡️ Security Group (SG)

Instance-level firewall rules. Decides which inbound/outbound traffic is allowed.

Important: SG ≠ “internet connection”. It is a traffic filter.

🌍 Public IP

A public identifier to receive requests from outside the VPC (internet). Typically used for instances in public subnets.

🧭 Where you set VPC + Subnet (EC2 Launch Wizard)

When you launch an EC2 instance and reach Network settings:

  1. You choose (or create) a Security Group (firewall).
  2. Click Edit (advanced settings) to pick the VPC and Subnet.
  3. Optionally enable Auto-assign public IP (usually for public subnet instances).
Remember 🙂
  • Your account has a default VPC per region.
  • If you created more VPCs, they will show in the VPC dropdown (still within the same region).

🌐 Public vs Private subnet: what changes?

Public Subnet ✅

  • Has a route to the Internet Gateway (IGW).
  • Instance can be reachable from the internet if:
    • It has a Public IP (or Elastic IP), and
    • The Security Group allows the inbound traffic (e.g., HTTP 80).

Private Subnet 🔒

  • No direct route to IGW.
  • Internet users cannot reach it directly (even if SG “allows HTTP”).
  • It can still talk to other instances in the VPC.
Optional: Add a NAT Gateway if you want outbound-only internet (e.g., download patches), but still block inbound internet traffic.

Example scenario 💡

  • 🖥️ Web Server in Public Subnet (needs internet traffic).
  • 🗄️ Database in Private Subnet (should not accept internet traffic).
  • Security Groups:
    • Web SG: allow inbound HTTP/HTTPS from the internet.
    • DB SG: allow inbound DB port (e.g., 3306) only from Web SG.

🔁 VPC connectivity vs Security Group rules

If instances are in the same VPC, they can usually communicate across subnets by default. That’s the network-level connectivity.

Two layers to remember 🧠
  1. Connectivity (network path): Subnet routing / VPC route tables decide whether traffic can reach the target at all.
  2. Permission (traffic allowed): Security Group decides whether the instance accepts/blocks that traffic.

So even if two instances are “technically reachable” within a VPC, your Security Group can still block the traffic. Example: If SG blocks HTTP, then no HTTP requests will be accepted — even though the network path exists.

📌 Public IP assignment (why it matters)

When launching an instance, you can enable AWS to auto-assign a public IPv4 address. This is typically needed when you want the instance to receive internet requests.

Important ⚠️
A public IP only makes sense for instances in a public subnet. If the instance is in a private subnet, internet requests still won’t reach it.

Mini example 🙂

  • Public subnet + Public IP + SG allows HTTP → website can be reached from the internet.
  • Private subnet + SG allows HTTP → still not reachable from the internet.

This lecture then leads into the next topic: IP addresses and CIDR blocks (CIDR ranges), which explain how subnets define available IP address space.

🧠 Quick Quiz (CLF-C02 style)

  1. True/False: If a Security Group allows inbound HTTP, the instance is reachable from the internet.
    Answer: False ❌. If the instance is in a private subnet (no IGW route), the internet can’t reach it.
  2. Which component primarily decides whether a subnet is public?
    Answer: Route table route to an Internet Gateway (IGW) ✅
  3. Two EC2 instances are in different subnets but the same VPC. Can they communicate?
    Answer: Typically yes ✅ (network connectivity exists by default), but Security Groups can still block specific traffic.
  4. What is the purpose of auto-assign public IP?
    Answer: Provide a public identifier so the instance can receive requests from outside the VPC (internet), assuming it’s in a public subnet and SG allows traffic.

📝 Key Takeaways (memorize this)

  • ✅ EC2 instances must be launched into a VPC and a Subnet.
  • 🌐 Public subnet (IGW route) enables internet connectivity; Private subnet does not.
  • 🛡️ Security Groups are firewalls — they do not “create” internet access; they only allow/deny traffic.
  • 📌 Public IP is usually needed for inbound internet access to a public subnet instance.
  • ➡️ Next topic: CIDR blocks explain IP address ranges for VPCs/subnets.
