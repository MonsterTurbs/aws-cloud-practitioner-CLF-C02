Beyond EC2 Instances — What Else Can Live in a VPC?

AWS CLF-C02 Reviewer • VPC concepts • Beginner-friendly notes with examples

📌 Topic: VPC / Networking 🧠 Exam Focus: “Which services can be placed in a VPC?” 🧾 Print: A4 • Single column • White background

Core Idea (Simple Definition)

✅ Key point:

EC2 instances are common “things” inside a VPC (and its subnets), but they’re not the only ones. A VPC is your private network boundary in AWS. Many services can attach to that boundary so they can:

  • Communicate privately using private IPs (inside subnets)
  • Be isolated from the public internet (private subnets) 🔒
  • Follow network rules (route tables, NACLs, security groups) 🧱

Think of a VPC like your company office network (LAN) — not everything in the company is a “PC”. You also have servers, databases, caches, load balancers, and more.

Why This Matters in Real Setups

As your architecture grows, you often separate workloads:

  • 🌐 Public subnet: internet-facing components (e.g., load balancer, web tier)
  • 🔒 Private subnet: internal components (e.g., database, cache, internal services)
Example:

A website can be reachable from the internet, but the database should not be. You put the database in a private subnet, and only allow the web tier to talk to it.

Note: “Private subnet” means “no direct internet route,” not just “blocked by firewall.”

Common AWS “Things” That Can Be Placed in a VPC

Below are the typical examples you’ll see in learning materials (and often in exam questions). You don’t need deep configuration knowledge for CLF-C02 — focus on what they are and why they sit in a VPC.

🗄️ Amazon RDS (Managed Databases) in a VPC

RDS databases are usually deployed into private subnets so they are not public-facing. Your app (EC2 / ECS / Lambda) connects to RDS via private networking.

  • Good for: MySQL, PostgreSQL, MariaDB, SQL Server, etc. (managed)
  • Why VPC: keep DB private + control who can connect 🔒

⚡ AWS Lambda (Can Run “Inside” a VPC)

Lambda is serverless, but it can be configured to access resources inside your VPC (like RDS). The key idea: Lambda can attach to subnets and use private networking.

  • Good for: event-driven tasks, APIs, background jobs
  • Why VPC: private access to DB/cache/internal services 🧩

Exam tip: serverless ≠ “no networking”. It can still use a VPC.

📦 ECS / EKS (Containers) in a VPC

Container services (ECS/EKS) run workloads that need networking. Tasks/pods often run in subnets and communicate with databases, queues, internal APIs, etc.

  • Good for: microservices, containerized apps
  • Why VPC: network segmentation + private service-to-service traffic 🔁

🧠 ElastiCache (Redis / Memcached) in a VPC

Caches are typically internal-only. You keep them private and let only your app access them.

  • Good for: speeding up reads, session storage, reducing DB load 🚀
  • Why VPC: protect cache endpoints from the internet 🔒

🎛️ Load Balancers (ELB) in a VPC

Load balancers distribute traffic to targets (like EC2 instances or containers). Internet-facing load balancers are commonly in public subnets.

  • Good for: high availability + scaling + routing
  • Why VPC: they are network entry points into your architecture 🌐

📁 EFS (Elastic File System) in a VPC

Shared network file storage that instances/containers can mount. Access happens via VPC networking (mount targets inside subnets).

  • Good for: shared files across multiple servers
  • Why VPC: controlled private file access ✅
Memory shortcut 🧠

If a service needs private IP networking or must be isolated from the internet, it likely integrates with a VPC.

Beginner-Friendly Mental Model

🏢 “Office Building” Analogy

  • VPC = the building
  • Subnets = floors (public floor vs private floors)
  • Security Group = door rules for a specific room (instance/service)
  • Route Table = directions for where traffic is allowed to go
  • Internet Gateway = main entrance to the street
  • NAT Gateway = private exit for staff (outgoing only) 🚪➡️
Common exam confusion:

A security group blocks/permits traffic when it reaches the resource. A private subnet can prevent the internet route from existing in the first place.

What You Should Remember for CLF-C02

  • ✅ EC2 is common in VPCs, but many services can run/attach inside a VPC.
  • ✅ VPC = your network boundary in AWS (subnets, routing, isolation).
  • ✅ Public subnet = has route to internet gateway (can be internet-facing).
  • ✅ Private subnet = no direct internet route (can still do outbound via NAT if configured).
  • ✅ Many managed services (like RDS, ElastiCache) are commonly placed in private subnets 🔒.

Quick Quiz (Exam-Style)

1) True or False: Only EC2 instances can be placed in a VPC.

❌ False. Many services can attach to a VPC (e.g., RDS, ECS/EKS, Lambda, load balancers, ElastiCache, EFS).

2) You want a database that is NOT reachable from the internet. Where should it go?

🔒 In a private subnet (and then allow only the app tier to connect via security groups).

3) What does a NAT Gateway primarily enable for private subnets?

➡️ Outgoing internet access (e.g., patch downloads) without allowing incoming internet traffic.

4) In one sentence: What is the purpose of a VPC?

🏗️ To provide a private, configurable network boundary for AWS resources (segmentation + routing + control).
