Public IP Addresses vs Elastic IPs (EIP) — AWS CLF-C02 Reviewer

Single-page study guide: what they are, why public IPs change, and when to use Elastic IPs. 🌐

Core idea 🎯

EC2 instances often get a public IP automatically (for internet access) and always get a private IP (for communication inside the VPC). Public IPs can change; Elastic IPs are the “stable” public IPs you can reserve.

1) Private IP vs Public IP (Know the difference)

🏠 Private IP 🌍 Public IP
  • Private IP = used for instance-to-instance communication inside the VPC only.
  • Public IP = used so the instance can be reached from the internet (only if it’s in a public subnet and networking allows it).

Memory tip: Private = “internal conversations”; Public = “internet-facing address”. 🙂

Important context 🧠

Even if an instance is in a public subnet, it still needs the right security group rules (firewall rules) to allow traffic. Public subnet = “network path exists”; Security group = “what’s allowed through the door”. 🚪

2) Why automatically assigned Public IPs are not stable

By default, AWS can assign a public IP to an instance (depending on subnet settings and whether you enabled it). But it’s not guaranteed to stay the same.

  • When you stop or terminate an instance, the automatically assigned public IP can be taken away.
  • When you restart or create a new instance, you typically cannot choose what public IP you’ll get.

This is why “raw public IP as your website address” is fragile. ⚠️

Beginner example 🧩

Scenario: You host a simple website on EC2 using an automatically assigned public IP. Day 1: Your site is reachable at 3.120.55.10 Day 2: You stop the instance to save cost → the public IP is released Day 3: You start it again → new public IP becomes 18.212.9.77 Result: Visitors who saved the old IP can’t reach the site anymore.

3) Elastic IP (EIP): the “reserved” public IP

Elastic IP = a public IP address you allocate to your AWS account and then manually attach to an EC2 instance. It is designed to be stable.

  • ✅ You control which instance uses the EIP.
  • ✅ It can remain the same even if you stop/start instances (depending on how you use it).
  • ✅ Helpful when you truly need a fixed public IP.
Where to find it 🧭

In the EC2 console, look for Elastic IP addresses (left menu), then allocate and associate.

Quick mental model 🧠

Public IP (auto) = “temporary rental address” Elastic IP (EIP) = “reserved address you keep under your name”

4) Why Elastic IPs should be used with care

  • Scarce resource 🌍: Public IPv4 addresses are limited worldwide, so AWS restricts how many EIPs you can have (per region/account).
  • Cost control 💸: AWS charges for unused Elastic IPs (to discourage hoarding). If it’s allocated but not attached/used, expect cost.

Exam framing: EIP = stable, but limited and can cost money when idle.

5) Better alternatives than using an Elastic IP (most of the time)

For websites and typical apps, you usually don’t want users typing an IP address. You want a domain name (example: example.com) that can point to your infrastructure.

  • 🌐 Domain names are human-friendly and can be updated to point to new IPs.
  • 🔁 When infrastructure changes, you update DNS/targets instead of relying on a fixed IP.
  • 🧰 AWS also provides services that help route traffic and connect systems without you managing fixed IPs for everything.

We’ll revisit domain names and DNS later (Route 53 typically appears in this area). 🙂

Practical recommendation ✅

Use an Elastic IP only when you have a clear requirement for a fixed IP (e.g., legacy allow-lists). For websites, prefer a domain name.

Quick Check for the Exam ✅

  • Private IP = used inside the VPC only.
  • Public IP (auto) = internet reachable (public subnet + rules), but can change.
  • Elastic IP = static public IP you allocate and assign; has limits and may incur cost if unused.
  • Best practice = don’t default to EIP for websites; use domain names / DNS and other AWS routing solutions where appropriate.
