31 — Understanding Roles 🎭🔐

Reviewer / Study Guide (single-column, A4 print-ready)

🎯 Lecture Goal

Understand what IAM roles are, why they exist, and what you (do and don’t) need to know for the Cloud Practitioner exam.

Big idea ✅ Roles are mainly used to grant permissions to AWS services / workloads (or temporarily to users) so they can access other AWS services.

🎭 Roles vs Users (Quick Comparison)

👤 IAM User

  • For people
  • Uses credentials (console password and/or access keys)
  • Long-term identity

🎭 IAM Role

  • Often for services / workloads
  • Typically assumed temporarily
  • Grants permissions needed to call other services

Memory hook ✅ Users = humans 🧑‍💼 • Roles = “hats” you put on temporarily 🎩

🧭 Creating Roles (High-Level)

You create roles from the Roles page in IAM. The flow is similar to creating users, but there are different role types and the setup is generally more advanced.

From the lecture ⚠️ You don’t need to create roles too often when getting started—many AWS services create roles automatically for you.

Exam scope ✅ For CLF-C02, you don’t need hands-on skill in creating roles. You mainly need to understand what roles are used for.

🧪 Example (from the lecture): Role for EC2

Example scenario: You want a role that will be used by EC2 (rented servers) so that applications running on those servers can interact with other AWS services.

  1. 1) Start the role creation wizard
  2. 2) Choose the trusted AWS service (e.g., EC2)
  3. 3) Choose which other service actions are needed (permissions)
  4. 4) Create the role and assign it to the EC2 workload later

Beginner-friendly explanation 💡

Your app on EC2 might need to read from storage, write logs, or access a database. A role is how you give that app the minimum permissions needed—without embedding long-term credentials in your code.

🧠 What You Need to Remember for the Exam

  1. 1) Roles are identities that can be assumed temporarily
  2. 2) Roles are commonly used by AWS services to access other services
  3. 3) Many services create/attach roles automatically (you often don’t build them manually)
  4. 4) You don’t need to write custom permission statements for CLF-C02

Trigger phrase ✅ If you see “service needs to access another service”, think: IAM Role.

🗂️ Key Terms (Exam Focus)

IAM Role Assume role Permissions Policy EC2 Service-to-service access

✅ Quick Self-Check

Q1: What is the main purpose of an IAM role?

A: To grant permissions that can be assumed temporarily, often by AWS services/workloads so they can access other AWS services.

Q2: Do you need to know how to create roles for the Cloud Practitioner exam?

A: No. You should understand what roles are and why they’re used, but hands-on role creation is not required.

Q3: Why might you not create roles manually often?

A: Many AWS services create roles automatically, especially for common integrations.
