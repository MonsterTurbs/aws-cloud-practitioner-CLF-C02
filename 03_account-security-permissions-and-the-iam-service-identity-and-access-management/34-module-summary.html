🎯 What This Section Covered

This section matters because securing your AWS account (and understanding AWS security concepts) is required for the exam and for real-world AWS usage.

Exam takeaway ✅ Security in AWS is not “all AWS” or “all you” — it’s shared.

🤝 Shared Responsibility Model

The Shared Responsibility Model means responsibilities are split between AWS and you.

AWS is responsible for (Security of the Cloud) 🏢

  • Physical infrastructure (data centers, hardware)
  • Internal processes and AWS-controlled systems
  • Managed services you can’t configure directly

You are responsible for (Security in the Cloud) 🧑‍💻

  • Your applications and code
  • Your workloads and configurations
  • Software you install on AWS services (patching, hardening)
  • Account protection (credentials, MFA, access control)

🛡️ Account Protection Basics

  • Use strong passwords 🔑
  • Enable MFA (for root and IAM users) 📲
  • Never share or expose credentials 🚫
  • Use IAM users instead of root for daily work 👤

Root warning ⚠️ Root has unlimited access. Use it rarely and protect it heavily.

🧩 IAM Basics (Identity & Access Management)

IAM answers two questions:

  • Who can do something? → Identities
  • What can they do? → Policies & permissions

👥 Identities (the “WHO”)

  • Users — typically for human people
  • User groups — assign permissions to many users at once
  • Roles — assumed temporarily (often by services/workloads)

🧾 Policies & Permissions (the “WHAT”)

  • Policies contain permission statements
  • Policies are attached to users, groups, or roles
  • They control whether actions are allowed or denied

🚫 Default Deny + Explicit Deny Wins

  1. 1) By default, identities have no permissions (implicit deny) 🚫
  2. 2) You attach policies to allow needed actions ✅
  3. 3) Multiple policies combine (permissions add up) 🧩
  4. 4) If there’s a conflict: Explicit Deny overrides Explicit Allow ❌

Under the hood ✅ AWS evaluates permissions when the request/command is made. Allowed actions run; denied actions are blocked.

🧠 Exam-Focused “One-Liner” Summary

AWS security is based on the Shared Responsibility Model, and access is controlled using IAM identities (users, groups, roles) plus policies that grant permissions — with default deny and explicit deny taking priority.

🗂️ Key Terms to Memorize

Shared Responsibility Model IAM User User Group Role Policy Permission Default deny Explicit deny MFA Root account
