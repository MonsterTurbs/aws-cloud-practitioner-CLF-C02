AWS Certified Cloud Practitioner (CLF-C02) — Security: A Closer Look

🧾 CloudTrail & GuardDuty — Track Account Usage (Reviewer / Study Guide)

Goal: understand how AWS helps you detect suspicious or malicious activity (including “threats from within”) using auditing and automated threat detection.

🔐 Account Protection 🕵️ Audit 🚨 Detection

1) Why this matters

Even if you already did the “basics” (IAM users, least privilege policies, MFA), there is still risk from inside the account. Example: an unhappy employee misuses permissions — or an attacker steals an employee’s credentials and uses them.

  • 🎯 You want visibility: “Who did what, and when?”
  • 🚧 You want faster detection: “Is this behavior suspicious?”
  • 🧯 You want incident investigation: “What happened after the compromise?”

2) Core idea (memorize this for the exam)

🧾 CloudTrail = “Audit Log”

CloudTrail records AWS API activity so you can see which identity performed which action. Think: a “history” of actions (create bucket, start EC2, change IAM policy, etc.).

🚨 GuardDuty = “Suspicious Activity Detector”

GuardDuty analyzes activity patterns and flags potential threats automatically. Think: “I don’t want to manually sift through logs; I want findings/alerts.”

3) CloudTrail (beginner-friendly)

What CloudTrail answers

  • 👤 Which identity (user/role) called an AWS API?
  • 🧰 What action happened? (e.g., “CreateBucket”, “RunInstances”)
  • 🕒 When did it happen?
  • 📍 From where (source IP / region / other details)?

🧠 Practical example

You discover an S3 bucket was created and made public. With CloudTrail, you can look up the event and identify who created the bucket and which changes were made (and when).

Exam-friendly phrasing: CloudTrail helps you track AWS API usage and investigate incidents by reviewing the recorded actions taken in your account.

4) GuardDuty (beginner-friendly)

What GuardDuty is for

  • 🤖 Automated detection of suspicious behavior (no manual log-search required)
  • 📌 Helps you notice issues earlier than “humans reviewing logs”
  • 🧩 Useful when there are many identities and lots of activity (common in bigger orgs)

🔎 Practical example

A user suddenly starts calling many unusual APIs, or operates in an unexpected way. GuardDuty can raise a finding so you can investigate quickly.

Exam-friendly phrasing: GuardDuty uses intelligent detection (often described as ML-based) to surface security findings about suspicious account activity.

5) How they work together (simple mental model)

  • 🧾 CloudTrail gives you the evidence trail (detailed “who/what/when”).
  • 🚨 GuardDuty gives you the warning signal (“this looks suspicious”).
  • 🕵️ When GuardDuty alerts you, you can use CloudTrail to investigate the exact actions taken.

6) Mini scenario walkthrough (beginner)

Scenario: An employee’s access keys were leaked. An attacker logs in and starts making changes.

  1. 🚨 GuardDuty flags suspicious behavior (you get a finding/alert).
  2. 🧾 You open CloudTrail and search around the time window of the finding.
  3. 🔎 You identify actions taken by the compromised identity (e.g., creating resources, changing policies).
  4. 🧯 You respond: disable/rotate keys, remove risky permissions, investigate impacted services, etc.

Key takeaway: GuardDuty helps you notice; CloudTrail helps you prove and investigate.

7) Quick Quiz ✅

  • Q1: “I need a history of AWS API calls and who did them.” → Which service? 🧾 CloudTrail
  • Q2: “I want automatic detection of suspicious account activity.” → Which service? 🚨 GuardDuty
  • Q3: “My account has lots of users/roles; manual log review is too hard.” → Which service helps? 🚨 GuardDuty
  • Q4: “An incident happened; I want to know what actions were taken after compromise.” → Which service? 🧾 CloudTrail

8) Exam tips (fast recall)

  • 🧾 CloudTrail = Audit / API activity log (“Who did what?”)
  • 🚨 GuardDuty = Threat detection / findings (“This looks suspicious!”)
  • 🧠 If the question says “track,” “audit,” “API history,” “investigate actions” → CloudTrail
  • 🧠 If it says “detect threats,” “suspicious behavior,” “alerts/findings,” “automated monitoring” → GuardDuty

End of reviewer — CloudTrail & GuardDuty (Track Account Usage).
