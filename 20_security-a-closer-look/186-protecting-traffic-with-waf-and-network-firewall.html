🛡️ Protecting Traffic in AWS: WAF, Network Firewall, Firewall Manager

Beginner-friendly study guide (CLF-C02) — how AWS blocks malicious traffic before it reaches your apps.

Single column A4 print-ready Focus: Network protection Exam-friendly takeaways
🎯 Big idea

Protecting your account (IAM) and workloads (Inspector) matters — but it’s even better if malicious traffic never reaches your application in the first place. AWS provides multiple layers of network/traffic protection, from simple port filtering to deep request inspection.

1) Quick refresher: Security Groups vs NACLs

Security Groups (SG) 🔐

  • Firewall attached to ENIs / EC2 / ALB / some services.
  • Usually described as stateful (if inbound is allowed, response is allowed out).
  • Great for: “Allow HTTPS (443) to this instance.” ✅

Network ACLs (NACL) 🧱

  • Firewall attached to a subnet (network-level guardrail).
  • Rules are evaluated in order; typically used for broad allow/deny at subnet boundary.
  • Great for: “Block a known bad IP range at the subnet.” 🚫

Important limitation: SGs/NACLs mostly decide based on IP, port, protocol — not the content inside the request.

2) AWS WAF (Web Application Firewall) 🌐🧯

What it is

AWS WAF inspects web requests (metadata + request body patterns) and blocks or allows them based on rules. It’s commonly attached to services like CloudFront (and other supported web-facing entry points).

Why WAF exists

  • SG/NACL allow traffic to a valid port, but the request can still be malicious. ⚠️
  • WAF can block requests based on what’s inside the request (headers, query string, body patterns, etc.). 🔍
🧠 What WAF can catch (classic examples)
  • SQL Injection (often written as “SQLi”) — attacker tries to inject SQL into inputs. 🧪
  • Cross-Site Scripting (XSS) — attacker injects malicious scripts into pages. 🕸️
  • Custom rules: block/allow based on headers, IP reputation lists, request size, user agent patterns, etc. 🧩
🧾 Simple mental model

Think of WAF as a “bouncer” for your web app: not only checking who is entering (IP/metadata) but also what they’re bringing in (request content).

3) AWS Network Firewall 🧱🛰️

What it is

AWS Network Firewall is a managed firewall to protect entire VPC networks by inspecting traffic more deeply than a basic subnet rule list. You can create detailed rules using attributes like source/destination IP, ports, and protocols.

What makes it different from NACLs?

  • More advanced inspection and more flexible rule capabilities. 🔍
  • Supports both stateless and stateful rule behavior. ⚙️
⚙️ Stateful vs Stateless (easy explanation)
  • Stateful ✅: If inbound is allowed, the return traffic is automatically allowed (similar idea to Security Groups).
  • Stateless 🚦: Inbound allowed does not automatically allow outbound response; you explicitly control both directions.

Exam tip: remember that AWS mentions “stateful” often for Security Groups; Network Firewall can do both.

4) Using layers together (defense in depth) 🧅

✅ Best practice mindset

AWS does not expect you to pick only one. In real setups, you often combine protections:

  • Security Groups: tight inbound ports (e.g., only 443) 🔐
  • NACLs: subnet-level guardrails / broad deny rules 🧱
  • WAF: web request inspection for app-layer attacks 🌐
  • Network Firewall: VPC-wide managed firewall with richer control 🛰️

5) AWS Firewall Manager 🧑‍✈️📌

What it is

Firewall Manager is a centralized service to manage firewall rules/policies (like WAF / Network Firewall policies) across an account — and commonly across multiple accounts in larger environments.

6) Mini scenarios (beginner-friendly examples) 🧪

Scenario A: “My app is public via CloudFront and getting SQL injection attempts.”

  • Use AWS WAF on CloudFront to detect/block SQLi patterns. 🛡️
  • Keep SGs strict (only needed ports to origin). ✅

Scenario B: “I need deeper control over traffic inside a VPC.”

  • Use AWS Network Firewall for VPC-level managed protection. 🧱
  • Use stateful rules for typical app flows; use stateless where you want explicit control. ⚙️

Scenario C: “We have many accounts and want consistent firewall policies.”

  • Use AWS Firewall Manager to apply/standardize policies centrally. 🧑‍✈️

7) CLF-C02 memory cues 🧠

  • WAF = web request inspection (helps with SQLi, XSS). 🌐
  • Network Firewall = managed VPC firewall, stateful + stateless rules. 🧱
  • Firewall Manager = central management across accounts. 🧑‍✈️
  • SG/NACL = basic network controls (IP/port/protocol); WAF adds content awareness. 🔎
