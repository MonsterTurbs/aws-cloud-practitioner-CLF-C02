Topic: Security — Data Protection Focus: KMS / CloudHSM / ACM Exam style: “What service do I use?”
🧠

Big Idea

Even if your account, apps, and network are secure, you still must protect the data. A core best practice is: encrypt data at rest and in transit.

“At rest” = stored (disk/object/database). “In transit” = moving over the network (requests/responses).

1) What does “encryption” do?

🔒

Encryption turns readable data (plaintext) into scrambled data (ciphertext) using a key. If data is exposed or stolen, encryption helps ensure attackers cannot do anything useful without the key.

  • Encrypt when storing or sending data.
  • Decrypt only when an authorized system/user needs to read it.

2) Encryption at rest (stored data)

🗄️

Meaning

Data is encrypted while it sits in storage (e.g., S3 objects, EBS volumes, RDS databases, snapshots, logs).

In AWS, two key services are commonly mentioned

  • KMS (Key Management Service): managed encryption keys (AWS manages key infrastructure).
  • CloudHSM: hardware security modules (HSM) for stronger control; you manage keys more directly.

2.1 KMS (Key Management Service) — the “default” exam answer

🧰

KMS provides encryption keys that integrate with many AWS services. For most major services, you can simply turn on encryption and select a KMS key.

  • ✅ Easy to use: "enable encryption" and AWS handles most of the heavy lifting.
  • ✅ Integrates broadly: commonly used with S3, EBS, RDS, Lambda env vars, etc.
  • ✅ Keys are protected and managed by AWS (you still control permissions to use them).

Practical mental model: “KMS = managed keys that many services can use automatically.”

2.2 CloudHSM — when you need “bring your own key store” control

🏦

CloudHSM uses dedicated hardware (HSM) so you can manage cryptographic keys with stronger isolation. The lecture frames this as a way to have a key store managed by you, with minimal AWS involvement.

  • ✅ More control over keys and key handling processes.
  • ✅ Useful for strict compliance/security requirements.
  • ⚠️ Typically more complex than KMS.
💡

Beginner Example: S3 encryption at rest

Scenario: You store customer PDF statements in S3. If a bucket is misconfigured or a backup leaks, you want the files to be unreadable.

  • Turn on S3 default encryption.
  • Choose SSE-KMS so S3 encrypts objects using a KMS key.
  • AWS automatically encrypts on upload and decrypts on authorized download.
Plaintext file (PDF)  →  S3 stores encrypted bytes (ciphertext)
Authorized user/app   →  S3 decrypts automatically (if allowed to use the KMS key)

3) Encryption in transit (network traffic)

🌐

Meaning

Data is encrypted while traveling across the network (client → AWS, AWS → client, service → service). This is commonly done with TLS/SSL (HTTPS).

Key AWS service mentioned in the lecture

  • ACM (AWS Certificate Manager): provisions and manages SSL/TLS certificates.

3.1 ACM (AWS Certificate Manager)

📜

ACM helps you get and manage SSL/TLS certificates so your users connect via HTTPS. Support is built into services that face the internet, such as: CloudFront and Application Load Balancer (ALB).

  • ✅ ACM can provide certificates (often free for supported integrations).
  • ✅ AWS services use them to encrypt traffic entering/leaving the AWS cloud.
  • ✅ Simplifies renewals and certificate lifecycle management.

Practical mental model: “ACM = HTTPS certificates for AWS edge/load-balancing services.”

🧪

Beginner Example: Encrypt website traffic

Scenario: Your customers open https://example.com and log in. You want usernames/passwords and session cookies protected from eavesdropping.

  • Request/provision a certificate in ACM (for your domain).
  • Attach it to CloudFront or an ALB.
  • Users connect via HTTPS (TLS), encrypting requests and responses in transit.

✅ Quick Check (Exam-style memory hooks)

  • Encrypt at rest (stored data): usually KMS (managed keys) → “turn on encryption.” 🔐
  • Need stronger key control / hardware-backed key store: CloudHSM. 🏦
  • Encrypt in transit (HTTPS/TLS): ACM provides certificates for services like CloudFront / ALB. 🌐

Common mistakes to avoid

⚠️
  • Only encrypting at rest and forgetting HTTPS/TLS for user traffic.
  • Hardcoding secrets (passwords/API keys) in code or repos. (Use Secrets Manager / Parameter Store instead.)
  • Assuming encryption is “automatic”: many services support it, but you often must enable it.

One-sentence summary

✅

Protect data by encrypting at rest (usually with KMS / sometimes CloudHSM) and in transit (TLS/HTTPS using ACM on edge/load-balancing services).
