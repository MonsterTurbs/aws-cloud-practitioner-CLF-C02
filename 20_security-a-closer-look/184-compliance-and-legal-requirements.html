Reviewer / Study Guide (Beginner-friendly) — focused on AWS services that help you enforce and prove compliance.

1) What “Compliance” Means (in simple terms) 🧩

Compliance means your company follows required rules such as laws, regulations, or industry standards (e.g., security, privacy, auditing). Even if your AWS account is secure, you may still need to prove you meet requirements.

Why it matters: If you cannot prove compliance during an audit, it can become a business risk (fines, loss of customer trust, or being blocked from doing business). 😬

Two big compliance needs

  • ✅ Enforce your internal rules (how resources should be configured).
  • ✅ Prove compliance to auditors (reports + evidence).

2) The 3 AWS Services You Must Know 🧰

1) AWS Config 🛠️

Enforce configuration rules. Detect “non-compliant” resources.

  • What it does: Lets you define rules for services (what “correct” configuration looks like) and checks if resources match.
  • What you get: A list of compliant vs non-compliant resources, so you can fix misconfigurations early.

Beginner example: “All S3 buckets must block public access.” If a bucket becomes public, Config flags it as non-compliant. 🚨

2) AWS Artifact 📄

Download AWS compliance reports (AWS proves its compliance).

  • What it does: Provides audit and compliance documents published by AWS (useful for your auditors).
  • Use case: You need proof that AWS meets certain standards, and you present AWS reports from Artifact.

Beginner example: An auditor asks: “Is your cloud provider compliant with a specific standard?” You retrieve AWS reports via Artifact. ✅

3) AWS Audit Manager 🧾

Track compliance evidence and generate auditor-friendly reports.

  • What it does: Helps you assess your AWS usage against compliance frameworks by collecting evidence automatically.
  • Key idea: You define requirements/rules, and Audit Manager gathers related data from AWS services to support an audit.
  • Extra: Can integrate with AWS Config for deeper evidence collection.

Beginner example: You want a report showing “encryption is enabled” for storage resources. Audit Manager helps generate an audit-ready report. 🧠

3) How They Work Together (simple flow) 🔁

  • 🛠️ AWS Config checks your resources against rules and flags non-compliance.
  • 📄 AWS Artifact gives you AWS-owned compliance documents (proof about AWS itself).
  • 🧾 AWS Audit Manager gathers evidence + generates reports about your AWS usage and controls.

Memory trick: Config = “Are we configured correctly?” ✅ | Artifact = “Show me AWS reports.” 📄 | Audit Manager = “Build the audit evidence for our account.” 🧾

4) Quick Review (Exam-style) ✅

  • 🧾 If the question is about meeting compliance requirements by enforcing resource configuration rules → AWS Config.
  • 📄 If the question is about downloading AWS compliance reports (AWS’s audit documents) → AWS Artifact.
  • 🧠 If the question is about collecting evidence and generating auditor-friendly reports for your account → AWS Audit Manager.
Common confusion (read this) 😵

AWS Artifact does not validate your own resource settings. It provides documentation about AWS’s compliance.

AWS Config is about configuration compliance (rules + evaluation), not delivering AWS audit PDFs.

Audit Manager is for audit preparation: evidence gathering and reporting.

5) Practical Examples (Beginner-friendly) 🧪

Example A: Enforce a rule across services

Goal: Ensure no one makes storage publicly accessible by mistake.

  • Use AWS Config rules to detect non-compliant resources (e.g., public S3 buckets).
  • Then your team fixes or remediates the configuration so it matches the rule again.

Example B: Provide AWS compliance proof to an auditor

Goal: Show official AWS compliance documentation during an audit.

  • Use AWS Artifact to download AWS compliance reports and provide them to auditors.

Example C: Prepare an audit package for your account

Goal: Generate a report that proves your account controls are in place.

  • Use AWS Audit Manager to define requirements and collect evidence automatically.
  • Optionally integrate AWS Config to strengthen evidence collection.

7) Key Terms to Remember 🗂️

  • 🧾 Compliance: following laws/standards + being able to prove it.
  • 🛠️ Config Rule: definition of “correct configuration” (used by AWS Config).
  • 📄 Compliance Reports: documents you can provide to auditors (AWS Artifact).
  • 🧠 Evidence Collection: gathering proof that controls are in place (Audit Manager).

Exam hint: If the question mentions “auditor-friendly report” or “evidence,” think Audit Manager. If it mentions “AWS compliance documents,” think Artifact. If it mentions “resource is non-compliant,” think Config. 🎯
