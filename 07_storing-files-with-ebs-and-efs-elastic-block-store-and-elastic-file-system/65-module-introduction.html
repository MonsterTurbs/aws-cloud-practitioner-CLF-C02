📁 AWS File Storage (Intro): EBS, EFS & a First Look at S3

🧠 Goal Understand what EBS, EFS, and S3 are and when to use each.

1) Why this module matters

✅ You already know how to run workloads in AWS (for example on EC2) and how to scale them. But almost every real workload also needs to store data — often as files.

In this section, the focus is on the main AWS services for file/storage needs: EBS and EFS, plus a brief early mention of S3.

2) Core idea: “Where do my files live?” 🗂️

Think of storage as “where your app puts files” (uploads, logs, generated reports, images, backups, etc.).

  • 🖥️ Compute = running code (e.g., EC2 instances)
  • 💾 Storage = keeping data (files, objects, databases)
  • 🔁 Reality = apps almost always need both
Beginner example 🧪

You host a website on EC2 and users upload images. Those images must be stored somewhere. EBS/EFS/S3 are common options depending on the architecture.

3) Quick definitions (memorize-friendly)

3.1 EBS — Elastic Block Store 💽

  • 🧱 Block storage you attach to an EC2 instance like a “virtual hard drive”.
  • 📌 Typically used by one EC2 instance at a time (exam-friendly simplification).
  • ✅ Great when you want storage that behaves like a disk for one server.
Simple mental model 🧠

EBS is like adding an extra SSD/HDD to one computer.

3.2 EFS — Elastic File System 🗃️

  • 📂 File storage that multiple servers can share (like a shared network folder).
  • 👥 Designed for scenarios where more than one EC2 instance needs the same files.
  • ✅ Great for shared uploads, shared app assets, shared configs, shared user content.
Simple mental model 🧠

EFS is like a shared folder on a network that multiple computers can mount.

3.3 S3 — Simple Storage Service 🪣 (first look)

  • 🧺 Object storage (not a normal disk, not a normal network folder).
  • 🌍 Commonly used for files like images, videos, backups, static website assets.
  • 📌 This course will cover S3 more deeply later — for now, just remember it’s a major storage service.
Simple mental model 🧠

S3 is like a huge bucket where you store “objects” (files) by key/name.

4) How EC2 connects to EBS/EFS 🔌

The practical point of this module is understanding that your compute (EC2) can be connected to storage. If your workload generates files, you usually don’t want those files to disappear when the instance is replaced.

  • 🖥️ EC2 + EBS: attach a virtual disk to an instance
  • 🖥️ EC2 + EFS: mount a shared file system that multiple instances can use
  • 🖥️ EC2 + S3: app uploads/downloads objects using the S3 API
Beginner example: Image uploads 🖼️
  • If you have one EC2 instance and want disk-like storage → EBS can work.
  • If you have multiple EC2 instances and they all need the same upload folder → EFS fits.
  • If you want a highly durable, scalable place for uploads and static content → S3 is a common design.

5) Fast “Which one should I pick?” decision cheat sheet ⚡

  • 🧱 Need storage that acts like a hard drive for one server → EBS
  • 📂 Need a shared folder used by multiple servers → EFS
  • 🪣 Need “store files as objects” for apps/backups/static assets → S3

Note: This module is an introduction. Later lessons will add deeper detail (performance, durability, access patterns, pricing).

6) Exam-minded notes 📝

  • 🎯 Know the names and the core differences: block vs file vs object.
  • 🎯 Be able to connect the idea to EC2: “My workload runs on EC2 but needs storage for files.”
  • 🎯 Recognize typical scenarios (uploads, shared files, backups/static assets).

7) Quick self-check (1 minute) ✅

  1. Which service is “like attaching a disk to EC2”? (Answer: EBS)
  2. Which service is “like a shared network folder” for multiple instances? (Answer: EFS)
  3. Which service is commonly used as an object bucket for files like images? (Answer: S3)
Tip 💡

When stuck, map the question to the storage type: Block (disk) vs File (shared folder) vs Object (bucket).
