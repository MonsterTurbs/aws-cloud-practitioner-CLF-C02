Different Kinds of File Storage in AWS

Reviewer / Study Guide (Beginner-friendly): Block Storage (EBS), Object Storage (S3), Network File Systems (EFS / FSx)

🧠 CLF-C02 Focus 💾 Storage Basics 🖨️ A4 Print-ready 📌 Single-column

Big Idea

AWS offers different storage services because there are different “styles” of storing files. In this lecture, the three major approaches are:

  • 🧱 Block storage → like attaching a raw hard drive to a server (AWS: EBS)
  • 📦 Object storage → store files as “objects” without managing disks (AWS: S3)
  • 🗄️ Network file system → a shared file system you mount (AWS: EFS / FSx)
✅ Exam mindset: When you see a question about “how the app needs to use files” (raw disk vs object store vs shared filesystem), you can usually pick the service quickly.

1) Block Storage → EBS (Elastic Block Store) 🧱

Block storage means you attach an unformatted virtual disk to a server. You (or your OS) then:

  • format it (create a filesystem),
  • mount it inside the instance,
  • then create folders/files like a normal hard drive.

How it looks in AWS

  • 💡 You attach an EBS volume to an EC2 instance.
  • 🔒 In this lecture’s framing: EBS is EC2-focused (you use it like an attached disk for EC2).

Beginner example

You run a web server on EC2 and need extra disk space for logs or app files. You add an EBS volume, format it, mount it, and store files there.

📝 Memory hook: EBS = “Extra disk for EC2”.

2) Object Storage → S3 (Simple Storage Service) 📦

Object storage focuses on storing and retrieving files (objects) directly. You don’t manage disks, formatting, or mounting.

Key characteristics (beginner-friendly)

  • 🧰 No “hard drive management” — you just upload/download files.
  • 🗂️ You don’t build a traditional OS filesystem by default; you store objects in a storage “place” (commonly thought of as buckets).
  • 📈 Great when you want to store files independently from any one EC2 instance.

Beginner examples

  • 🖼️ Website uploads user images → store them in S3.
  • 🧾 Online shop generates invoices (PDF) → store PDFs in S3.
  • 📚 Archive legal documents or backups → store long-term in S3.
📝 Memory hook: S3 = “store files as objects; no disk to manage”.

3) Network File Systems → EFS / FSx 🗄️

A network file system gives you a ready-to-use filesystem that you mount over the network. You care about folders and file paths, but you don’t want to manage the underlying disk like with block storage.

Why this exists

  • 🤝 You may want a shared filesystem usable by multiple compute resources (e.g., multiple EC2 instances).
  • 🧩 You want a “filesystem experience” (folders, structure) without manually attaching/formatting disks.

Services mentioned in the lecture

  • 📁 EFS (Elastic File System) — network file system concept
  • 🧊 FSx family — includes specialized options (lecture mentions FSx Lustre)

Beginner example

You have two EC2 instances (behind a load balancer) that both need to read/write the same shared files. A network file system lets both instances access the same folder structure.

📝 Memory hook: EFS/FSx = “shared network folders”.

Quick Comparison (Exam-friendly)

Type What it feels like (and when you pick it)
🧱 Block
EBS		 Like adding an extra disk to a server. You format/mount it inside EC2. Pick when your workload needs “disk attached to server” behavior.
📦 Object
S3		 Store files directly without managing disks or filesystems. Pick when you want durable file storage independent of a single EC2 instance.
🗄️ Network FS
EFS / FSx		 A mountable shared filesystem (folders/paths) accessible over the network. Pick when multiple servers/services need shared file access.

Common Confusions (and Simple Fixes)

  • ❓ “I want to store files… should I always use EBS?” → Not always. If you don’t want to manage disks and the files should outlive an EC2 instance, S3 is often a better fit.
  • ❓ “S3 is file storage, so it’s a filesystem?” → Think of S3 as object storage, not a traditional mounted filesystem.
  • ❓ “I need folders shared between multiple EC2 instances.” → Think EFS/FSx (network file system).
✅ Quick decision question: “Do I need a disk, an object store, or a shared filesystem?”

Mini Quiz (for retention) 🧪

  1. You need an extra drive attached to your EC2 instance for app data. Which storage style is this?
    Answer: Block storage → EBS 🧱
  2. Your website stores user-uploaded images and you don’t want to manage disks/formatting. Which service style fits best?
    Answer: Object storage → S3 📦
  3. Two EC2 instances must access the same folder structure (shared files). What storage style is that?
    Answer: Network file system → EFS / FSx 🗄️

Key Terms to Remember

  • 🧱 Block storage = raw disk attached to a server (format/mount)
  • 📦 Object storage = store/retrieve files as objects (no disk management)
  • 🗄️ Network file system = mountable filesystem over the network (shared folders)
  • 🔤 EBS = Elastic Block Store (lecture: EC2-focused disk attachment)
  • 🔤 S3 = Simple Storage Service (major AWS service; deeper dive later)
  • 🔤 EFS / FSx = managed network file system services (file system without manual disk setup)
🧠 Fast recall: EBS = disk, S3 = objects, EFS/FSx = shared folders.
