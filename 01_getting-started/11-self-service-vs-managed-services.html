11 — Self-Service vs Managed Services 🧩

Reviewer / Study Guide (single-column, A4 print-ready)

🎯 Lecture Goal

Learn the two broad categories of AWS services used throughout the course: self-service services and managed services. This mental model helps you reason about AWS offerings and makes exam questions easier.

Big idea ✅ With self-service services, you manage more things yourself. With managed services, AWS manages more of the “hard parts” for you.

🧠 Two Main Categories (High-Level)

1) Self-service services 🛠️

You control the environment and configuration. AWS mainly provides the underlying hardware and cloud platform.

2) Managed services 🤝

AWS takes care of many operational tasks (maintenance, patching, backups, running the service), while you focus on configuration and usage.

🛠️ Self-Service Example: EC2 (Virtual Servers)

In the lecture, EC2 is used as the example of a self-service service.

  • 🖥️ You configure and launch a server (virtual machine).
  • 🔐 You connect to it and install any software you want.
  • ⚙️ You decide how it’s configured and what workloads run there.
  • 🏗️ AWS manages the underlying physical hardware.

Beginner mental model 💡 EC2 is like renting a computer in the cloud. AWS owns the building and physical server; you control the OS/software inside your “rented computer.”

🤝 Managed Services Example: Managed Databases

The lecture contrasts EC2 with managed database services.

  • 🧩 You still configure some aspects (settings, capacity, access rules).
  • 🩹 AWS handles patching the database software.
  • 💾 AWS handles backups (and often other operational tasks).
  • 🧰 AWS runs the database servers behind the scenes.

Beginner mental model 💡 Managed database = you use the database; AWS operates the database engine like a service.

🧩 Mix & Match Services

You are not forced to choose only one category. You can combine both types depending on what you need.

Example 💡 Run your app on EC2 (self-service) while using a managed database (managed). This can reduce operational work while keeping flexibility where you need it.

✅ Why This Matters (Course + Exam)

  • 🧠 Helps you reason about AWS services as you learn more later.
  • 📝 Exam questions often test what AWS manages vs what you manage.
  • ⚖️ Helps you choose services based on trade-offs: control vs convenience.

Rule of thumb ✅ Managed services usually reduce your operational work. Self-service usually gives you more control (but more responsibility).

🗂️ Key Terms (Exam Focus)

Self-Service Managed Service EC2 Virtual Machine Patching Backups Operations

✅ Quick Self-Check

Q1: What is the core difference between self-service and managed services?

A: Self-service means you manage more configuration and operations; managed services mean AWS manages more of the operational tasks for you.

Q2: Why is EC2 considered self-service?

A: You configure the server, connect to it, and manage the software/workload; AWS mainly manages the underlying hardware.

Q3: Give two operational tasks AWS can handle in managed database services.

A: Patching and backups (and running/operating the database server).

Q4: Can you combine self-service and managed services?

A: Yes. You can mix and match services based on your needs.
