05 — Cloud Advantage: Reliability ✅

Reviewer / Study Guide (single-column, A4 print-ready)

🎯 Lecture Goal

Understand how cloud computing (and AWS) helps solve common on-premise problems and why reliability is a major cloud advantage.

Big idea ✅ AWS manages infrastructure for you (maintenance, upgrades, capacity), and gives tools so you can build reliable applications that stay available under changing demand and failures.

🛠️ What AWS Removes From Your To-Do List

Compared to running your own data center, AWS helps because AWS takes care of the underlying infrastructure tasks:

  • 🔧 Infrastructure maintenance
  • 📈 Capacity planning and scaling challenges
  • ⬆️ Hardware/software upgrades (infrastructure level)
  • 🛡️ Securing the infrastructure (facility + hardware level)

Beginner note 💡 You still secure your applications and configuration, but AWS operates and protects the physical layer.

✅ What “Reliability” Means in the Cloud

In this lecture, reliability has two related meanings:

1) You can rely on AWS 🏢

  • AWS manages the infrastructure and aims to keep services available.
  • Some services come with SLAs (Service Level Agreements), which are formal availability commitments.

2) You can build reliable applications 🧩

  • AWS provides services and features to design apps that keep working even when demand or failures happen.
  • Reliability also means your customers can rely on your app to behave consistently.

📈 Example: Auto Scaling for Reliability

AWS provides services that can add or remove servers automatically as demand changes (traffic increases or decreases).

Simple example 💡 If your website gets a traffic spike, AWS can scale out by adding more server capacity so the site stays responsive. When traffic drops, it can scale back in to reduce cost.

Why this improves reliability ✅ Your app is less likely to crash or slow down when demand changes unexpectedly.

🌍 Global Reach = Better Resilience

AWS operates a worldwide network of data centers. This enables strategies like failing over to another region if one location has a major issue.

  • 🌐 Multiple regions help reduce reliance on one physical location.
  • 🚨 If a catastrophe affects one region/data center, workloads can move to another region.
  • ⏱️ Moving in the cloud can be faster (minutes/hours, sometimes seconds) compared to traditional data centers (days/weeks).

Beginner note 💡 This is the core reason cloud is often more resilient than a single-company data center: you can design for redundancy across locations.

🗂️ Key Terms to Remember

Reliability SLA Availability Auto Scaling Global Reach Region Failover Workload

✅ Quick Self-Check

Q1: Name three infrastructure responsibilities AWS reduces for you.

A: Maintenance, capacity planning/upgrades, and securing the infrastructure.

Q2: Reliability in the cloud means what two things in this lecture?

A: You can rely on AWS infrastructure (sometimes backed by SLAs) and you can build reliable applications using AWS services.

Q3: How does auto scaling improve reliability?

A: It adds/removes capacity automatically so your app can keep up with demand changes.

Q4: Why does global reach improve reliability?

A: You can fail over to another region if one region is affected, helping keep workloads running.
