10 — AWS Infrastructure: Regions & Availability Zones 🌍🏢

Reviewer / Study Guide (single-column, A4 print-ready)

🎯 Lecture Goal

Understand how AWS is structured globally—especially the two exam-critical terms: Region and Availability Zone (AZ). Learn why these matter for availability, latency, pricing, and compliance.

Big idea ✅ AWS runs data centers worldwide. You choose where your workloads run using Regions (large geographic areas) and Availability Zones (separate locations inside a Region).

🌍 AWS Has Many Data Centers Worldwide

  • AWS owns and operates data centers across dozens of locations worldwide.
  • These locations are organized into Regions.
  • AWS has more Regions than a simplified schematic map might show; AWS lists both current and planned Regions on its official pages (linked in the course resources).

🏷️ Key Term 1: Region

A Region is a geographic area that contains multiple data centers.

Important ✅ A Region is not a single data center. A Region contains multiple data centers grouped into Availability Zones.

🧱 Why Regions exist

  • Regions are physically isolated from each other.
  • If a major catastrophe affects one Region, other Regions are expected to be unaffected.

🧩 Regional vs Global Services

  • Many AWS services are regional: you can choose the Region where you use the service.
  • Some services are global: you don’t pick a Region for them.

Console tip 💡 For many regional services, you choose the Region from the Region selector (often a dropdown) in the top-right of the AWS Management Console.

🧭 Why Choose One Region Over Another?

The lecture lists common reasons for Region selection:

💰 Pricing differences

Costs can differ by Region because AWS has different operating costs in different parts of the world.

🧰 Service availability

Not all services exist in all Regions (Regions can differ in size/hardware/capabilities).

⚖️ Legal / compliance

You may need to store data in a specific geography (example: EU data residency). That influences Region selection.

⚡ Latency

Run workloads closer to end users so requests are faster (lower latency).

✅ High availability & resilience

Run workloads in multiple Regions so if one Region is impacted, another can continue serving users.

🏷️ Key Term 2: Availability Zone (AZ)

A Region is divided into Availability Zones (AZs).

  • A Region contains multiple AZs.
  • A Region has at least three AZs (as described in the lecture).
  • An AZ contains at least one data center.

Exam-friendly relationship ✅

Region → multiple Availability Zones (AZs) → one or more Data Centers

🧯 Why AZs improve reliability

  • AZs are separated from each other (different buildings, independent power).
  • They are closer than Regions (miles / tens of miles apart), so they support low-latency redundancy inside one Region.
  • A disaster may affect one AZ, but is less likely to affect all AZs in the Region.

Practical takeaway 💡 You can increase availability by spreading your workload across multiple AZs within the same Region.

🕸️ AWS Global Network Connectivity

AWS Regions are connected by a network owned and operated by AWS.

  • 🔒 Can provide secure connectivity between workloads across Regions.
  • ⚡ Can be faster and more reliable than depending only on the public internet.
  • 🌐 You can still use public internet too—both approaches exist depending on architecture.

Why this matters 💡 Running apps across Regions can still be practical because the underlying network connectivity is designed for global operation.

✅ Quick Self-Check

Q1: Is a Region the same as a data center?

A: No. A Region contains multiple Availability Zones, and those contain data centers.

Q2: What is an Availability Zone (AZ)?

A: A grouping of one or more data centers within a Region, separated from other AZs with independent infrastructure.

Q3: Name two reasons to choose a specific Region.

A: Pricing differences, service availability, legal requirements (data residency), reducing latency, and/or designing for higher availability.

Q4: How can you improve availability without leaving a Region?

A: Spread workloads across multiple Availability Zones within the same Region.

Q5: How do Regions help with catastrophe risk?

A: Regions are physically isolated; if one Region is impacted, another Region can host the workload.
