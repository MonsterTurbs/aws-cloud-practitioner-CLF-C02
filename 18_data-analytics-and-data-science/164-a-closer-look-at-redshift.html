📊 AWS Redshift — Reviewer / Study Guide (CLF-C02)

Single-column, print-ready notes on Amazon Redshift as a data warehouse for analytics.

🧠 Beginner-friendly 🖨️ A4 Print-ready 📚 Topic: Data Analytics & Data Science

1) What is Amazon Redshift?

Amazon Redshift is AWS’s data warehouse service. 🏭📈

Think of a data warehouse as a place where you store analytics data (data you want to analyze and run reports on), not the day-to-day transactional data used by your app.

Exam mindset ✅

  • Redshift = analytics / reporting / BI (SQL queries over large datasets).
  • Not the typical database for “live app transactions” (that’s usually RDS/DynamoDB).

2) Redshift vs RDS (Simple Comparison)

Both are “database-like” services, but they serve different goals. 🎯

🧾 RDS (Relational Database Service) is for application transactions

  • Used by your app for everyday operations: orders, logins, product browsing, payments, etc.
  • Optimized for transactional workloads (many small reads/writes constantly happening).

📊 Redshift is for analytics queries

  • Used for reporting, dashboards, and deep analysis.
  • Optimized for large-scale analytics (scanning lots of data, aggregations, trends).

Quick memory trick 🧠

RDS = Run the business (transactions).
Redshift = Understand the business (analytics).

3) Key Capabilities You Should Know

  • 🧱 SQL-based: You query Redshift using SQL (familiar to many developers/analysts).
  • 📈 Scalable: Designed to handle large analytics datasets and heavy reporting workloads.
  • 🧩 Flexible / integrates multiple sources: Redshift can also query data stored elsewhere (e.g., data in S3) so you can analyze across sources.
👀 Beginner explanation: “Query data in S3 without moving it”

In many analytics setups, raw data is stored in S3 (data lake). Instead of copying everything into the warehouse, Redshift can be connected so that you can run queries over data in S3 as well.

Conceptually: Redshift becomes a “hub” where you can analyze data across sources.

4) Simple Example (E-commerce Scenario)

Imagine an online shop. 🛒🙂

Transactional side (RDS)

  • Store live orders, carts, product inventory updates.
  • App reads/writes constantly while users browse and buy.

Analytics side (Redshift)

  • Store historical events: orders over months/years, product views, marketing campaigns, etc.
  • Run questions like: “What are the top-selling products this quarter?” “Which campaigns increased sales?”
-- Example analytics query (conceptual)
-- "Which products generated the most revenue last month?"
SELECT product_id, SUM(order_total) AS revenue
FROM order_facts
WHERE order_date >= DATEADD(month, -1, CURRENT_DATE)
GROUP BY product_id
ORDER BY revenue DESC
LIMIT 10;

Note: The exact table names depend on your warehouse design; the goal is to recognize the analytics pattern (aggregate + trends).

5) Exam Takeaways (High Yield) ✅

  • 📌 Redshift = Data warehouse (analytics / BI / reporting).
  • 📌 RDS = App database (transactional workloads).
  • 📌 Redshift is SQL-based and built for querying/aggregating large datasets.
  • 📌 Redshift can integrate with other sources (e.g., S3) to analyze data without necessarily moving it all.

6) Mini Quiz (with Answers)

📝 Quiz
  1. Which AWS service is primarily for a data warehouse used in analytics?
  2. Which service is typically used for transactional app data (orders, logins, etc.)?
  3. Why might a company keep raw data in S3 and still use Redshift?
✅ Answers
  1. Amazon Redshift.
  2. Amazon RDS (or DynamoDB for certain NoSQL app use cases).
  3. Because S3 can act as a data lake (cheap storage for lots of raw data), and Redshift can be used to run analytics queries and integrate multiple data sources for reporting.

Tip: If you see “analytics / BI / data warehouse” in a question, think Redshift. If you see “app transactions,” think RDS. 🧠
