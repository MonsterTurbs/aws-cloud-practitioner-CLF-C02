📊 AWS CLF-C02 — Data Analytics & Data Science (Module Summary)

Print-friendly reviewer / study guide (single-column, A4-ready). Focus: ingestion → storage → transform → analyze.

🧠 Beginner-friendly 🖨️ A4 Print CSS 📌 Exam-focused takeaways ✅ Examples included

1) Big Picture: What problem are we solving? 🤔

Data analytics is a pipeline, not a single service. You usually need multiple steps that work together:

  • 📥 Ingest data (get data into AWS)
  • 🧺 Buffer / stream data if it arrives very fast (high frequency)
  • 🗄️ Store data (data lake and/or data warehouse)
  • 🧽 Transform data (clean, standardize, reshape)
  • 🔎 Analyze data (SQL queries, dashboards, visualizations)
Key idea (exam-friendly): Different ingestion frequencies need different approaches.
  • 🐢 Low/moderate frequency → typical storage like S3, RDS, DynamoDB
  • ⚡ High frequency / streaming → use Kinesis to handle bursts and continuous streams

2) Ingestion: Kinesis for streaming data ⚡

Kinesis is designed for high-frequency data streams (dozens/hundreds/thousands of events per second). Think: sensor data, clickstream logs, IoT events.

How to think about it (simple mental model) 🧠

  • 📥 Many tiny events arrive very quickly.
  • 🧺 Kinesis buffers and groups the stream so downstream services are not overwhelmed.
  • 🚚 With Kinesis Firehose, you can deliver/forward data to destinations (e.g., S3) more smoothly.
  • 🧮 You can also run near real-time analytics on streaming data (use-case dependent).
Example: Your website produces 1,000 log events/second. Instead of writing 1,000 objects/rows every second directly into storage, you send the stream to Kinesis first. Kinesis then delivers it in a controlled way.

3) Storage: Data Lake vs Data Warehouse 🗄️

🌊 Data Lake (usually S3)

A data lake means storing lots of data (structured + unstructured) in one place—commonly S3. It’s great when you want flexibility.

  • ✅ Store raw files (CSV/JSON/Parquet/logs/images)
  • ✅ Useful for ML/data discovery
  • ✅ Cheap and scalable storage
  • ⚠️ Often needs schemas/ETL later to analyze efficiently

🏢 Data Warehouse (Redshift)

Redshift is a data warehouse built for analytics. You store data specifically to run analytical queries and reporting.

  • ✅ SQL-based analytics database
  • ✅ Best for BI reporting (dashboards, metrics)
  • ✅ Can integrate multiple sources (including S3 query capability)
  • 🚫 Not meant as your app’s transactional DB (that’s more like RDS/DynamoDB)
Exam tip: If a question says “data warehouse for analytics” → think Redshift. If it says “store huge amounts of diverse data files” → think S3 data lake.

4) Transform: Glue (serverless ETL) vs EMR (big data clusters) 🧽

Service What it is When to use Simple example
🧪 AWS Glue Serverless, managed ETL (Extract → Transform → Load). Includes a crawler to infer schemas. You want an easier managed ETL workflow with minimal infrastructure work. Clean raw CSV files in S3 → load cleaned data into Redshift.
🧱 EMR Managed way to spin up big data clusters (more control). You choose frameworks/tools. You need more control, custom big data frameworks, or complex large-scale processing. Run Spark/Hadoop jobs across many instances to transform massive datasets.
Shortcut: Glue = “serverless ETL with crawler” ✅ | EMR = “your big-data cluster playground” 🧰

5) Analyze: Athena vs QuickSight 🔎📈

🔎 Athena

Athena lets you run SQL queries on data in S3 (and some other sources). It treats S3 like a database (without moving data into a DB).

  • ✅ Great for fast ad-hoc queries (“quick insights”)
  • ✅ Commonly paired with Glue crawler (schema discovery)
  • 💡 Think: “SQL over files”
Example query use-case: “How many orders per day are in my S3 logs?” → Athena can query the S3 data directly.

📈 QuickSight

QuickSight is AWS’ Business Intelligence (BI) tool. You use it to build dashboards, charts, reports for stakeholders.

  • ✅ Visual reporting (KPIs, trends, charts)
  • ✅ Share dashboards with teams/executives
  • 💡 Think: “BI dashboards and reporting”
Rule of thumb: Athena = “ask the data a question with SQL” 🧾 | QuickSight = “show the answer as charts/dashboards” 📊

6) Search + Visualization: OpenSearch + Grafana 🔍📊

If you need strong search + filtering and interactive visualizations, AWS also offers: OpenSearch (managed search/analytics engine) and Managed Grafana (dashboards).

When this combo makes sense ✅

  • 🔎 You want to search large datasets (often logs/events) quickly.
  • 📈 You want highly interactive dashboards (Grafana-style).
  • 🧩 You may combine it with other monitoring/analytics workflows.
Important distinction: QuickSight is a classic BI tool. OpenSearch + Grafana is often chosen when you prioritize search + exploration (especially for log-like data).

7) CloudSearch: Search for your end users 🔎🛒

CloudSearch is primarily about adding search functionality to an application/website (e.g., product search on an online shop), including features like efficiency and auto-completion.

Exam-friendly wording: If the question says “add search bar for customers” → think CloudSearch. If it says “internal search/analytics exploration” → think OpenSearch.

9) One-page storyline (for recall) 🧠

✅ Collect/ingest data (Kinesis for high-frequency streams).
✅ Store raw data in S3 (data lake) and/or analytics data in Redshift (warehouse).
✅ Transform with Glue (serverless ETL) or EMR (big-data clusters).
✅ Analyze with Athena (SQL over S3) and/or QuickSight (BI dashboards).
✅ Use OpenSearch + Grafana when search + interactive dashboards are important.
✅ Use CloudSearch when you need search for your product’s users.

10) Practice questions (quick self-test) 📝

  1. You receive sensor events at very high frequency. What service helps ingest and buffer the stream?
    Answer: Kinesis
  2. You want to run SQL queries over CSV/Parquet files stored in S3 without loading them into a database. What service?
    Answer: Athena (often with Glue crawler)
  3. Your manager asks for a shareable dashboard with charts and KPIs. What service?
    Answer: QuickSight
  4. You need an analytics data warehouse (not a transactional database). What service?
    Answer: Redshift
