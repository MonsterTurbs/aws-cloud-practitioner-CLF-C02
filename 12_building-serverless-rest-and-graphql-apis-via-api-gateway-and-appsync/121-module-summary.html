📘 Module Summary — Building Serverless REST & GraphQL APIs (AWS)

Reviewer / Study Guide (Beginner-friendly) — API Gateway, AppSync, Cognito, Amplify

🧠 Focus: Exam-ready concepts 🧾 Layout: Single-column, print-first ⚪ Background: White, A4-ready

1) Big Picture 🗺️

In real applications, your front end (web / mobile / desktop) needs to talk to your cloud back end to fetch data (e.g., products) or trigger actions (e.g., upload an image, place an order). This typically happens via HTTP APIs.

Key idea 💡: You can build REST/GraphQL APIs with your own code and host them (EC2/containers), but AWS also offers managed services so you don’t need to run API servers yourself.

Typical flow (conceptual) 🔁

User App (Browser / Mobile)
  ↓ HTTP request
API Layer (API Gateway for REST OR AppSync for GraphQL)
  ↓ triggers
AWS Lambda (business logic)
  ↓ reads/writes
Database (e.g., DynamoDB / RDS)
  ↓
Response back to the user

2) REST vs GraphQL (What’s the difference?) ⚖️

🌐 REST API (common, URL-based)
  • Uses multiple endpoints (URLs) such as /books/1.
  • Uses HTTP methods like GET, POST, PUT, DELETE.
  • Often returns a full “resource” payload (sometimes more data than needed).
GET /products/123
→ returns product 123 (often a full object)

POST /orders
→ creates an order
🧩 GraphQL API (query-based)
  • Usually uses a single endpoint (one URL).
  • You send a query describing exactly what fields you want.
  • Can reduce “over-fetching” (less redundant data).
query {
  product(id: "123") {
    id
    title
    price
  }
}

Exam-friendly takeaway ✅: REST = multiple URLs + HTTP methods. GraphQL = one endpoint + query in the request asking for specific fields.

3) API Gateway — Managed Serverless REST APIs 🚪

API Gateway helps you build and run REST (and HTTP) APIs without hosting your own API servers. It handles a lot of “boilerplate” work: request parsing, routing, validation, auth hooks, and response formatting.

What you define in API Gateway ✍️

  • Resources / paths (e.g., /products, /orders)
  • Methods (GET/POST/…)
  • Request/response rules, parameters, schemas (optional)
  • Integration target (commonly Lambda)
  • Stages (deploy different versions/environments)

Beginner example 🧪

Goal: Mobile app fetches products.

1) API Gateway route: GET /products
2) API Gateway triggers: Lambda function "GetProducts"
3) Lambda reads products from DynamoDB
4) API Gateway returns JSON response to the app

Memory hook 🧷: API Gateway = “I want endpoints without running an API server.” 🙂

4) AppSync — Managed GraphQL APIs 🧠

AWS AppSync is the managed service for building GraphQL APIs without writing the “API server” part. You focus on the schema (what data can be requested) and how each query/mutation gets resolved.

What you define in AppSync 🧩

  • Schema (types, queries, mutations)
  • Resolvers (how AppSync fetches the data)
  • Data sources (often DynamoDB, Lambda, etc.)
  • Auth settings + optional caching/optimization

Beginner example 🧪

Goal: App requests only fields it needs.

Client sends GraphQL query:
  product(id:"123") { id title }

AppSync:
  - matches it to schema
  - runs a resolver (often Lambda or DynamoDB)
  - returns only requested fields

Memory hook 🧷: AppSync = “GraphQL, schema-first, managed.” 😄

5) Cognito — Authentication for Your App Users 🔐

Cognito is for users of your application (customers/end-users), not for AWS account users. Don’t confuse it with IAM.

👤 IAM (Account access)
  • For admins/devs/services that need access to AWS resources.
  • Controls permissions inside your AWS account.
  • Not meant for your app’s customers.
🧑‍💻 Cognito (App user auth)
  • Manages sign-up / sign-in (email + password, MFA, etc.).
  • Stores users in User Pools (managed user directory).
  • Can integrate social logins (Google/Facebook/Apple) via federated identities.
  • Can provide temporary AWS permissions when needed (narrow, controlled access).

Beginner example 🧪

Scenario: App lets users upload profile photos to S3.

1) User logs in (Cognito)
2) App receives tokens / auth state
3) App can upload to S3 with controlled, temporary permissions
   (only if you configure it that way)

Memory hook 🧷: IAM = “AWS account access.” Cognito = “My app’s users.” 🔑

6) Amplify — “Front End + AWS” Made Easier 🧰

AWS Amplify is a platform / toolset that makes it easier to build apps that use AWS. It helps in two main ways:

  • Back end support: Amplify can create/configure AWS resources for you (example: set up a database, auth, hosting).
  • Front end SDKs: Amplify provides SDKs (JavaScript, etc.) so your app can easily talk to services like Cognito.

Beginner example: using Amplify SDK for Cognito 🧪

Conceptually, you use Amplify libraries in your front end so you don’t manually handle all the auth plumbing.

// Conceptual (not exam-required)
// Your app uses Amplify SDK to authenticate with Cognito.

import { Auth } from 'aws-amplify';

await Auth.signIn(email, password);
const user = await Auth.currentAuthenticatedUser();

Memory hook 🧷: Amplify = “Developer-friendly toolkit for building AWS-backed apps.” 🧩

Amplify can also provide a more complete workflow (including a CMS-like experience via Amplify Studio), so you can manage back end resources and application data more conveniently.

7) Quick Check ✅ (Exam-style prompts)

  • 🟦 Which service builds managed REST APIs? → API Gateway
  • 🟪 Which service builds managed GraphQL APIs? → AppSync
  • 🔐 Which service manages authentication for your app’s end-users? → Cognito
  • 🧰 Which platform provides SDKs + simplifies AWS-backed app development? → Amplify
  • ⚙️ Where does your “business logic” often run? → Lambda (commonly used behind API Gateway/AppSync)

Final reminder 🎯: API Gateway and AppSync remove the need to run API servers. You focus on routing/schema + business logic (often Lambda) and data sources (databases).

8) Ultra-short Summary (1-minute review) ⏱️

  • 🌍 Front ends talk to cloud back ends via HTTP APIs.
  • 🚪 API Gateway = managed, serverless REST/HTTP APIs.
  • 🧠 AppSync = managed GraphQL APIs (schema + resolvers).
  • 🔐 Cognito = auth for your app users (not IAM users).
  • 🧰 Amplify = toolset + SDKs to simplify building AWS-backed apps.
