API Gateway (REST APIs) — Reviewer / Study Guide

Beginner-friendly notes for AWS CLF-C02: what API Gateway is, why it matters, and how it commonly integrates with Lambda.

🧠 Topic: Serverless APIs 🧩 Focus: REST via API Gateway 📍 Regional service 🧪 Console-friendly testing

Tip: For best results, use your browser print dialog and keep margins enabled (A4).

1) What is API Gateway?

✅ Simple definition

API Gateway is an AWS service that helps you build and run HTTP/REST APIs without having to write all the “plumbing” code for handling requests and responses.

🎯 Main benefit

You focus on the business logic (what should happen when a request arrives), while API Gateway handles common API tasks like routing, validation, and response formatting.

What “boilerplate code” does API Gateway reduce?

  • 📌 Matching requests to the correct path (resource) and HTTP method (GET/POST/etc.).
  • 🧰 Basic request checks: query parameters, required headers, request structure.
  • 🔐 Enforcing authentication (when configured).
  • 🧾 Returning the correct status code and a structured response (when configured).

2) The “mental model”

Think of API Gateway as the front door for your backend. It receives HTTP requests, applies rules, then forwards the request to a backend integration (commonly AWS Lambda), and finally sends a response back to the client.

🧠 Common flow
Client (Web/Mobile) → API Gateway (routes + checks) → Lambda (your code) → API Gateway (build response) → Client

Beginner example

Imagine you want a simple endpoint:

GET /products
  • API Gateway receives the request.
  • If needed, it checks auth and validates inputs.
  • It triggers a Lambda function that fetches products (e.g., from a database).
  • API Gateway returns the Lambda output to the client as JSON.

3) What you “define” in API Gateway

🧭 API structure Resources / paths (e.g., /books, /books/{id}) and HTTP methods (GET, POST, PUT, DELETE).
🔎 Request requirements Query params, headers, and (in some cases) schemas/validation rules to enforce inputs.
🔐 Authentication Rules to require authenticated requests (how authentication is set up depends on your chosen approach).
🧾 Responses Status codes (200/400/401/500, etc.) and response formatting rules.
⚙️ Integrations Where the request goes next (commonly Lambda). API Gateway can also integrate with other AWS services.
🧪 Testing & deployment Test in the console and deploy via stages (e.g., dev, prod).
💡 Key point

API Gateway can automatically extract data from requests (like path params or query params) and pass it to your backend integration, reducing custom parsing code.

4) Why API Gateway pairs well with Lambda

Lambda is “on-demand code execution.” API Gateway can act as the HTTP interface, and Lambda can do the work. This combination is common because:

  • ⚡ You don’t run or manage servers for your API runtime.
  • 🧩 API Gateway handles routing and request filtering; Lambda focuses on business logic.
  • 💸 You typically pay based on usage (requests + execution), not server uptime.
Example scenario (practical)

📦 POST /orders → API Gateway checks auth → triggers Lambda → Lambda writes order to DB → returns result → API Gateway responds with 201 Created.

5) REST API vs HTTP API vs WebSocket API (exam-level)

When creating an API in API Gateway, you’ll see different API types:

  • 🔁 WebSocket API: for real-time, two-way communication (persistent connection).
  • 🌐 HTTP API: typically simpler/leaner to set up.
  • 🧰 REST API: more feature-rich “classic” API Gateway option.
✅ Exam takeaway

API Gateway is used to build APIs. REST APIs are more feature-rich; HTTP APIs are simpler; WebSocket APIs are for real-time apps.

6) Testing, stages, and deployment

  • 🧪 Testing: You can test endpoints from the AWS console while building (helpful during learning).
  • 🚦 Stages: You can deploy multiple versions/environments (e.g., dev, staging, prod).
  • 🧩 Versioning mindset: Different clients can use different stages (e.g., internal testers use dev).
Beginner tip

🧭 Use stages like separate “URLs for environments.” It keeps experiments away from production.

7) Cost & free tier note

API Gateway is usage-based. You can start small and learn with minimal cost, but as traffic grows, costs grow too.

  • 🧾 Costs depend on request volume and features used.
  • 🆓 There is a free tier to help you get started (check AWS pricing for current limits).
Why it can be cost-effective

💰 You don’t need to rent and run an always-on server (like EC2) just to expose endpoints—API Gateway can remove that operational burden.

8) Quick self-check (mini reviewer)

  • ✅ API Gateway helps build REST/HTTP APIs with less boilerplate.
  • ✅ You define paths + methods, request rules, auth (optional), and integrations.
  • ✅ A very common integration is Lambda for request handling.
  • ✅ API Gateway supports stages (dev/prod versions).
  • ✅ It is a regional service (APIs are created per region).
  • ✅ WebSocket APIs are for real-time applications.
