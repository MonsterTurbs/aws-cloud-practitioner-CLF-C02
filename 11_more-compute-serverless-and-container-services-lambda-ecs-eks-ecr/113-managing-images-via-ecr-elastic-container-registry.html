📦 AWS ECR (Elastic Container Registry) — Reviewer / Study Guide

CLF-C02 focused notes • Beginner-friendly explanation + examples • Single-column • A4 print-ready

Topic: Containers Services: ECR • ECS • EKS • (Docker Hub) Goal: Store & share container images

1) Big Picture: What is ECR?

🧠 Core idea: ECR is AWS’s managed place to store container images so that ECS/EKS (or any server with Docker) can pull them later. 🙂

When you work with containers, you typically create a container image (a blueprint). To run the app, a machine or service (like ECS or EKS) must be able to download/pull that image. If you’re not running everything locally, you need an online image repository.

📌 One-sentence definition

ECR (Elastic Container Registry) is a managed container image registry where you create repositories and push/pull images for use by AWS container services (ECS/EKS) or other machines.

2) Key Terms (Exam-Friendly)

Term Meaning (Beginner-friendly)
Image 🧱 A packaged blueprint of your app + runtime needs (built with Docker). It’s what you “run” to create a container.
Container 🚀 A running instance of an image (the actual app process, live and executing).
Registry 🗃️ A service that stores images so other systems can download them (ECR is AWS’s registry).
Repository 📁 A “folder-like” place inside ECR where related images live (often one repo per app/service).
Tag 🏷️ A label for an image version, e.g. v1, latest, 2025-12-22.
Private vs Public 🔒🌍 Private: only allowed AWS identities can pull/push.
Public: share images with the world (useful for demos or open-source).

3) Why ECR Exists (Compared to “Local Only”)

😵 Without a registry

  • You build an image on your laptop… but ECS/EKS can’t see it.
  • You need a way to move that image to wherever containers run.

✅ With ECR

  • You push the image once to ECR.
  • ECS/EKS (or EC2 with Docker) pulls the image anytime it needs to run or scale.
  • You can store multiple versions using tags.

4) Typical Workflow (Simple Example)

Here’s the common “build → push → run” flow. This is conceptual (you don’t need to memorize commands for CLF-C02), but it helps you understand the moving parts. 🙂

  1. Build the image locally (Docker): docker build
  2. Tag the image with a version: :v1 or :latest
  3. Push the image to an ECR repository (so AWS can access it).
  4. Reference the ECR image in ECS task definitions / EKS manifests.
  5. Run containers. When scaling happens, ECS/EKS pulls the same image again.
# Conceptual example (not required for exam)
# 1) Build
docker build -t my-app:1.0 .

# 2) Tag for ECR
docker tag my-app:1.0 <account-id>.dkr.ecr.<region>.amazonaws.com/my-app:1.0

# 3) Push
docker push <account-id>.dkr.ecr.<region>.amazonaws.com/my-app:1.0

# 4) ECS/EKS pulls this image when starting containers
🎯 Quick mental model: ECR is “GitHub for Docker images” (not code), but inside AWS.

5) Public vs Private Repositories

🔒 Private repositories (most common)

  • Best for company/internal workloads.
  • Access controlled via AWS permissions (IAM).
  • ECS/EKS typically pulls images from private ECR repos.

🌍 Public repositories

  • Useful when you want others to pull images without AWS credentials.
  • Common for demos, sample apps, open-source tools.

6) Security Features You Should Recognize

  • 🔐 Encryption: you can enable extra encryption for repos/images.
  • 🕵️ Image scanning: scan images to detect known vulnerabilities (security hygiene).
  • 👮 Access control: decide who can push/pull (private repos) using AWS permissions.
Exam hint 🙂: If you see “store container images for ECS/EKS” → think ECR.

7) Quick Recall (Memorize These)

  • 📦 ECR = AWS-managed container image registry.
  • 📁 You create repositories to store images.
  • 🏷️ Images are versioned with tags (e.g., v1, latest).
  • 🔒 Repos can be private or public.
  • 🧰 ECR images are commonly used by ECS/EKS (and can be pulled by any Docker-capable server).
  • 🛡️ Security options include encryption and image scanning.

8) Mini Practice Questions

Q1: You built a Docker image for your app and want ECS to run it. Where do you store the image?

A: In an ECR repository (so ECS can pull it).

Q2: Your company doesn’t want the world to access images. Which repo type should you use?

A: Private repository 🔒

Q3: You want vulnerability checks on container images. Which ECR feature helps?

A: Image scanning 🕵️

9) Common Confusions (Clearing Them Up)

🤔 “Is ECR the same as ECS/EKS?”

No. ECR stores images. ECS/EKS runs containers that are created from those images. Think: Warehouse (ECR) vs Factory/Runner (ECS/EKS).

🤔 “Is Docker Hub an AWS service?”

No. Docker Hub is a popular third-party image registry. ECR is AWS’s own managed registry.
