1) What the lecture is saying (in plain words) 🙂

Up to now, you mostly learned EC2 — servers in the cloud that you rent and manage. But AWS also offers other compute options for running code. This module introduces two big categories beyond EC2:

  • Serverless compute → mainly AWS Lambda ⚡
  • Container-based compute → mainly ECS and EKS 📦
Key idea: EC2 is important, but it’s not always the best tool. AWS gives multiple compute services because different workloads have different needs.

2) Quick definitions (exam-friendly) 🧾

EC2 (baseline reference) 🖥️ Servers you manage

  • You pick instance type, OS, networking, storage.
  • You manage patching, scaling setup, uptime strategy, etc.
  • Great when you need full control (custom software, special configs).

AWS Lambda ⚡ Serverless

  • You upload code as a function.
  • AWS runs it when triggered (events), and scales automatically.
  • You don’t manage servers (no EC2 instances to patch).

Think: “Run my code when something happens.”

ECS 📦 Containers (AWS-managed orchestration)

  • Run containerized apps (Docker containers) with AWS tooling.
  • You define tasks/services, ECS schedules and manages them.
  • Often used with Fargate (serverless containers) or with EC2-backed clusters.

EKS ☸️ Kubernetes on AWS

  • Run containers using Kubernetes (industry-standard orchestrator).
  • AWS manages the Kubernetes control plane; you run workloads on worker nodes or Fargate.
  • Preferred when your team already uses Kubernetes or needs its ecosystem.

3) Beginner-friendly mental model (simple analogy) 🧩

  • EC2 = renting an apartment. You decide what to install and maintain inside.
  • Lambda = ordering a meal per request. You only “pay” when you order; no kitchen to maintain.
  • Containers (ECS/EKS) = renting a commercial kitchen where each dish is packaged in a standardized box (container). The system schedules and runs those boxes for you.

4) When to use what (practical guidance + examples) 🎯

When EC2 “shines” ✅

  • You need full OS-level control (custom agents, special networking, niche software).
  • You have a long-running app that’s easier to manage as a server.
  • You already have a traditional server setup and want a straightforward migration.
Example: “We run a legacy app that needs specific OS packages and background services.”

When Lambda “shines” ⚡

  • You want event-driven execution (something triggers your code).
  • You want automatic scaling without managing servers.
  • You have tasks like small APIs, file processing, automation, scheduled jobs.
Example: “A user uploads an image to S3 → Lambda resizes it → saves the thumbnail.” 🖼️➡️⚡➡️🗂️

When Containers (ECS/EKS) “shine” 📦

  • You want to package an application with its dependencies in a container.
  • You want consistent runs across environments: laptop → staging → production.
  • You have microservices or multiple components that need orchestration.
Example: “We deploy 5 microservices. Each service is a container. ECS/EKS keeps the desired number running and replaces unhealthy ones.”

5) EC2 vs Lambda vs ECS vs EKS (very quick compare) 🧠

Service What you manage Best for Simple phrase
EC2 Servers/OS, scaling setup, patching strategy Full control, custom setups, traditional workloads “Rent servers.”
Lambda Only your function code + config Event-driven jobs, lightweight APIs, automation “Run code on events.”
ECS Containers, task/service definitions (AWS orchestration) Container apps without Kubernetes overhead “Run containers (AWS-managed).”
EKS Kubernetes workloads + cluster setup decisions Standard Kubernetes deployments, portability “Kubernetes on AWS.”

For CLF-C02, focus on the core idea and typical use cases—not deep configuration details.

6) Key takeaways (memorize these) 📌

  • ✅ EC2 is important, but AWS compute includes serverless and containers.
  • ⚡ Lambda = run code without managing servers (event-driven).
  • 📦 ECS/EKS = run containerized workloads (different orchestration styles).
  • 🎯 Choose based on control vs convenience, and workload shape (event-driven, long-running, microservices).

7) Mini quiz (with answers) ✍️

Q1. What is the main “message” of this module intro?
A: EC2 is not the only compute option. AWS also offers serverless (Lambda) and container compute (ECS/EKS), and you should understand when they’re better than EC2.
Q2. Which service is the most associated with “serverless functions”?
A: AWS Lambda.
Q3. If you want Kubernetes on AWS, which service should you remember?
A: Amazon EKS.
Q4. Give one simple example where Lambda is a good fit.
A: Image resize after S3 upload; scheduled cleanup job; small API endpoint; reacting to database changes—anything event-driven.
