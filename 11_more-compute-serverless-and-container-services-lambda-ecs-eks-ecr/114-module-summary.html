📌 Module Summary — Compute Beyond EC2: Lambda + Containers

AWS Certified Cloud Practitioner (CLF-C02) — Reviewer / Study Guide (Print-ready A4, Single Column)

Focus: EC2 vs Serverless (Lambda) vs Containers (ECS/EKS/Fargate) + Image Registry (ECR)
Goal: Understand what each service does, when to use it, and the key exam keywords.

🧭 Big Picture (What this section was about)

This module introduced alternative compute models to running code on EC2 virtual servers. You can often achieve the same business goal (run code) in different ways — but the operational effort, pricing model, and best-fit workloads differ.

Key idea: You can “mix and match” compute approaches. Many real systems use EC2 + Lambda + Containers together. 🙂
  • 🖥️ EC2 = rent servers (high control, more ops work)
  • ⚡ Lambda = run code on-demand (event-driven, serverless)
  • 📦 Containers = package code + runtime environment (portable, microservices-friendly)
  • 🏷️ ECR = store container images so ECS/EKS can pull them

🔍 EC2 vs Lambda vs Containers (Core Differences)

Compute Option What you manage Best for
EC2 🖥️ OS + installed software + patches + long-running processes. You choose instance type, networking, scaling approach. Web servers, custom software stacks, legacy migrations, long-running jobs, custom networking needs.
Lambda ⚡ You upload code + set triggers + configure runtime (memory, timeout, env vars). No server management. Event-driven tasks (file processing, automation), short-lived compute, “only pay when used”.
Containers 📦 Build images; define tasks/services; runtime managed by ECS/EKS. Optional: use Fargate to avoid managing EC2 worker nodes. Microservices, consistent deployments, portability (“works the same everywhere”), scaling web APIs.
Exam pattern: If the scenario says “event triggers code execution” → think Lambda ⚡. If it says “package runtime + dependencies” → think Containers 📦. If it says “full control over OS” → think EC2 🖥️.

⚡ AWS Lambda (Serverless, Event-Driven Compute)

Definition

Lambda runs your code in response to events without you provisioning or managing servers.

What you configure (typical)
  • 🧩 Function code (console editor, ZIP upload, or container image)
  • ⏱️ Timeout (max execution time)
  • 🧠 Memory (affects performance and cost)
  • 🌱 Environment variables
  • 🔐 IAM execution role (permissions)
  • 🪝 Triggers (S3 events, API calls via other services, schedules, etc.)

Beginner-friendly example

🖼️ Image processing workflow: A user uploads a JPG to an S3 bucket → that upload event triggers Lambda → Lambda resizes the image and saves it to another bucket. 

Event: S3:ObjectCreated (new file)
Lambda: resizeImage(file)
Output: save resized file to another S3 bucket
Pricing intuition: You pay for execution time (milliseconds) and resources used — not for idle time. Many accounts also have a recurring free-tier allowance each month. 💡

📦 Containers (Concept Refresher)

A container is a packaged unit that contains your application code plus the runtime environment it needs. This helps ensure consistent behavior across environments (local → test → production).

  • 🧱 Image = blueprint (what to run, dependencies, runtime)
  • 🚀 Container = running instance of an image
  • 🧩 Apps can be single-container or multi-container (microservices)
Common keyword: “Microservices” often appears with containers because each service can ship its own image independently. 🙂

🧰 ECS vs EKS + Fargate (Running Containers on AWS)

ECS and EKS (What they are)

  • ECS (Elastic Container Service) = AWS-managed container orchestration (AWS-native approach) 🧩
  • EKS (Elastic Kubernetes Service) = managed Kubernetes on AWS (Kubernetes-based approach) ☸️

Fargate (Serverless container execution)

Fargate is a serverless compute engine for containers used with ECS/EKS. It reduces infrastructure management: you don’t directly manage EC2 worker nodes; you focus on task-level config.

Term What to remember
Task Definition 🧾 Blueprint describing which image(s) to run and how (CPU/memory, ports, env vars).
Task ⏳ Runs and finishes (batch-style / job-style).
Service 🟢 Long-running tasks (e.g., web API) kept running and scaled to desired count.
Fargate ☁️ “Serverless containers” — fewer instance choices; simplified compute management.
Beginner-friendly example: You have a Node.js API as a container image. You run it as an ECS Service (always on) and scale it to 3 tasks behind a load balancer. 🌐

🏷️ ECR (Elastic Container Registry)

ECR is AWS’s managed container image registry. It stores your Docker images in repositories so services like ECS and EKS can pull them during deployments.

Key points to remember

  • 📁 Repositories can be private or public
  • 🔐 Supports security features like encryption and image scanning (conceptually)
  • 🔁 Typical flow: build image → push to ECR → ECS/EKS pulls image → runs containers
Developer machine:
  docker build -t my-app:1.0 .
  docker push (to ECR repo)

AWS side:
  ECS/EKS pulls image from ECR
  runs containers based on that image
Exam pattern: If the question says “store container images in AWS” → answer is usually ECR. ✅

🧠 Mini Quiz (CLF-C02 style)

  1. A file upload to S3 should automatically trigger code to resize the image. Which compute service fits best?
    Expected: Lambda ⚡
  2. You want to deploy a microservice that must run consistently with its dependencies and scale out. Which approach fits best?
    Expected: Containers via ECS/EKS 📦
  3. You need a place to store your Docker images so ECS can deploy them. Which service?
    Expected: ECR 🏷️
  4. You need full control over OS packages and want to run a long-running process. Which compute option is most suitable?
    Expected: EC2 🖥️

📚 Key Terms (Fast Recall)

  • Serverless = no server provisioning; pay mainly for usage (conceptually).
  • Event-driven = an event (S3 upload, schedule, etc.) triggers compute.
  • Lambda Function = the unit you create in Lambda containing your code.
  • Container Image = blueprint that packages app + dependencies.
  • ECS / EKS = orchestrate and manage container workloads.
  • Fargate = serverless environment for running containers (ECS/EKS).
  • ECR = AWS container image registry.

🧾 One-Line Summary

EC2 gives maximum control (you manage servers), Lambda runs code on-demand via events (no servers), and ECS/EKS run containers (often with Fargate), with ECR storing the images.
