🎯 What you’re learning in this lesson

When you build an application, you typically repeat the same loop: write code, store/share it, test + build it, and deploy it. AWS provides tools for each step to reduce manual work and mistakes.

Big idea: As systems scale (more developers, more releases), automation becomes critical. Tools like pipelines keep deployments consistent and repeatable. 🙂

🧩 The typical workflow (step-by-step)

Think of this as a simple “CI/CD-lite” flow for Cloud Practitioner level.

  1. 1) ✍️ Write code
    Use an IDE (e.g., VS Code) locally, or a cloud IDE like AWS Cloud9.
    • Local IDE: fast, familiar, works offline.
    • Cloud IDE (Cloud9): browser-based, consistent environment, useful for teams.
  2. 2) 🗃️ Store code in a remote repository
    So you can collaborate, back up work, and work from multiple machines.
    • Common: GitHub, GitLab, Bitbucket
    • AWS option: CodeCommit (managed Git repository)
  3. 3) 🧪 Run automated tests
    Validate that your code changes did not break anything (unit tests, integration tests).
    Beginner tip: Tests are like a “safety net.” They catch problems early before deployment. ✅
  4. 4) 🏗️ Build the application
    Create an output artifact: a ZIP, executable, container image, etc.
    • For containers: build a Docker image 🐳
    • For server apps: compile / bundle / package
  5. 5) 🚀 Deploy
    Move the built artifact to where it runs (servers, containers, serverless).
    • Targets mentioned in AWS tools: EC2, ECS, Lambda
  6. 6) 🔁 Repeat (automate it)
    You do this cycle frequently (sometimes many times per day), so you automate it with pipelines.

🧰 AWS services mapped to each step

✍️ Write code

Cloud9 — cloud-based IDE you can use instead of (or alongside) local IDEs.

Example: You open Cloud9 in the browser, edit your app, and run commands in the built-in terminal.

🗃️ Store code

CodeCommit — managed Git repository in AWS (similar goal to GitHub, but AWS-native).

Example: Your team pushes commits to CodeCommit so everyone can pull the latest code.

🧪 Test + 🏗️ Build

CodeBuild — managed build service that can run tests and build artifacts.

  • Runs in a controlled environment (good for consistency).
  • Can be triggered by commits or pipelines.

Example: After a push, CodeBuild runs unit tests; if they pass, it builds a deployable ZIP.

🚀 Deploy

CodeDeploy — deploys your built artifact to targets like EC2, Lambda, ECS.

Example: Deploy version v1.2.0 of your app to an EC2 Auto Scaling group.

🔁 Automate the workflow

CodePipeline — orchestrates stages (Source → Build/Test → Deploy) and automates the full loop.

Example: Every time you push to main, the pipeline runs tests, builds, then deploys automatically. 🤖

🧩 “Simplified starter”

CodeStar — a simpler way to set up a project/pipeline experience (conceptually: “getting started faster”).

Memory aid: Like how Elastic Beanstalk simplifies certain deployments, CodeStar simplifies getting started with dev tooling. 🙂

🧠 Visual memory: the flow in one line

Memorize this. Many exam questions are just “Which service fits this step?”

Write code (VS Code / Cloud9) → Store in repo (GitHub / CodeCommit) → Test + Build (CodeBuild) → Deploy (CodeDeploy → EC2 / ECS / Lambda) → Orchestrate everything (CodePipeline) → (Optional quick-start) CodeStar

📌 Beginner-friendly examples

Example A: Simple website/app update

  • 👩‍💻 You update code (fix a bug).
  • 🗃️ Push to repo (CodeCommit).
  • 🧪 CodeBuild runs tests (passes ✅).
  • 🏗️ CodeBuild packages the app.
  • 🚀 CodeDeploy deploys to EC2 (or ECS/Lambda).

Example B: You want it automatic

  • 🔁 Use CodePipeline to connect Source → Build → Deploy.
  • 🤖 Now each commit triggers a consistent release process.
Why automation matters: Manual deployments are error-prone (different settings, missed steps). Pipelines enforce a standard process. ✅

✅ Quick check (mini reviewer)

A: CodeCommit.

A: CodeBuild.

Q4: Which service deploys to EC2/Lambda/ECS? 🚀

A: CodeDeploy.

Q5: Which service orchestrates the end-to-end workflow? 🔁

A: CodePipeline.

📝 Exam-focused notes

  • 🎯 CLF-C02 typically tests service purpose, not deep configuration.
  • 🧩 If the question mentions “automate steps from source to deployment,” think CodePipeline.
  • 🧪 If it says “run tests/build in a managed environment,” think CodeBuild.
  • 🚀 If it says “deploy artifacts to EC2/Lambda/ECS,” think CodeDeploy.
  • 🗃️ If it says “store code in AWS repo,” think CodeCommit.
