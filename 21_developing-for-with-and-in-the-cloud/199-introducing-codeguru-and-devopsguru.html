AWS Certified Cloud Practitioner (CLF-C02) — Developer Services

CodeGuru & DevOps Guru — Reviewer / Study Guide

Focus: ML-powered recommendations for code quality and operational improvements 🧠🔍

1) Big Picture 🌩️

In addition to build/deploy tools (like CodeCommit, CodeBuild, CodeDeploy, CodePipeline), AWS also provides recommendation engines that use machine learning to help you improve:

  • Your code (quality, best practices, potential issues) — via Amazon CodeGuru 👨‍💻
  • Your running applications (operational signals, potential issues, optimizations) — via Amazon DevOps Guru 🛠️
Exam mindset 🎯: You usually don’t need deep configuration details. Know what each service analyzes and what output you get (recommendations/findings).

2) Service Cheat Sheet 🧾

Amazon CodeGuru Code Analysis

ML-based service that analyzes source code and provides recommendations.

  • Finds best-practice issues and common mistakes 🧩
  • Helps you write better, safer, more efficient code ✨
  • Works as a developer productivity tool (optional but helpful)

Think: “I want feedback on my code before/while I ship.” ✅

Amazon DevOps Guru Ops Analysis

ML-based service that analyzes running applications using operational signals.

  • Analyzes signals like CloudWatch metrics/logs (and other sources) 📈
  • Detects potential issues and suggests improvements 🔎
  • Helps improve reliability and operational setup 🧯

Think: “My app is running—warn me early and suggest fixes.” 🚨

3) Beginner-Friendly Explanation + Examples 🧑‍🏫

3.1 Amazon CodeGuru — What it does 👨‍💻

CodeGuru reviews your code and gives recommendations. This can include highlighting patterns that might lead to bugs, security problems, or inefficient implementations.

Simple example:

  • 🙂 You write code that works but is inefficient (e.g., unnecessary loops or expensive operations)
  • 🧠 CodeGuru flags it and suggests a better approach (best practice / optimization)
  • ✅ You apply improvements before deployment
Memory hook 🧠: CodeGuru = “Guru for your code.”

3.2 Amazon DevOps Guru — What it does 🛠️

DevOps Guru looks at your application while it is running. It analyzes monitoring data (commonly CloudWatch) and detects patterns that suggest problems or areas to improve.

Simple example:

  • 📈 Your app’s error rate gradually increases after a new release
  • 🔍 DevOps Guru detects an unusual pattern (anomaly) and surfaces a recommendation
  • 🧯 You investigate and adjust configs / resources / deployments before the issue becomes a major outage
Memory hook 🧠: DevOps Guru = “Guru for operations (running systems).”

4) When to Use Which? 🤔

  • Use CodeGuru when your goal is better code quality before it causes incidents. 🧼
  • Use DevOps Guru when your goal is better operational reliability and earlier detection of issues in production. 🧯

In practice, teams may use both: CodeGuru to reduce defects earlier, and DevOps Guru to monitor & improve the live system.

5) Quick Check (Exam-Style) ✅

Q1: You want ML recommendations to improve source code best practices. Which service? 🤓

A: Amazon CodeGuru 👨‍💻

Q2: You want ML recommendations based on CloudWatch logs/metrics to improve a running app. Which service? 📊

A: Amazon DevOps Guru 🛠️

Q3: Are CodeGuru and DevOps Guru mandatory to build and deploy apps on AWS? 🙃

A: No. They are optional, helpful services for recommendations and improvements.

6) Final Summary 🧾

  • 🧠 Both services use machine learning to deliver recommendations.
  • 👨‍💻 CodeGuru analyzes code and suggests improvements (best practices / issues).
  • 🛠️ DevOps Guru analyzes running applications using operational signals (often CloudWatch) and suggests improvements.

If you remember only one thing: Code = CodeGuru, Operations = DevOps Guru. ✅
