Module Summary: Developing for, with, and in the Cloud

Single-column, print-ready notes (A4) with beginner-friendly explanations, examples, and memory cues.

1) Big idea (what this section is about) 🧠

Deploying applications is a multi-step workflow—not only on AWS, but anywhere. The typical loop is: write → store → test → build → deploy → repeat.

Memory cue: “WSTBD” (Write, Store, Test, Build, Deploy) — then do it again. 🔁

2) Why use cloud-based dev tools? ☁️⚙️

  • Performance: a cloud build server can focus on builds/tests (no background apps like your laptop). 🚀
  • Always available: schedule builds/deployments even at 2:00 AM without waking up. ⏰
  • Team-friendly: teammates can access, trigger, monitor, and standardize processes in one place. 👥
  • Consistency: same environment each time reduces “works on my machine” problems. ✅

3) The AWS services you should know (and where they fit) 🧩

Focus on “what it does” and “where it fits in the workflow.” You don’t need deep configuration details for CLF-C02.

✍️ Write Code: Cloud9 IDE in the browser

  • Cloud-based development environment (IDE) inside the AWS console.
  • Runs on an underlying compute environment (historically EC2-backed in the course material).

Example: You open Cloud9, edit a Node.js project, run commands in the built-in terminal, and commit changes.

🗂️ Store Code: CodeCommit Git repository

  • Private Git repositories managed in AWS.
  • Stores your code history (“commits”) so you can collaborate and roll back. 🧾

Example: Push your git push to CodeCommit so teammates can pull the same code.

📦 Packages: CodeArtifact Package repository

  • Managed repository for software packages (public and private).
  • Useful when your company wants internal packages not available publicly. 🏢

Example: Your team publishes a private “company-logging-lib” and CodeBuild pulls it during builds.

🧪 Test + 🏗️ Build: CodeBuild Managed build environment

  • Runs automated tests and builds in a managed environment.
  • Controlled by a buildspec file (commands + phases). 🧾
  • Build outputs (artifacts) are often stored in S3. 🪣
# Example build steps (conceptual) Install dependencies Run tests Build the app Upload artifact to S3

🚚 Deploy: CodeDeploy To EC2 / ECS / Lambda

  • Deploys your built output to targets like EC2, ECS, or Lambda.
  • Supports deployment strategies and makes monitoring / retry / rollback easier. 🔁

Example: Deploy a new version to EC2 instances and roll back if health checks fail.

🔗 Orchestrate Everything: CodePipeline CI/CD pipeline

  • Connects stages like Source → Test → Build → Deploy.
  • Triggered automatically (e.g., on push to the repository). ⚡
  • Can include manual approval steps. ✋

Think: “Pipeline = the assembly line that runs the steps in order.”

🎛️ Simplified Setup: CodeStar Starter templates

  • Helps you get started quickly with a pre-configured CI/CD workflow.
  • Uses CodePipeline and related services under the hood. 🧱

Exam-friendly summary: CodeStar = easier “starter kit” for a typical pipeline.

🤖 Recommendations: CodeGuru + DevOps Guru ML insights

  • CodeGuru: analyzes code and recommends improvements/best practices. 🧠
  • DevOps Guru: analyzes running apps/metrics/logs and flags operational issues. 📈

4) Beginner example: putting it together 🧑‍💻

Scenario: You have a small web API and want safer, repeatable deployments.

  1. Write code in VS Code (or Cloud9). ✍️
  2. Push to CodeCommit (remote backup + collaboration). 🗂️
  3. CodePipeline detects the push and triggers CodeBuild. 🔔
  4. CodeBuild runs tests and builds the package; artifact goes to S3. 🧪🏗️
  5. CodeDeploy deploys the new version to EC2/ECS/Lambda. 🚚
  6. If deployment fails, roll back quickly. 🔁

Why this matters: you get repeatability (same steps every time), shared visibility, and less manual error. ✅

5) Quick Check (exam-style recall) ✅

  • ✅ Cloud9 = cloud IDE (write code in the browser).
  • ✅ CodeCommit = Git repo (store code privately).
  • ✅ CodeBuild = run tests/build in managed environment (buildspec controls steps).
  • ✅ CodeDeploy = deploy to EC2 / ECS / Lambda (supports rollback/monitoring).
  • ✅ CodePipeline = end-to-end CI/CD orchestration (stages + triggers).
  • ✅ CodeStar = simplified “starter” project/pipeline setup (templates).
  • ✅ CodeArtifact = managed packages repo (private + public packages).
  • ✅ CodeGuru / DevOps Guru = ML-based recommendations (code vs running ops).

📌 Fast distinction

  • Build = produce an output (package/image) from source code. 🏗️
  • Deploy = move that output to where it runs (EC2/ECS/Lambda). 🚀
  • Pipeline = automate the chain from source to deployment. 🔗
