1) Big Picture: Where Cloud9 + CodeCommit Fit

In a typical development workflow, you do this repeatedly: write code ✍️ → store code 🗂️ → test 🧪 → build 🏗️ → deploy 🚀. This page focuses on the first two steps.

Workflow step AWS service Purpose (easy meaning)
Write code ✍️ Cloud9 🧑‍💻 Cloud-based IDE (coding environment) you open in the browser.
Store code 🗂️ CodeCommit 🧾 Private Git repository hosting for saving code history (commits) and sharing with a team.
⭐ Exam mindset

For CLF-C02, focus on what each service does (the “job”) more than the deep setup details.

2) Cloud9 🧑‍💻 (Write Code in the Cloud)

What it is (beginner explanation) 🙂

Cloud9 is a cloud-based IDE (Integrated Development Environment). Think of it as “VS Code in the browser” (conceptually), where AWS prepares a development machine for you.

How it works under the hood ⚙️

  • When you create a Cloud9 environment, AWS uses an EC2 instance behind it.
  • You choose the instance type (the size/capacity of the dev machine).
  • After ~30 minutes of inactivity, the instance may be hibernated (paused) to reduce costs while preserving state (memory saved).

Note: You don’t pay “for the editor UI,” you pay for the compute (the EC2 instance) that runs it.

What you can do inside Cloud9 🧰

  • Write code in many programming languages 🧑‍💻
  • Use an integrated terminal 💻 (run commands, install packages, build demos)
  • Preview and test your work while coding 👀
🧠 Quick analogy

Cloud9 is like renting a “developer laptop” in AWS (EC2), opening it through a browser, and coding there.

3) CodeCommit 🧾 (Store Code + History with Git)

What it is (beginner explanation) 🙂

CodeCommit is AWS’s managed Git repository service. It stores your code in a private repository by default. Only you (and people you allow) can access it.

Git basics (must-know) 🧠

  • Git = source control tool (not AWS-specific).
  • Commit = a saved “snapshot” of your code changes 📸.
  • History = list of commits, so you can go back if something breaks ⏪.
  • Push = upload commits from your machine (or Cloud9) to the remote repo ☁️.

Why teams use a remote repo 👥

  • Share code with colleagues (collaboration) 🤝
  • Back up your work (laptop lost? still safe) 🔒
  • Enable automation later (tests/build/deploy pipelines) 🔁

Security & access 🔐

  • Repos are private by default.
  • Access is controlled by who you grant permissions to (IAM policies / permissions).
✅ Key takeaway

Cloud9 helps you write code. CodeCommit helps you store and share code safely (including its full change history).

4) Simple Example Workflow (Cloud9 + CodeCommit) 🧪

Here’s a beginner-friendly, realistic sequence:

  1. Open Cloud9 🧑‍💻 and create a small project folder.
  2. Initialize Git in the project folder.
  3. Make changes (write code) ✍️ and create a commit 📸.
  4. Push commits to CodeCommit ☁️ so your code is saved remotely and shareable.
# Example Git commands (conceptual)
# 1) Initialize a local repo
git init

# 2) Add files to commit
git add .

# 3) Create a snapshot (commit)
git commit -m "Add first version"

# 4) Push to a remote repository (CodeCommit remote)
# (remote setup varies, but the idea is always: push your commits)
git push

You don’t need to memorize exact commands for CLF-C02, but you should understand the concepts: commit = snapshot, push = upload to remote repo.

5) Quick Check (Exam-Style) 🧪

Questions

  • Q1: Which service provides a cloud-based IDE? 🙂
  • Q2: Which service stores your Git repositories privately in AWS? 🔐
  • Q3: What are you paying for when using Cloud9? 💸
  • Q4: What is a “commit” in Git? 📸

Answers

  • A1: Cloud9 🧑‍💻
  • A2: CodeCommit 🧾
  • A3: The EC2 instance running under the hood (compute), not “the editor UI” 💻
  • A4: A snapshot of code changes stored in history 📸

6) Tiny Glossary 📚

  • IDE: A tool for writing code, often with editor + terminal + debugging.
  • Repository (repo): A folder tracked by Git with full change history.
  • Private repo: Only authorized users can view/clone/push to it.
  • Hibernation: Pausing an instance while preserving memory state (as described in the lecture).
