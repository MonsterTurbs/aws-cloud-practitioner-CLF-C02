1) Big Picture (What problem are these services solving?)

When you build software, you typically repeat the same steps again and again: store code → test → build → deploy. Doing these steps manually is slow and error-prone. AWS provides tools to automate this workflow.

Core takeaway ✅

CodePipeline is the managed service that orchestrates your CI/CD stages (source, build, deploy, approvals, etc.).

CodeStar is the simplified “getting started” experience that can create a project + pipeline setup faster (it uses other services behind the scenes).

2) CodePipeline (CI/CD Orchestrator) 🚦

What it is

AWS CodePipeline is a managed Continuous Integration / Continuous Delivery (CI/CD) service. You define a pipeline as a set of stages that run in order. Each stage has one or more actions (e.g., pull code, run tests, deploy).

Common stages (beginner-friendly)

  • 📥 Source: fetch code from a repo (e.g., CodeCommit / GitHub).
  • 🧪 Test: run automated tests (often via CodeBuild).
  • 🏗️ Build: compile/package your app (often via CodeBuild).
  • 🚀 Deploy: ship the new version (often via CodeDeploy to EC2/ECS/Lambda).
  • 🧍‍♂️✅ Manual approval: pause until someone approves (useful for production).
  • ⚙️ Custom action: run a Lambda function for scripts/extra checks.

Triggers (how it starts)

Most common 🔔 Auto-trigger when you push code to the repository (example: push to main branch).

Also possible ▶️ Manually start an execution (for testing or one-off runs).

Monitoring and control

  • 👀 You can monitor pipeline executions (which stage is running, failed, or succeeded).
  • 🔁 You can retry failed executions or re-run a stage (depending on setup).
  • ⏸️ You can disable transitions between stages to intentionally “pause” a pipeline between two steps.
Example (simple pipeline) 🧠

You push code to CodeCommit → CodePipeline triggers → CodeBuild runs tests → CodeBuild builds an artifact → CodeDeploy deploys to EC2. Result: consistent deployments with fewer manual steps.

3) CodeStar (Simplified Setup) 🧰

What it is

AWS CodeStar is designed to make it easier to get started with a typical development workflow. Instead of assembling everything piece-by-piece, you select a template and CodeStar can provision a project with preconfigured build/deploy steps.

How to think about it

CodePipeline = powerful orchestrator you design stage-by-stage.

CodeStar = “starter kit” experience that helps you create common CI/CD setups quickly. 😌

Beginner tip 💡

If you feel overwhelmed building a pipeline from scratch, CodeStar templates can be a helpful starting point. Later, when you need full customization, you can work directly with CodePipeline and the underlying services.

4) Map the services to the workflow (memorize this)

This mapping is a common exam-style memory check.

  • ✍️ Write Code → Cloud9 (cloud IDE) or local IDE
  • 🗃️ Store Code → CodeCommit (AWS Git repo) or GitHub
  • 🧪🏗️ Test / Build → CodeBuild (managed build/test environment)
  • 📦 Packages/Dependencies → CodeArtifact (optional package repository)
  • 🚀 Deploy → CodeDeploy (deploy to EC2/ECS/Lambda)
  • 🔁 Orchestrate the entire chain → CodePipeline
  • 🧰 Simplified project + pipeline setup → CodeStar

5) Beginner examples (mental models) 🧪

Example A — Small team web app

  • 👨‍💻 Developer pushes code to CodeCommit
  • 🔔 CodePipeline triggers automatically
  • 🧪 CodeBuild runs tests
  • 🏗️ CodeBuild builds a deployment artifact
  • 🚀 CodeDeploy deploys to EC2 instances

Example B — Add a “human gate” for production

  • ✅ Deploy automatically to staging
  • 🧍‍♂️✅ Manual approval stage before production
  • 🚀 Deploy to production after approval
Why manual approval matters 🎯

It helps prevent accidental production deployments when tests pass but you still want a final review (change window, business sign-off, etc.).

6) Exam-focused mini Q&A (quick checks) ✅

Q: Which service automates the steps of a CI/CD workflow as stages?

A: CodePipeline 🚦

Q: Which service helps beginners by providing templates and a simplified setup?

A: CodeStar 🧰

Q: Can CodePipeline include steps that are not “code services”?

A: Yes — e.g., Manual approval or Lambda actions.

Q: How does CodePipeline commonly start?

A: Triggered by a code change in your repository (e.g., push to CodeCommit). 🔔

7) Key terms (fast glossary) 📌

  • 🧱 Stage: a major step in a pipeline (source, build, deploy).
  • 🧩 Action: a specific operation inside a stage (run CodeBuild, manual approval, invoke Lambda).
  • 🔁 CI/CD: automate integration (tests/build) and delivery/deployment (release).
  • 🎛️ Transition: the movement from one stage to the next (can be paused/disabled).

8) One-page summary (if you remember only this) 🧠

  • 🚦 CodePipeline = managed CI/CD pipeline orchestrator (stages + actions + triggers).
  • 🧰 CodeStar = simplified project setup using templates (often uses CodePipeline internally).
  • 🧪 CodeBuild runs tests/builds; 🚀 CodeDeploy deploys; 🗃️ CodeCommit stores code.
  • 🧍‍♂️✅ Pipelines can include manual approval or Lambda steps.
