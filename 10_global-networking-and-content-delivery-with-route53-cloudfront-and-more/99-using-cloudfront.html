1) Big Picture (What you’re doing and why) 🚀

You already have a static website hosted on S3. S3 provides a URL, but your bucket lives in a specific AWS Region (example: North Virginia / us-east-1). If users are far away (e.g., Asia), they may experience higher latency.

💡 Core idea

CloudFront creates a Distribution that caches your website content in AWS Edge Locations worldwide, so users download content from a nearby location.

🧭 Simple mental model

User (PH/Asia) → CloudFront (nearest Edge Location) → Origin (S3 bucket in us-east-1) First request: Edge pulls from S3 (cache miss) Next requests: Edge serves cached copy (cache hit) ✅

2) Key Terms (Know these for CLF-C02) 🧠

🌐 CDN (Content Delivery Network)
A network that serves content from locations closer to users to reduce latency.
📦 CloudFront Distribution
A CloudFront configuration that defines what to deliver, from where (origin), and how to cache it.
🏁 Origin
The source of your content (e.g., S3 bucket, ALB, EC2/website server). CloudFront fetches from here.
🗺️ Edge Location
AWS global locations that cache and serve content close to users.
⚙️ Cache Behavior
Rules that control what gets cached, for how long, and what request data is forwarded to the origin.
🔐 HTTPS / SSL
CloudFront can serve content over HTTPS; you can attach a certificate (ACM) for custom domains.

3) How to Use CloudFront (Step-by-Step) 🧩

✅ Starting point

You have an S3 bucket hosting a static website (HTML/CSS/JS). You can access it via the S3 website endpoint/URL.

Step 1 — Open CloudFront

  • Go to the AWS Console → search for CloudFront.
  • Create a Distribution (CloudFront is a global service, so you do not “pick a region” for the distribution).

Step 2 — Choose your Origin (S3)

  • In the distribution wizard, set Origin domain to your S3 website/bucket.
  • CloudFront will typically suggest S3 automatically. (It can also suggest an ALB, since CloudFront can front many origins.)

Step 3 — Name & identify the distribution (optional)

  • You can assign a friendly name/description to identify the distribution in your account.
  • CloudFront also generates a default domain like d123abcd.cloudfront.net.

Step 4 — Keep defaults first (recommended for learning)

  • For beginners, keep the default settings and create the distribution.
  • Deployment takes some time; once deployed, your CloudFront domain becomes active.

Step 5 — Test the CloudFront URL

  • Open the CloudFront domain in your browser.
  • CloudFront routes you to a nearby Edge Location and serves cached copies of your static files.
🌍 Important note

Distributions are global, but origins are regional (S3 bucket / ALB / EC2 lives in a specific region).

4) Cache Behavior & Policies (Why “it feels faster”) ⚡

When creating a distribution, you can define caching behavior either by: (a) selecting a caching policy or (b) configuring behavior in the wizard.

📌 What you control (conceptually)

  • What gets cached (static assets like images/CSS/JS are ideal).
  • How long it stays cached (TTL-like behavior).
  • What CloudFront forwards to the origin (headers, query strings, cookies — more forwarding often means less caching efficiency).
⚠️ Beginner trap

If you forward “too much” (cookies/query strings/headers for every request), CloudFront may cache less effectively. For a simple static website, you usually want high cacheability.

5) Custom Domain via Route 53 (Optional but common) 🧭

By default, CloudFront gives you a domain. If you want your own domain (e.g., www.example.com), you can connect it using Route 53.

✅ High-level steps

  • In Route 53, create (or use) a hosted zone for your domain.
  • Create an A / AAAA record (Alias) pointing to the CloudFront distribution.
  • (Common in practice) Attach an SSL certificate so your custom domain works with HTTPS.
🔎 Exam-friendly wording

Route 53 can create an Alias record that points to AWS resources (including CloudFront).

6) Exam Tips & Common Traps ✅

  • CloudFront = CDN that uses Edge Locations to cache content near users. 🌍
  • Distribution is global; origin is regional. 🧭
  • CloudFront is not only for S3 — it can use origins like ALB / web servers as well. 🔁
  • Default CloudFront domain works immediately after deployment; custom domains require DNS (Route 53 or other registrar). 🧾
  • Cache behavior matters: better caching = better performance, but you must avoid stale content by using correct policies/TTL. ⚙️
🧠 10-second memory hook

CloudFront = “Copy my content closer to users.” First request pulls from origin; next requests are served from Edge cache.

7) Mini Scenario (Beginner-friendly example) 🙂

You have an S3 static website in us-east-1. Users in the Philippines report slow loading. You add CloudFront:

  • Origin: S3 bucket website
  • Distribution: created globally
  • Result: CloudFront caches your index.html, styles.css, and images at Edge Locations closer to PH/Asia.
🎯 Outcome

Lower latency, faster page loads, better user experience — without deploying servers worldwide.
