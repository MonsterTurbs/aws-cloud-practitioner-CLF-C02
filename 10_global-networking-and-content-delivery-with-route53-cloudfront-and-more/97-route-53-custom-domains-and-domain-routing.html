🌐 Route 53 (DNS) — Custom Domains, Hosted Zones & Routing (CLF-C02)

Print-friendly reviewer / study guide (single-column, A4-ready). Focus: what Route 53 is, how DNS records route traffic, and a practical EC2 + ALB example.

🧠 Beginner-friendly🖨️ A4 Print📌 Exam Notes
Goal: Understand how a domain like demo1.example.com can point to an AWS resource (e.g., an Application Load Balancer) using Route 53 records.

1) Quick Overview

DNS in one sentence: DNS translates human-friendly names (e.g., example.com) into destinations (usually IP addresses, or AWS resources). 🧭

  • Route 53 is AWS’s managed DNS service (register + manage domains).
  • You manage a domain using a Hosted Zone (a container for DNS records).
  • You create DNS Records (A/AAAA/CNAME/etc.) to route traffic to services.
  • Route 53 supports advanced routing like failover and geolocation-based routing.

2) Key Terms You Must Know (Exam-Friendly)

Term Meaning (Beginner Explanation)
DNS 🌍 System that maps domain names to destinations so browsers/apps know where to go.
Domain Registrar 🧾 Company/service where you buy/own a domain name. Route 53 can be a registrar too.
Hosted Zone 🗂️ Where Route 53 stores DNS records for your domain. Think “domain configuration folder.”
DNS Record 🧩 A rule like: “When someone requests demo1.example.com, send them to X.”
A Record 📍 Routes a name to an IPv4 destination. In Route 53, it can also route to AWS resources via Alias.
Alias 🔁 Route 53 feature that lets a record point to certain AWS resources (e.g., ALB) without you typing an IP address.
Propagation ⏳ DNS changes take time to spread. You might see errors for minutes (sometimes longer) after updates.

Memory hook: Hosted Zone = container Record = rule Alias = AWS shortcut

3) Route 53 Capabilities

✅ Basic: Register + Route

  • Register a new domain (paid) or transfer an existing domain to AWS.
  • Create records to route traffic to your AWS workloads (ALB, EC2, S3 website, etc.).

🚦 Advanced Routing (Know these exist)

  • Failover: If one target is down, route to a backup target.
  • Geolocation / Geo routing: Different countries can go to different targets.
  • More complex policies exist (don’t memorize details; know the idea).

4) Concrete Example: Domain → ALB → Target Group → EC2 (Node.js)

In the lecture scenario, a simple Node.js app runs on an EC2 instance (listening on a port). An Application Load Balancer (ALB) sits in front, and the ALB forwards requests to a Target Group that contains the EC2 instance.

Why not use the EC2 public IP? Public IPs can change. People also prefer names over IPs. Route 53 solves that. 🙂

Flow (mental model)

  • 👤 User types: demo1.aws-course-demo-1.com
  • 🌐 DNS (Route 53) says: “Send this to the ALB.”
  • ⚖️ ALB forwards the request to a healthy target in its Target Group.
  • 🖥️ EC2 instance responds (e.g., Hello World).

Step-by-step (what you do in AWS Console)

  1. Buy/transfer a domain in Route 53 (optional for the exam; costs money).
  2. Route 53 creates a Hosted Zone automatically after registration completes.
  3. In the Hosted Zone, click Create record.
  4. Choose record type: A (IPv4).
  5. Optional: set a subdomain (e.g., name: demo1 → full domain becomes demo1.yourdomain.com).
  6. Turn on Alias and select the target AWS resource:
    • Alias target type: Application Load Balancer
    • Select the region where the ALB exists (ALBs are regional)
    • Select the correct ALB from the list
  7. Save the record.
  8. Wait for DNS propagation ⏳, then test in your browser.

Beginner example: Think of Route 53 like a receptionist. When someone asks for demo1.aws-course-demo-1.com, the receptionist points them to the ALB “front desk,” and the ALB routes them to an available “staff member” (EC2 instance) behind the scenes.

5) Common Pitfalls (Why It Doesn’t Work Yet)

  • “Block Public Access” vs “Public Access Allowed”: For some scenarios (like S3 website hosting), simply unblocking is not the same as granting public access. You still need correct policies.
  • Wrong region: ALB is regional; ensure your Alias target uses the ALB’s region.
  • DNS propagation delay: It can take minutes (sometimes longer). Initial errors can be normal.
  • Security groups / ports: Even if DNS points correctly, traffic fails if ALB/EC2 SG rules block it.

Tip: If troubleshooting, validate the chain: DNS record → ALB listener → target group health → EC2 app port.

6) Quick Exam Notes

  • Route 53 = managed DNS (and domain registration is also possible).
  • Hosted Zones hold DNS records for a domain.
  • Route 53 supports failover and geo routing (know the concept).
  • Alias records can point to AWS resources (e.g., ALB) instead of typing IPs.

8) One-Line Summary

Route 53 lets you attach a real domain name to AWS workloads by creating DNS records (often Alias records) inside a Hosted Zone—so users can reach your app using a friendly URL. 🚀
