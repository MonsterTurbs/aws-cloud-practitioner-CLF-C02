🌍 Big picture: delivering content is more than domains

Route 53 helps you use custom domain names (example: myapp.com), but users worldwide also care about speed. If your server is far from the user, the website can feel slower due to higher latency.

Key idea ✅ A CDN (Content Delivery Network) reduces latency by serving cached copies of your content from locations closer to users.

🚚 CDN basics (beginner-friendly)

Imagine your website is hosted in the USA. A user in the USA has a short “internet travel distance” to your server. But a user in Asia or India travels farther (network hops + physical distance), so requests and responses take longer.

🧩 What a CDN does

  • 📦 Makes a copy of your content (cache) closer to users.
  • ⚡ Users are automatically routed to the nearest cache location.
  • 🧠 Your “main server” still exists (called the origin), but many users are served from cached copies.

Translation: CDN = “serve near the user” + “cache popular content” to make things faster. 🙂

📍 Edge locations

AWS has Regions (big data center areas) and Availability Zones (separate data centers inside a region). In addition, AWS has a global network of Edge locations.

🗺️ What are Edge locations?

  • 🏢 Smaller AWS facilities distributed globally (closer to end users).
  • 🧊 Used mainly for caching and fast delivery of content.
  • ➡️ Requests are routed to the closest edge location for lower latency.

☁️ CloudFront: AWS CDN service

AWS provides a CDN service called CloudFront. CloudFront uses AWS Edge locations to cache and deliver content globally.

📦 “Distribution” (CloudFront term)

In CloudFront, you create a distribution to define what content should be delivered via the CDN. Think of a distribution as the “CDN configuration” for your website or files.

🏠 “Origin” (where the original content lives)

The origin is your main source of truth (where CloudFront fetches from when it needs the latest content). Common origins: S3 bucket, EC2 / ALB, or other HTTP endpoints.

🔁 Routing to the nearest edge

CloudFront automatically routes users to the closest edge location, so the site feels faster globally.

🧊 Caching behavior and keeping content fresh

Because edge locations store cached copies, you must consider how updates reach users. If you update your website, you don’t want users to see an outdated copy forever.

🧠 Caching policies (high-level)

  • ⏱️ Decide how long content stays cached (conceptually: “time to live”).
  • 🔄 Define when CloudFront should fetch a newer version from the origin.
  • 🎯 Goal: balance speed (more caching) vs freshness (more updates).

Simple example: If an image rarely changes, cache it longer. If a homepage changes often, cache it shorter. 🙂

🛠️ What you can configure (as mentioned in the lecture)

  • 🧾 Logging (who requested what, when)
  • 🔐 SSL / HTTPS settings (secure delivery)
  • 🧯 Security settings (control access patterns)
  • 📜 Behaviors (how requests are forwarded and cached)

🔐 Security & HTTPS basics (beginner view)

In many real systems, you want traffic to be encrypted using HTTPS. CloudFront can be configured with SSL settings so users connect securely.

Remember for the exam: CloudFront isn’t only about speed; it also supports secure delivery with SSL/HTTPS configuration. ✅

🧪 Advanced features (know they exist)

You don’t need deep implementation detail for CLF-C02, but you should recognize these concepts.

🧠 Running code at the edge

CloudFront can support executing code when requests hit edge locations (for example, to modify requests/responses). This is advanced, but the key idea is: logic can run closer to the user.

  • 🧾 Example use: add headers, rewrite URLs, basic request/response manipulation
  • ⚠️ Exam-level: just know “edge compute exists”

🧰 Examples you can reuse

Example 1: Website hosted in one country, users worldwide

Problem: Website hosted in the USA feels slow in Asia due to latency. 😕
Solution: Put CloudFront in front. Users are routed to the nearest edge location and get cached content faster. ⚡

Example 2: Distributing public files (images, PDFs)

Problem: Many users download the same files from far away, causing slow downloads and origin load. 📉
Solution: Use a CloudFront distribution so files are cached at edge locations. Faster downloads + less load on the origin. 📈

Example 3: Keeping content updated

Problem: Cached content might become outdated. ⏳
Solution: Configure caching policies so CloudFront refreshes content appropriately (faster for changing pages, longer for stable assets). ✅

📝 Exam-style takeaways (CLF-C02)

Must-know definitions

  • 🌍 CDN: Network that delivers content from locations close to users to reduce latency.
  • 📍 Edge location: AWS global caching/delivery location used by CloudFront.
  • ☁️ CloudFront: AWS CDN service that caches and delivers content globally.
  • 📦 Distribution: CloudFront configuration that defines what content is delivered and how.
  • 🏠 Origin: The original content source (S3 / EC2 / ALB / HTTP endpoint).

High-yield “why” questions

  • ❓ Why use CloudFront? → Lower latency + faster global delivery + caching.
  • ❓ What problem does it solve? → Serving users far away from your origin server.
  • ❓ What tradeoff exists? → Speed vs freshness (cached copies can become outdated without good caching rules).

One-sentence summary you can memorize: CloudFront is AWS’s CDN that caches content at edge locations to deliver it faster worldwide. 🌍⚡
