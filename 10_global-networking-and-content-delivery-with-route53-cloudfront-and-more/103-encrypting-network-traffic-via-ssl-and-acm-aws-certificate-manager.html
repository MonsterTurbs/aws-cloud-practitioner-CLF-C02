🔒 SSL/TLS + ACM (Amazon Certificate Manager) + SSL Termination

Beginner-friendly notes on encrypting network traffic for CloudFront and Load Balancers.

1) Big Idea (What problem are we solving?) 🌐➡️🔐

When users access your website, you typically want encrypted connections so that:

  • ✅ passwords, tokens, and personal data are protected in transit
  • ✅ users see HTTPS (trust + browser security)
  • ✅ attackers can’t easily read/modify traffic in the middle (MITM)
Exam cue ACM is the AWS service used to request and manage SSL/TLS certificates. 🧾

2) What is SSL/TLS in simple terms? 🧠

SSL/TLS is the technology behind HTTPS.

  • 🔐 Encryption: data is scrambled so outsiders can’t read it
  • 🪪 Identity: a certificate helps prove the site is the real site
  • 🛡️ Integrity: prevents silent tampering with data in transit

HTTP = unencrypted (not secure) HTTPS = encrypted via SSL/TLS (secure)

3) ACM (Amazon Certificate Manager) — what it does ✅

ACM helps you:

  • 📌 Request an SSL/TLS certificate for your domain (e.g., example.com)
  • 🗂️ Manage certificates in one place (renewals/availability handled by AWS for supported cases)
  • 🔗 Use certificates inside other AWS services (commonly: CloudFront, Elastic Load Balancing)

Key workflow idea: You often “touch” ACM from inside another service.

  • CloudFront Distribution → add HTTPS → “Request certificate” → ACM opens
  • Load Balancer (ALB/NLB) → add HTTPS listener → pick ACM certificate

4) SSL Termination (the important concept) 🧩

SSL termination means an AWS edge/service becomes the “HTTPS endpoint” for users:

  • 👤 User → sends HTTPS request
  • ☁️ CloudFront or Load Balancer → decrypts the request (uses the certificate)
  • 🔁 Then forwards the request to your origin/app (often HTTP) inside AWS

Why is this useful? 🎯

  • 🧰 Your EC2 app/server does not need to manage certificates directly
  • 📉 Reduced app complexity (cert renewals + termination handled upstream)
  • 🛡️ Traffic inside AWS network is not the public internet, so risk surface is reduced

5) Practical Example (CloudFront + S3 website) 🧪

Scenario: You host a static website in S3 and deliver it globally using CloudFront.

Steps (conceptual)

  1. 🪣 Create/host site files in S3 (origin)
  2. 🌍 Create CloudFront distribution pointing to S3
  3. 🔒 Enable HTTPS in CloudFront settings
  4. 🧾 Request/select an ACM certificate for your domain (e.g., www.example.com)
  5. ✅ Users access https://www.example.com and CloudFront terminates SSL

What’s happening under the hood?

  • 🌐 Browser ↔️ CloudFront: encrypted (HTTPS)
  • ☁️ CloudFront ↔️ Origin (S3): forwarded inside AWS network

6) Quick Check (Exam-style reminders) ✅

  • 🧾 ACM = request & manage SSL/TLS certificates.
  • 🔒 HTTPS uses SSL/TLS encryption.
  • 🧩 SSL termination commonly happens at CloudFront or a Load Balancer.
  • 🧠 Benefit: app/instances don’t have to handle certs + decryption logic directly.

Mini Q&A 📝

Q: “Glacier” is referenced in an exam question — what is it? 🧊

A: It usually means S3 Glacier storage classes (Instant, Flexible, Deep Archive) for long-term archival.

7) One-page Summary 🧾

  • 🔐 Encrypt user traffic using HTTPS (SSL/TLS)
  • 🧾 Use ACM to request/manage certificates
  • ☁️ Enable HTTPS on CloudFront or Load Balancers
  • 🧩 They perform SSL termination and forward requests inside AWS
