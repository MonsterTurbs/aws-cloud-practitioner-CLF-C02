🧊 The Snow Family & Snowball Edge

CLF-C02 Reviewer: moving very large datasets to AWS without the public internet — plus “edge computing” basics.

📄 Print-ready (A4) 🧠 Beginner-friendly ✅ Exam-focused 🧩 Single-column

1) Big Idea (in simple words) 🙂

The Snow Family is a set of physical devices AWS can ship to you so you can copy huge amounts of data onto the device and then ship it back. AWS imports the data into your AWS environment.

Why it exists: Sometimes sending data over the internet is too slow (bandwidth limits), too costly, or not allowed (security/compliance). Snow is the “ship it instead of stream it” option. 🚚➡️☁️

Core exam phrase: “Migrate large datasets to AWS without using the public internet.”

2) When would you choose Snow? ✅

  • 📦 You have terabytes/petabytes of data and network transfer would take too long.
  • 🔒 You prefer/require offline transfer for security or compliance reasons.
  • 🌍 Remote locations with poor connectivity (limited bandwidth).

Quick example

🏥 A hospital needs to migrate years of imaging data to AWS. Uploading over the internet would take months. Snow devices allow the hospital to load data locally and ship it to AWS for import.

3) What’s inside the “Snow Family”? 🧊

🧊 Snowcone (small)

Portable device for smaller-scale offline transfers and edge use cases. Good when you need something easy to transport.

🏋️ Snowball / Snowball Edge (medium / popular)

Designed for large transfers and commonly referenced in exams. Snowball Edge variants can also support edge computing (running workloads locally).

🚛 Snowmobile (very large)

A truck-sized solution used for extremely large data transfers (think “data center move” scale).

4) Snowball Edge = “Data transfer” + “Edge computing” ⚙️

Edge computing means you run compute near where the data is created (on-premises / remote site), instead of sending everything to an AWS Region first.

  • 📍 Compute runs at the “edge” (closer to the source).
  • ⏱️ Useful for low-latency needs, intermittent connectivity, or heavy local processing.
  • 🧰 Snowball Edge can run certain AWS-style workloads locally (conceptually: compute + storage on a rugged device).

Beginner-friendly mental model: Snowball Edge can act like a “mini data center in a box” for specific tasks — store data + run some processing locally — then sync/ship results to AWS later. 📦⚡

5) Snow vs other migration/transfer services (fast comparison) 🧭

  • DataSync 🪢: online synchronization/copy over network to AWS storage (S3/EFS/FSx). Use when network transfer is feasible.
  • Transfer Family 🔁: managed SFTP/FTP/FTPS endpoints mapped to S3/EFS (good when legacy systems require SFTP).
  • Snow Family 🧊🚚: offline, physical transport for very large datasets or restricted networks.

6) Key Takeaways for CLF-C02 📝

  • ✅ Snow Family = physical devices to move huge data to AWS without public internet.
  • ✅ Snowball Edge can also support edge computing (run workloads locally).
  • ✅ Choose Snow when bandwidth is limited, time is critical, or offline transfer is required.
