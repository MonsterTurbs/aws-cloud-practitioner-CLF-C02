🎯 What this module is about

Many companies didn’t start in the cloud (they’re not startups). They’ve been operating for years (or decades) and already have systems running on-premises (in their own data centers). This module introduces how AWS helps those companies migrate to the cloud—and how AWS supports hybrid environments where some workloads stay on-premises while others run in AWS.

Key idea ✅

Migration can be gradual and may take years. During that time (or permanently), many companies run a hybrid setup: some workloads in AWS, some on-prem.

🧩 Core terms you must know

On‑premises
🏢 Workloads running in a company’s own data center (not in a public cloud).
Cloud migration
🚚 Moving applications, servers, databases, or data from on‑prem to AWS.
Hybrid cloud
🔁 A mixed environment: some workloads stay on‑prem, others run in AWS (connected securely).
Workload
⚙️ Any unit of compute work: an app, a service, a database, batch jobs, containers, etc.

🧠 Why migration can be tricky

  • 🧱 Legacy complexity: older apps may be tightly coupled (hard to move parts independently).
  • 🗄️ Data gravity: large databases are hard/slow to move; downtime constraints matter.
  • 🔒 Security & compliance: rules may require some data to stay on-premises.
  • ⏳ Time: migration projects can take months/years; hybrid becomes the “bridge” during the journey.
  • 🔌 Connectivity: hybrid requires reliable, secure connections between on‑prem and AWS.

🧪 Beginner examples

Example A: Gradual migration (common) 🙂

  • Step 1: Keep the main database on‑prem (for now).
  • Step 2: Move the public web app to AWS (e.g., EC2 / containers) to reduce hosting burden.
  • Step 3: Connect the web app in AWS to the on‑prem database via secure networking.
  • Step 4: Later, migrate the database to AWS once ready (lower risk).

Example B: Permanent hybrid (by design) 🧩

  • Some sensitive systems must remain on‑prem (legal/compliance).
  • Analytics + reporting runs in AWS to scale easily.
  • Data sync happens securely between on‑prem and AWS.

✅ Quick memory checklist

  • ☁️ Migration = moving workloads to AWS.
  • 🔁 Hybrid = split workloads (AWS + on‑prem) connected securely.
  • ⏳ Hybrid is often temporary during multi‑year migrations—but can also be permanent.
  • 🎯 AWS offers services specifically to reduce migration complexity and win enterprise customers.

🧩 Mini Quiz (CLF-C02 style)

  1. A company has been running on-premises for 15 years and wants to move some services to AWS over the next 2 years. What setup is most likely during the transition?
    Answer

    Hybrid environment 🔁 — some workloads remain on-prem while others run in AWS during the migration.

  2. Why might a company keep some workloads on-prem even after adopting AWS?
    Answer

    Common reasons: compliance, latency, or legacy constraints 🛡️⏱️ — not everything is easy/allowed to move.

  3. True or False: Only startups benefit from AWS.
    Answer

    False ❌ — AWS targets enterprises too and provides migration + hybrid tooling to help them adopt the cloud.

📌 Key takeaway (one sentence)

AWS migration and hybrid services exist to help long‑running companies move to the cloud safely—often step‑by‑step—while keeping business running.
