Hybrid Cloud Computing — Key AWS Services

CLF-C02 reviewer / study guide (beginner-friendly). Single-column, A4 print-ready.

☁️ Topic: Cloud Migration & Hybrid 🧠 Goal: Understand what each service is for 📝 Exam focus: “When to use what?”

1) What is “Hybrid Cloud”?

Hybrid cloud means you run some workloads on AWS and some workloads on-premises (your local data center). 🌍

Simple mental model: You have “two homes” for your apps — AWS and on-prem — and you need tools to make them work together reliably (connect, store, manage, and operate).

Why companies do hybrid setups

  • 🏢 Regulations / data residency (some data must stay on-prem)
  • ⏳ Long migration timelines (years, not weeks)
  • 🔌 Legacy dependencies (old systems that can’t be moved quickly)
  • ⚡ Low-latency needs (apps must be physically near local machines/users)

2) Key AWS Services for Hybrid Cloud

Below are the services mentioned in the lecture, with beginner-friendly definitions + examples.

🧰 AWS Outposts

What it is: AWS sends physical racks/servers to your data center so you can run selected AWS services on-prem using AWS-style management.

  • ✅ Useful when you need AWS services locally (latency/compliance) but still want AWS operational model.
  • 🔁 “AWS hardware in your data center.”

Example: A factory runs a latency-sensitive app on-prem (needs millisecond response). With Outposts, they run parts of the AWS stack locally, while still integrating with AWS cloud services.

❄️ Snow Family (context for hybrid)

What it is: Physical devices mainly for data transfer without using the internet, but some devices can also do edge computing (run limited workloads locally).

  • ✅ Useful if bandwidth is poor or transferring huge data is impractical online.
  • 🧠 Think: “Move data (and sometimes run small compute) at the edge.”

Example: A media company collects terabytes of video footage on-site, then ships devices to AWS for upload and processing.

📦 ECS Anywhere & EKS Anywhere

What it is: Tools/APIs that let you run ECS or Kubernetes (EKS) workloads on your own infrastructure (on-prem), while still using AWS tooling patterns.

  • ✅ Useful if your container platform must stay on-prem but you like ECS/EKS workflows.
  • 📌 ECS = AWS container orchestration; EKS = Kubernetes-based orchestration.

Example: Your company standardizes on Kubernetes. Some clusters run in AWS, some run on-prem due to compliance. “EKS Anywhere” helps keep a consistent operational model.

🗄️ AWS Storage Gateway

What it is: A hybrid storage service that lets your on-prem environment access AWS storage (especially S3) in a more “local-like” way.

  • ✅ Useful when you want cloud storage benefits but local systems still expect “file-like” access.
  • 🧠 Lecture phrasing: “Extend S3 into your local environment.”

Example: A local app writes files to a share; Storage Gateway helps move/store those files in S3 without rewriting the app immediately.

Quick compare: DataSync is more about scheduled/managed data transfer/sync jobs; Storage Gateway is more about hybrid access patterns and “cloud-backed storage” behavior.

🛠️ AWS Systems Manager (SSM)

What it is: A service for managing fleets of servers and operational tasks from one place — and it can manage both EC2 and on-prem servers (by installing SSM Agent).

  • ✅ Useful for hybrid ops: one dashboard for patching, running commands, session access, and configuration.
  • 🔐 Requires permissions (IAM role/instance profile) and the agent installed.

Example: You have 200 EC2 instances + 60 on-prem servers. Systems Manager lets you patch them and run commands across all machines consistently.

3) “Which service should I pick?” (Exam-style cues)

If the question says…

  • “Run AWS services in our data center” → Outposts 🧰
  • “Run ECS/EKS on-prem” → ECS Anywhere / EKS Anywhere 📦
  • “Access S3 like local storage” → Storage Gateway 🗄️
  • “Manage EC2 + on-prem servers centrally” → Systems Manager 🛠️
  • “Move huge data without the internet” → Snow Family ❄️

Common beginner confusion

  • Outposts vs Snow: Outposts is long-term “AWS on-prem”; Snow is mainly “move data” (and limited edge compute).
  • DataSync vs Storage Gateway: DataSync is typically “sync/transfer jobs”; Storage Gateway is hybrid storage access patterns.
  • EKS Anywhere is still Kubernetes thinking; ECS Anywhere is ECS thinking.

4) Mini Scenarios (Beginner Examples)

  • 🏥 Hospital with compliance rules: keep patient records on-prem, but run analytics in AWS → use hybrid connectivity + Storage Gateway for storage patterns, plus Systems Manager for unified operations.
  • 🏭 Manufacturing plant (low latency): run control systems locally but still use AWS services → consider Outposts.
  • 🧑‍💻 Dev team uses containers everywhere: some clusters in AWS, some on-prem → EKS Anywhere (Kubernetes) or ECS Anywhere (ECS model).

5) Self-check Quiz (with answer key)

Tip: Try answering first. Click “Show answers” on screen; answers always appear when printing.

Q1. You need AWS-managed services running inside your local data center. Which service fits best? 🧠

A1: AWS Outposts 🧰 — AWS ships racks/servers so you can run AWS services on-prem.

Q2. You want to run ECS/EKS workloads on-prem (not in AWS) but keep familiar tooling. What do you use? 📦

A2: ECS Anywhere and/or EKS Anywhere 📦.

Q3. Your legacy app expects file-like access, but you want storage in S3. What’s a key hybrid option? 🗄️

A3: AWS Storage Gateway 🗄️ — helps extend S3 usage patterns into on-prem environments.

Q4. You must manage and patch EC2 instances and on-prem servers from one place. What service? 🛠️

A4: AWS Systems Manager 🛠️ — install SSM Agent on servers to manage them centrally.

Q5. You need to move massive data to AWS but network transfer is too slow. What family of solutions? ❄️

A5: Snow Family ❄️ — physical devices for offline data transfer (and some edge compute capabilities).

6) Quick Memory Hook

  • 🧰 Outposts = AWS racks in your building
  • 📦 ECS/EKS Anywhere = containers on-prem with AWS patterns
  • 🗄️ Storage Gateway = S3 feels local
  • 🛠️ Systems Manager = manage everything (cloud + on-prem)
  • ❄️ Snow = ship data (and sometimes run small compute)
