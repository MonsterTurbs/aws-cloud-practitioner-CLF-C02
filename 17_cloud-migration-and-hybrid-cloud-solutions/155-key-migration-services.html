Identify the right AWS migration service based on the problem

🧭 Tracking 🖥️ App/Server move 🗄️ Database move 📁 File move 🔁 Legacy file transfer 🚚 Massive datasets
💡 Beginner translation
Migration is typically done step-by-step so business stays online. AWS offers different tools depending on whether you’re moving apps/servers, databases, or files—plus special options for legacy transfer protocols (SFTP) and very large data (physical devices).

🧾 Quick Map: Service → Best Use Case

Service What it does (simple) Example (exam-style)
Migration Hub 🧭 Tracks migration progress in one place “We are migrating many servers and want a single dashboard to track everything.”
Application Migration Service 🖥️ Migrates servers/apps by replicating on‑prem to AWS (often EC2) “Move a local VM/server to AWS quickly without rebuilding manually.”
Database Migration Service (DMS) 🗄️ Migrates databases/data to AWS DBs (e.g., RDS), same or different engines “Migrate Oracle → MySQL” or “MySQL → MySQL into RDS.”
DataSync 📁 Copies/synchronizes files to AWS storage (e.g., S3 / EFS / FSx) “Sync file server data into S3 as we migrate.”
AWS Transfer Family 🔁 Provides managed SFTP endpoints mapped to S3/EFS “Legacy partner can only upload via SFTP, but we want data stored in S3.”
Snow Family 🚚 Move huge data using physical devices (when internet transfer is too slow or not allowed) “We must transfer PB-scale data quickly without relying on the internet.”
🧠 Memory shortcut
Hub = Track App Migration = Servers/Apps → EC2 DMS = Databases DataSync = Files Transfer Family = SFTP → S3/EFS Snow = Physical shipping

🧭 Migration Hub (Visibility)

✅ Main purpose: give a central dashboard to track the overall migration process.

  • 👀 Visibility is critical: you want to confirm systems work after migration and identify blockers early.
  • 🧾 Migration Hub is not “the mover”; it’s the “tracker.”
Example
“We have multiple migrations happening (apps, DBs, files). We want one place to monitor the status.” → Migration Hub 🧭

🖥️ Application Migration Service (Move apps/servers)

✅ Main purpose: migrate applications by replicating your on‑prem environment to AWS (commonly onto EC2).

  • 🧩 Install an agent on your local systems (servers in your data center).
  • 🔎 The agent analyzes OS + installed software + configs + workloads.
  • 📦 AWS replicates it into the cloud to reduce manual rebuild effort.
Beginner-friendly example
You have a legacy server running a business app. Instead of manually creating EC2 + reinstalling everything, you install the agent and migrate by replication.

🗄️ Database Migration Service (DMS)

✅ Main purpose: move database data from on‑prem to cloud databases (e.g., RDS).

  • 🔁 Homogeneous migrations: same DB engine → same DB engine (e.g., MySQL → MySQL).
  • 🔀 Heterogeneous migrations: different engine → different engine (e.g., Oracle → MySQL).
  • 🧱 Can support schema changes/conversions as needed during migration.
Exam clue
If the question explicitly says “migrate a database,” your answer shortlist should include DMS.

📁 DataSync (Migrate/sync files)

✅ Main purpose: synchronize/copy files from on‑prem to AWS storage such as S3, EFS, or FSx.

  • 🔄 Think: “If we add a file locally, it gets copied to the cloud.”
  • 🧰 On-prem environments can use protocols like NFS to integrate with file systems.
  • 🚫 Common confusion: this is not for EBS and not for database rows (that’s DMS).
Example
“We are migrating a shared drive to AWS and want continuous syncing into S3.” → DataSync 📁

🔁 AWS Transfer Family (Keep SFTP workflows)

✅ Main purpose: map managed SFTP endpoints to S3 or EFS.

  • 🏢 Many legacy systems depend on FTP/SFTP uploads to a server endpoint.
  • 🧱 S3/EFS don’t provide classic “FTP server endpoints” out of the box.
  • 🧩 Transfer Family provides a managed endpoint (like a proxy) and stores uploads into S3/EFS.
How to recognize it in questions
Look for: “SFTP”, “FTP”, “file transfer endpoint”, “legacy system uploads files.”

🚚 Snow Family (Physical device migration + edge compute)

✅ Main purpose: transfer very large data without relying on the internet.

  • 🐢 Use when internet transfer is too slow (bandwidth limits) or not acceptable (policy/security).
  • 📦 AWS ships devices → you copy data onto them → ship back → AWS imports data.
  • 🧠 Extra: some Snow devices can run compute tasks near the data source (“edge computing”).

Three main products (size intuition)

  • 🧊 Snowcone: small + portable.
  • 🏐 Snowball: larger device for bigger transfers.
  • 🚛 Snowmobile: truck for extreme scale (exabytes).
Example
“We need to move petabytes of archived footage to AWS quickly, and network upload would take months.” → Snow Family 🚚

⚖️ Quick Confusion Fixes

Confusing pair Fast decision rule
DataSync 📁 vs DMS 🗄️ DataSync = files. DMS = databases.
Transfer Family 🔁 vs DataSync 📁 Transfer Family = SFTP endpoint to S3/EFS. DataSync = sync/copy file systems.
Migration Hub 🧭 vs Application Migration Service 🖥️ Hub = track. App Migration Service = move/replicate servers.
Snow Family 🚚 vs “upload over internet” Snow = when the data is too large or internet transfer is too slow/not allowed.

🧪 Mini Quiz (Tap “Toggle Answer Key”)

1) You want a central place to track the overall migration progress. Which service?
✅ Migration Hub 🧭
2) You want to replicate on‑prem servers into AWS (typically EC2) without rebuilding manually. Which service?
✅ Application Migration Service 🖥️
3) You want to migrate Oracle → MySQL into AWS. Which service?
✅ Database Migration Service (DMS) 🗄️
4) You want to continuously synchronize on‑prem files into S3. Which service?
✅ DataSync 📁

✅ AWS Transfer Family 🔁

✅ Snow Family 🚚

Exam tip: Always identify the “thing being migrated” (apps vs DB vs files) and look for protocol/scale clues (SFTP → Transfer Family, huge → Snow).

✅ One-minute Summary

  • 🧭 Migration Hub = track everything.
  • 🖥️ Application Migration Service = replicate/move servers/apps to AWS (often EC2).
  • 🗄️ DMS = migrate databases (same engine or different engine).
  • 📁 DataSync = sync/copy files to S3/EFS/FSx.
  • 🔁 Transfer Family = managed SFTP endpoint backed by S3/EFS.
  • 🚚 Snow Family = physical device/truck for huge data + optional edge compute.
