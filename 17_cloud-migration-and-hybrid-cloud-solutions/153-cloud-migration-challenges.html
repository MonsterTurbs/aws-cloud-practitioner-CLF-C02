Cloud Migration Challenges (AWS CLF-C02)

Reviewer / study guide — beginner-friendly notes with examples

☁️ Migration 🧠 Exam Focus 🕒 Downtime & Continuity 💸 Cost Estimation 🛠️ Refactor / Rewrite

Big Idea

Moving workloads from on‑premises (your own servers) to AWS is rarely “copy and paste.” Migration takes time, must protect business continuity, and often requires cost planning and code changes.

Memory tip 🧩 Think: “No downtime, know the cost, update the code, and (optionally) modernize.”

Key Challenges You Must Remember

  • ⏳ Migration takes time: transferring applications and data to cloud services isn’t instant.
  • 🟢 Workloads must not be interrupted: production systems should remain available during migration.
  • 💸 Cost estimation is required: once you have a target architecture idea, you must estimate ongoing costs (compute, storage, data transfer, managed services, etc.).
  • 🧩 Code/workloads may need adjustment: apps that rely on local network assumptions or environment specifics may break in the cloud.
  • 🚀 Optional “cloud-native” modernization: you may refactor or rewrite parts of the app to use AWS-managed services for better scalability and operations.

Beginner-Friendly Examples

🛒 Example: Online shop cannot go offline

If your store is down for weeks during migration, you lose sales and customer trust. That’s why companies use phased migration, parallel environments, and cutover plans.

🌐 Example: Code relies on “local network” settings

An app might assume it can reach a database using an internal IP or a local hostname. In AWS, networking changes (VPC, subnets, security groups), so the app may need configuration or code updates.

📦 Example: Adopting AWS services (SQS / DynamoDB)

If you decide to use SQS for decoupling apps or DynamoDB for a managed NoSQL database, your code must call AWS APIs (usually via the AWS SDK). This is a “modernization” step, not just migration.

Quick Checklist (Exam-Style)

  • ✅ Plan for minimal / zero downtime (business continuity).
  • ✅ Create a target architecture and estimate cost early.
  • ✅ Identify dependencies (networking assumptions, OS dependencies, file paths, integration points).
  • ✅ Decide: lift-and-shift vs refactor (or a mix).
  • ✅ Expect iterative work: testing, validation, and gradual cutover.
Exam hint 🎯 Migration questions often test whether you understand that “moving” an app can require planning + cost awareness + compatibility changes, not just creating an EC2 instance.

Answer Key ✅
  • A1: Because production systems (e.g., online shops) must stay available; prolonged downtime can cause major business loss.
  • A2: Updates to configuration and/or code due to changed environment and networking (VPC, security groups, endpoints, assumptions).
  • A3: To embrace managed services for scalability/operations (decoupling with SQS, managed database with DynamoDB), which requires AWS SDK integration.
