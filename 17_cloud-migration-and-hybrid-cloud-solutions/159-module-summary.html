🎯 What this module is about

This section summarizes how AWS supports cloud migration and hybrid cloud setups. Many companies started with on‑premises data centers, so moving to AWS can be challenging.

🧠 Remember

In the exam, questions are usually: Which service helps migrate apps? Which service moves databases? Which is most secure for connectivity?

🧩 Core ideas (simple explanation)

☁️ Cloud migration

Moving existing workloads from on‑prem (your own servers) to AWS. Challenges include planning cost, avoiding downtime, and dealing with complex networking.

🏢 Hybrid cloud

Keeping some workloads on‑prem while running some in AWS. This can be temporary (during migration) or permanent (company decision).

💡 Beginner example

You keep your legacy payroll system on‑prem (strict requirements), but move your public website and backups to AWS. That is a hybrid setup.

🧰 Migration services you should recognize

Focus on the “what does it migrate?” question.

🧭 Migration Hub (visibility / tracking)

  • 📍 Central dashboard to track migration progress across multiple migration tools/tasks.
  • ✅ Use when you need visibility and coordination for a larger migration.

🖥️ Application Migration Service (move servers/apps)

  • 🧩 Install an agent on on‑prem servers to analyze and replicate them to AWS.
  • 🎯 Goal: migrate applications by creating equivalent workloads on EC2 in the cloud.

🗄️ Database Migration Service (move databases)

  • 📦 Migrates database data to AWS (e.g., to RDS).
  • 🔁 Supports homogeneous (same engine → same engine) and heterogeneous (engine → different engine) migrations.
  • 🧱 Can support schema conversion when needed.

📁 DataSync (sync files)

  • 🔄 Synchronizes files from on‑prem to AWS storage like S3, EFS, or FSx.
  • 🧠 Think: “I have lots of files/folders locally and want them copied/synced to AWS.”

🔌 Transfer Family (SFTP/FTP endpoints for S3/EFS)

  • 📫 Helps when you need SFTP (or FTP-like workflow) but your target storage is S3/EFS.
  • ✅ Good for legacy systems that can only push files using SFTP.

❄️ Snow Family (move huge data without the internet)

  • 🚚 Physical devices shipped by AWS to transfer very large datasets to AWS.
  • 🧊 Includes Snowcone (small), Snowball (bigger), and Snowmobile (truck-scale).
  • ⚙️ Snowball can also be used for edge computing (run some workloads locally on the device).
📝 Fast memory trick

Apps → Application Migration Service • DB → DMS • Files → DataSync / Transfer Family • Huge data → Snow devices • Tracking → Migration Hub

🔗 Connectivity options: Internet vs VPN vs Direct Connect

When connecting your on‑prem environment to AWS, you have three common options. The “best” choice depends on security, reliability, and cost.

🌐 Public Internet

  • ✅ Easiest to start
  • 💸 No special setup
  • ⚠️ Least secure compared to other options (it’s public)

🔒 VPN (Private network over the internet)

  • ✅ More secure than plain internet traffic
  • 👩‍💻 Client VPN: employees connect securely to AWS
  • 🏢 Site-to-Site VPN: connects your data center to AWS
  • (You may see terms like Virtual Private Gateway / Transit Gateway as endpoints.)

🧵 Direct Connect (dedicated private connection)

  • 🛡️ Highest security/isolation (uses AWS network, not just public internet)
  • ⚡ Often more consistent performance
  • 💰 Higher cost (requires physical connectivity to a Direct Connect location)
✅ Exam-friendly conclusion

Internet = easiest • VPN = more secure over internet • Direct Connect = most secure + dedicated link (but costs more).

🏢 Hybrid cloud: services that help

🧺 Storage Gateway

  • 🗂️ Extends S3 into your local environment (treat S3 like part of your file system).
  • 🎯 Think: “We want cloud storage benefits but still access it from on‑prem workflows.”

🛠️ Systems Manager (manage servers anywhere)

  • 🧩 Manage fleets of servers in AWS and on‑prem (install SSM Agent on servers).
  • 📌 Centralized operations: run commands, patch, manage configuration at scale.

🧱 Outposts (AWS infrastructure in your data center)

  • 🏗️ AWS ships racks/servers that run AWS services on‑prem.
  • ✅ Useful when you need AWS services locally due to latency, data residency, or strict requirements.
💡 Quick scenario

If you must keep data in your building but still want AWS-managed infrastructure, Outposts is a typical answer.

🧠 Key takeaways (memorize-ready)

  • 🚧 Migration is hard: cost planning, no downtime, complex networks, possible code adjustments.
  • 🧭 Migration Hub = track everything (visibility).
  • 🖥️ Application Migration Service = replicate servers/apps to AWS (EC2).
  • 🗄️ DMS = migrate databases (same engine or different engine).
  • 📁 DataSync / 🔌 Transfer Family = move/sync files to AWS storage.
  • ❄️ Snow Family = move huge datasets without using the public internet; Snowball can do edge compute.
  • 🔗 Connectivity choices: Internet (easy) → VPN (more secure) → Direct Connect (most secure, higher cost).
  • 🏢 Hybrid helpers: Storage Gateway (S3 locally), Systems Manager (manage on‑prem + cloud), Outposts (AWS on‑prem).

✅ One-sentence “exam answers”

  • 🧭 Migration Hub: Central place to track migration progress.
  • 🖥️ Application Migration Service: Agent-based replication of servers/apps to AWS (EC2).
  • 🗄️ DMS: Migrates databases; supports homogeneous/heterogeneous migrations.
  • 📁 DataSync: Sync/copy files to S3/EFS/FSx.
  • 🔌 Transfer Family: Managed SFTP endpoints that map to S3/EFS.
  • ❄️ Snow Family: Physical devices for offline bulk data transfer; Snowball supports edge compute.
  • 🔒 VPN: Encrypted private network over the internet (client or site-to-site).
  • 🧵 Direct Connect: Dedicated private connection into AWS network.
  • 🏢 Outposts: AWS infrastructure/services in your on‑prem data center.
  • 🛠️ Systems Manager: Central ops for cloud + on‑prem servers (via SSM Agent).
