AWS S3 Storage Classes (incl. Glacier) — Reviewer / Study Guide

📦 AWS S3 Storage Classes (incl. Glacier) — Reviewer / Study Guide

Beginner-friendly notes on choosing the right S3 storage class based on access patterns, cost, and retrieval speed.

🎯 Goal: Save cost without breaking your app 🧠 Exam Focus: Know what each class is “for” 🧊 Glacier = archival (restore needed)

1) Big Idea: Why Storage Classes Exist 💰

In S3, you pay primarily for how much data you store and (often) how you access it. AWS offers different storage classes because files don’t all behave the same:

  • 📈 Some objects are read constantly (e.g., website images, app assets).
  • 📉 Some objects are rarely opened (e.g., old invoices, archived logs).
  • 🗄️ Some objects are kept for compliance (accessed once a year or never).
✅ Rule of thumb

The less often you access an object and the longer you can wait to retrieve it, the cheaper the storage can be.

⚠️ Common mistake

Putting frequently-used objects into an “infrequent” or “archive” class can backfire because retrieval costs and/or restore delays can hurt performance and increase cost.

2) Access Patterns (Simple Categories) 🧭

⚡ Frequent access

Used constantly; you need instant access. Default is usually S3 Standard.

🕒 Infrequent access

Used occasionally; you still want quick access, but accept a retrieval fee when you read it.

🧊 Archive

Kept long-term; retrieval may require a restore step and could take minutes to hours. Great for backups and compliance.

🤖 Unsure / mixed

Use Intelligent-Tiering so AWS can move objects based on observed access patterns.

3) Storage Class Cheat Sheet 🧾

This table is “what to pick” in plain terms. Exact pricing varies by region.

⚡ S3 Standard Frequently accessed objects (app assets, active content) ✅ Instant access
💡 Usually the default class
💰 Higher storage cost vs. archival
🕒 S3 Standard-IA (Infrequent Access) Occasionally accessed objects (monthly reports, older images) ✅ Instant access

💰 Lower storage cost than Standard
🏝️ S3 One Zone-IA Infrequent access where you accept “single AZ” tradeoff (recreatable data) ✅ Instant access
💸 Retrieval fee
💰 Cheaper than Standard-IA in exchange for resilience tradeoff
🧊 S3 Glacier Instant Retrieval Archive data that still needs milliseconds access (quarterly access) ⚡ Millisecond retrieval (no restore wait)

💰 Lower storage cost than Standard-IA
🧊 S3 Glacier Flexible Retrieval Archive data accessed 1–2× per year (backups, DR) ⏳ Restore required: minutes to hours (depends on tier)
💸 Retrieval cost (bulk can be cheaper)
💰 Lower ongoing storage cost
🧊 S3 Glacier Deep Archive Long-term compliance retention (almost never accessed) 🕰️ Restore required: hours (very slow, cheapest storage)
💸 Retrieval cost when needed
💰 Lowest storage cost (for long retention)
🤖 S3 Intelligent-Tiering Unknown or changing access patterns 🔁 AWS moves objects between tiers based on access
💰 Can save money without manual decisions

🧠 Beginner translation
  • Standard = “I use it a lot.”
  • Standard-IA / One Zone-IA = “I don’t use it often, but when I do, I want it now.”
  • Glacier classes = “I’m storing this for a long time, and I can wait (or restore) when needed.”
  • Intelligent-Tiering = “I’m not sure — let AWS decide.”

4) Glacier: What “Restore” Means 🧊➡️📦

For archival storage classes (especially Glacier Flexible Retrieval and Deep Archive), objects are not always immediately readable. You typically:

  1. 📝 Submit a restore request.
  2. ⏳ Wait (minutes to hours, depending on tier/class).
  3. ✅ Access a temporary restored copy for a chosen period.
⚠️ App design note

If your application must serve files instantly (e.g., user profile photos), avoid archival classes unless you’re using an instant-retrieval option.

5) How You Choose a Storage Class in the Console 🖱️

When you upload an object to a bucket in the S3 console, you can select a storage class. Typical flow:

  1. Open S3 → choose a bucket.
  2. Click Upload and select a file.
  3. Under Properties → choose Storage class.
  4. Upload the object.
💡 Practical tip

You can also use Lifecycle rules (covered later in most courses) to automatically move objects from Standard → IA → Glacier over time.

6) Quick Examples (Pick the Class) 🧪

  • 🌐 Website images/CSS/JS used every minute → S3 Standard
  • 🧾 Invoices accessed once a month → S3 Standard-IA
  • 🧪 Test data you can recreate if a zone fails → S3 One Zone-IA
  • 🏥 Medical records accessed quarterly, must be fast → S3 Glacier Instant Retrieval
  • 💾 Backups used 1–2× per year → S3 Glacier Flexible Retrieval
  • ⚖️ Compliance archives accessed rarely → S3 Glacier Deep Archive
  • 🤷 Unsure which bucket objects are hot/cold → S3 Intelligent-Tiering

7) Mini Reviewer: Exam-Friendly Reminders 📝

  • Storage classes exist to optimize cost for different access patterns.
  • Frequent access = Standard; Infrequent access = IA (retrieval cost).
  • Glacier = archive; some require restore time; Instant Retrieval is “fast archive.”
  • Intelligent-Tiering = AWS automatically moves objects across tiers.
  • Pick based on: how often accessed + how fast needed + cost sensitivity.
