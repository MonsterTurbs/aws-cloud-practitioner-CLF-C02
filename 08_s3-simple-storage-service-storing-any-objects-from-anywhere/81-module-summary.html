🗂️ AWS S3 — Module Summary (Reviewer / Study Guide)

Object Storage • Buckets • Storage Classes • Security • Advanced Features

📄 A4 print-ready 🧠 Beginner-friendly ✅ CLF-C02 oriented 🧩 Single-column
Big idea (in one sentence): ☁️ S3 stores objects/files in the cloud inside buckets—you don’t manage disks or servers; you manage files, access, and storage behavior.

1) What S3 is (and what it is not) 🧠

  • S3 = Object Storage 📦 → focus is the file/object, not the disk or file system.
  • You don’t format a drive, mount a volume, or manage capacity ahead of time. ✅
  • It’s not like a traditional server hard drive (that’s more like EBS) and not like a shared network file system (that’s more like EFS).
Beginner mental model: 🗄️ Think of S3 as an “unlimited cloud folder service” with strong security controls and different “storage modes” (classes) to save cost.

2) Buckets & (pseudo) organization 🪣

  • Buckets are containers for objects. You create a bucket first, then upload files into it.
  • S3 is flat internally (no true folders), but you can use prefixes to simulate folders.
Example (prefix “folders”):
  • invoices/2025/INV-0001.pdf 📄
  • invoices/2025/INV-0002.pdf 📄
  • uploads/images/user123/avatar.png 🖼️
It looks like folders, but S3 treats these as object keys (names) with a common prefix.
Reminder: Bucket naming is strict. In many AWS setups, bucket names must be globally unique (not just unique in your account). 🔒

3) How you access S3 (lots of options) 🔌

One key advantage of S3 is that it’s not “attached” like EBS/EFS. You can upload, retrieve, and delete objects using multiple access paths:

  • 🧭 Management Console (web UI)
  • 💻 AWS CLI (commands)
  • 🌐 HTTP API (via SDKs / applications)
  • 🧩 AWS SDKs (Node.js, Python, Java, etc.)
Example: A web app on EC2 uploads user photos to S3 using the SDK; a developer later downloads the same file using the CLI.

4) Storage Classes (cost vs access pattern) 💸

S3 storage classes help you save money by choosing the class that matches how often you access a file.

Frequent access ⚡
  • Best for files used often (daily/hourly).
  • Fast retrieval; typically higher storage cost.
Infrequent access 📆
  • Store cheaper, but you may pay a retrieval fee.
  • Good for files used “sometimes”.
Archive (Glacier classes) 🧊
  • Great for long-term retention (rarely accessed).
  • Some options require waiting before retrieval.
Intelligent-Tiering 🤖
  • AWS moves objects between tiers based on access patterns.
  • Good if you’re unsure and want automation.
Exam cue: If you see “Glacier” mentioned, it usually refers to S3 Glacier storage classes (optimized for archive/long-term storage). 🧊

5) Lifecycle Management (automate class transitions) 🔁

If file access changes over time, you can set rules to move objects automatically between storage classes.

Simple example rule:
  • Days 0–30: keep in frequent access (hot)
  • After 30 days: move to infrequent access (warm)
  • After 180 days: move to Glacier (cold archive)
✅ You save money without manually moving files.

6) Permissions & Security (control access) 🔒

  • S3 includes fine-grained access controls at bucket and object levels.
  • Common approach: Bucket Policies (policy documents similar to IAM policies, but attached to the bucket).
  • Goal: ensure files are accessible exactly as intended (private by default, public only when needed).
Common mistake: 🚫 “I disabled ‘Block public access’, so my bucket is public.”
No—disabling that setting only allows public access to be configured. You still need the right permissions/policy.

7) Encryption (object-level or bucket-level) 🔐

  • You can enable encryption per object or enforce encryption for the whole bucket.
  • Purpose: protect data at rest; leaked files are unreadable without the key.
Beginner-friendly takeaway: If security/compliance matters, turn on encryption and restrict access (least privilege). ✅

8) Advanced features you should recognize 🌟

📊 Inventory & Analytics

  • Helps you understand what’s in a bucket (counts, listings, insights).
  • Can support analytics workflows when buckets contain large numbers of objects (e.g., logs).

🧾 Versioning

  • Uploading the “same object key” can create a new version instead of overwriting.
  • Useful for rollback / recovery when a new upload is wrong.

🧷 Object Lock

  • Helps with compliance: prevent deletion or changes for a defined period (or indefinitely).
  • Designed to prove files were not altered or removed.

🧬 Replication (same-region or cross-region)

  • Automatically copies objects to another bucket (backup / resilience).
  • Can be configured within the same region or across regions for stronger protection.

🌐 Static Website Hosting

  • Host static sites (HTML/CSS/JS). No server-side code execution.
  • Low-cost alternative to running a web server for purely static content.

9) Quick “When do I use S3?” examples 🧪

🖼️ Website uploads images — where store them?
Use S3 to store the images as objects; your app can upload via SDK and serve/download later.
🧾 Need to keep invoices for 7 years with rare access?
Use S3 + Glacier storage classes (archive) and optionally Object Lock for compliance.
📄 Host a simple static landing page?
Use S3 Static Website Hosting (HTML/CSS/JS only).
🧯 Want automatic backup to another region?
Use S3 Cross-Region Replication (CRR) to copy objects to another bucket in another region.

10) Exam-friendly checklist ✅

  • ☑️ S3 = object storage (files/objects, not disks)
  • ☑️ Objects live in buckets; prefixes can simulate folders
  • ☑️ Access via console, CLI, HTTP API, SDK
  • ☑️ Storage classes match access pattern (hot/warm/cold)
  • ☑️ Lifecycle can auto-move objects between classes
  • ☑️ Security: bucket policies / permissions control access
  • ☑️ Encryption can be object-level or bucket-level
  • ☑️ Versioning, Object Lock, Replication, Static Website Hosting are key features to recognize
  • ☑️ “Glacier” usually means S3 Glacier storage classes 🧊

Tip: In exam questions, look for keywords like archive, rarely accessed, static website, replication, object lock—they often point directly to an S3 feature.
