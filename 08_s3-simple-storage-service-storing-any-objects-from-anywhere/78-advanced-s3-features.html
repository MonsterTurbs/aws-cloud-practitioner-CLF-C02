🪣 AWS S3 — Advanced Features

Reviewer / Study Guide (Beginner-friendly) • Single-column • A4 print-ready

Focus: features beyond storage classes (versioning, lifecycle rules, analytics, compliance controls, replication, encryption, and static website hosting).

🎯 Big idea

Amazon S3 is object storage. After you understand buckets, objects, and storage classes, the next step is learning features that help with: cost optimization 💰, data protection 🔐, compliance 🧾, and distribution 🌍.

1) Versioning 🧾

What it is Data protection

With Versioning, uploading a file with the same object key (same “filename”) does not overwrite the old one. Instead, S3 keeps multiple versions.

  • ✅ Helps you roll back to an older version if a new upload was wrong.
  • ⚠️ Costs more because you store more data (multiple versions).

Example 🧠: You upload report.pdf every week. If week 3 has a mistake, you can restore week 2’s version.

2) Lifecycle Management ♻️

What it is Cost optimization

Lifecycle rules automatically move objects between storage classes over time. This is useful when access patterns change (hot → warm → cold).

  • ✅ Automatically transition objects to Infrequent Access after (e.g.) 30 days.
  • ✅ Later transition to Glacier / archive tiers for long-term retention.
  • ⚠️ You must pick rules carefully—frequent retrieval from “cold” classes can increase costs.

Example 🧠: Website logs are read often in the first month → move to IA after 30 days → Glacier after 180 days.

3) Analytics & Inventory 📊

What it is Visibility

Large buckets can contain thousands or millions of objects. S3 provides features to help you understand what you store and how it’s used.

  • 📦 Inventory: get a report-like listing of objects and metadata.
  • 📈 Analytics: insights that can support decisions (e.g., storage class usage patterns).

Tip: In exams, “analytics/inventory” usually maps to: “How do we gain visibility into lots of objects?”

4) Object Lock 🔒

What it is Compliance

Object Lock can enforce retention rules so objects cannot be deleted or changed for a defined period (or potentially indefinitely). This supports compliance and audit requirements.

  • ✅ Helps prove files were not tampered with (useful for auditors).
  • 🧾 Common for legal/regulatory retention (e.g., financial records).

Example 🧠: Keep invoices immutable for 7 years to satisfy legal retention policies.

5) Replication 🧬

What it is Resilience

Replication copies objects automatically to another bucket for redundancy and disaster recovery.

  • 🏠 Same-Region Replication (SRR): copy to another bucket in the same region.
  • 🌍 Cross-Region Replication (CRR): copy to a bucket in a different region.
  • ✅ Helps with backup, resilience, and sometimes compliance (geo-redundancy).

Example 🧠: Replicate a bucket from Singapore to Frankfurt so files remain available even if a region has issues.

6) Encryption 🔐

What it is Security

S3 supports automatic encryption so files are stored encrypted “at rest.” You can apply encryption at the bucket level or object level.

  • ✅ You don’t need to manually encrypt files before upload (S3 can do it automatically).
  • ✅ Protects against data exposure if someone lacks the decryption permissions/keys.

Example 🧠: HR uploads employee documents; encryption ensures stored files remain unreadable without proper access.

7) Static Website Hosting 🌐

What it is Low-cost hosting

If your site is static (HTML, CSS, JS only), you can store those files in a bucket and enable Static Website Hosting. S3 then serves the files like a simple web server.

  • ✅ Great low-cost option for static sites (portfolio, docs, landing pages).
  • ⚠️ Not suitable for server-side code (no PHP/Node/Python execution in S3).

Example 🧠: A company marketing page (static) hosted in S3 instead of running an EC2 web server.

🧩 Exam-ready mapping
  • “Need rollback / keep old copies” → Versioning 🧾
  • “Move files to cheaper storage over time automatically” → Lifecycle rules ♻️
  • “Immutable / can’t delete for compliance” → Object Lock 🔒
  • “Copy to another bucket / another region” → Replication (SRR/CRR) 🧬
  • “Encrypt automatically at rest” → Bucket/Object encryption 🔐
  • “Host a static website cheaply” → S3 Static Website Hosting 🌐

Quick self-check ✅

  • 🙂 If I upload the same filename again, what feature preserves the older copy? Versioning
  • 🙂 If files become less used after 30 days, what feature moves them to cheaper storage? Lifecycle
  • 🙂 If auditors require “cannot delete,” what feature helps? Object Lock
  • 🙂 If I want a backup in another region, what feature helps? Cross-Region Replication
  • 🙂 If I want a simple HTML/CSS/JS site without servers, what feature helps? Static Website Hosting
