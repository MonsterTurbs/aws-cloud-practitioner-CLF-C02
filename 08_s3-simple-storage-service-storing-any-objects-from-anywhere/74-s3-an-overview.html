Amazon S3 — Overview (Reviewer / Study Guide)

Focus: Object Storage basics, buckets, organization, regions, and access control (AWS CLF-C02 level).

🗂️ Topic: S3 Object Storage 🧠 Level: Beginner / Exam-ready 🖨️ Print: A4 single-column

1) What “Object Storage” Means (and why it matters) 🧩

Core idea: With object storage, you focus on the file (object) itself — not the hard drive and not the file system.

  • ✅ You store files directly (images, PDFs, videos, backups, logs, etc.).
  • ✅ You do not manage disks, partitions, or formatting.
  • ✅ You do not “mount” S3 like a traditional drive (unlike EBS/EFS).

Beginner mental model 🧠

Think of S3 like a highly durable online “storage service” where you upload and download files on demand.

  • 📦 You put files into containers called buckets.
  • 🔎 You retrieve files by their name (key) and permissions.

2) What is S3? 🪣

Meaning of S3: Simple Storage Service ("3" because it’s Simple Storage Service).
Main purpose: Store and retrieve files (objects) from anywhere.
How you access it: Console, CLI, SDKs, and an HTTP-based API.
Object size limit: Up to 5 TB per object (file).
Number of objects: Practically “no fixed limit” for most use cases.

Key difference vs EBS / EFS ⚖️

  • 🧱 EBS = attach a raw “disk” to EC2, then you format/mount it.
  • 🗃️ EFS = managed network file system, mountable by multiple services.
  • 🪣 S3 = upload/download objects; no disk/file-system management from your side.

3) Buckets: Your Top-Level Organization 🪣

You must create a bucket to store objects in S3.

  • 🧺 Bucket ≈ “folder” conceptually, but it’s actually a top-level container.
  • 📍 Buckets are regional → you pick the region when creating them.
  • 📈 You don’t pre-allocate size; buckets scale automatically.

Bucket name must be globally unique 🌍

Not just unique in your account — unique across all AWS accounts worldwide.

Practical tip: include your company/project name + environment + random suffix.

Example bucket names:
mycompany-bpims-uploads-prod-9f3a
reymond-aws-clf-s3-notes-dev-2025

4) “Folders” in S3: Flat Storage + Prefixes 📁

S3 is technically flat: all objects sit “next to each other” inside a bucket.

But you can simulate folders using prefixes in object keys (names).

Example object keys (look like folders, but are really just names):
photos/2025/boracay/img_0001.jpg
photos/2025/boracay/img_0002.jpg
invoices/2025/12/invoice-1031.pdf

When you view these in the console, S3 shows them like folders for convenience.

5) How Files Get Into S3 (and out of S3) 🚚

  • 🖥️ AWS Console: Upload/download through the UI.
  • ⌨️ AWS CLI: Script uploads/downloads (great for automation).
  • 🧩 SDKs: Your application uses APIs to store/retrieve objects.
  • 🌐 HTTP API: Under the hood, S3 exposes HTTP endpoints.

Simple real-life examples 💡

  • 🖼️ Website image uploads: user uploads images → app stores them in S3.
  • 🧾 Invoices: system generates PDFs → saves PDFs to S3 for later download.
  • 🗄️ Backups/archives: store documents safely off your local machine.

6) Permissions: Keeping Files Secure 🔐

S3 includes a detailed permission model to control who can access which bucket/object and what actions they can do.

  • ✅ Common actions: read (download), write (upload), delete, list.
  • ✅ Permissions can be applied at bucket-level and/or object-level.

Bucket Policies (recommended) 🧾

Bucket policies are policy documents (similar style to IAM policies) attached to a bucket to define access.

  • 👍 Recommended approach for most scenarios.
  • 🧠 Exam-level takeaway: they exist, they control access, and they look like IAM policies.

ACLs (not recommended for most modern setups) ⚠️

Access Control Lists can be used and can be detailed, but generally bucket policies are preferred.

Exam note: If you see “ACL” in a question, remember it’s an older/more complex access mechanism compared to bucket policies.

7) Quick Exam Pointers ✅

  • 🪣 S3 stores objects in buckets.
  • 📍 Buckets are regional.
  • 🌍 Bucket names must be globally unique.
  • 📦 Object size limit: 5 TB.
  • 📁 “Folders” are really prefixes (flat storage underneath).
  • 🔐 Access is controlled via bucket policies (recommended) and/or ACLs (less recommended).
  • 🌐 You can use S3 directly from your computer (console/CLI) — it doesn’t need to be “attached” like EBS/EFS.
