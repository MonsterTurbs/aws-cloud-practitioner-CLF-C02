1) What is S3?

Amazon S3 (Simple Storage Service) is AWS’s object storage service for storing files (“objects”) at massive scale. 📦 In this section of the course, the focus is: what S3 is, how to store files, and the key concepts you’ll see in the console and exam.

🧩 Beginner translation: Think of S3 like a very durable, online “warehouse” for files. You upload files, then download them later—without managing disks, servers, or file systems.

2) Core Concepts You Must Know

🪣 Buckets

  • A bucket is a container that holds your objects (files).
  • You create a bucket first, then you upload objects into it.
  • In the console, you’ll typically: Create bucket → Upload → configure settings.

📄 Objects

  • An object is the file you store (e.g., image, PDF, log file, video, backup).
  • Objects live inside buckets.
  • When the lecture says “store files”, that usually means “upload objects to S3”.

⚙️ Settings when storing files

The lecture mentions “various settings we can choose when storing files.” Expect these categories throughout the S3 lessons:

  • 🔒 Access / Permissions — who can read/write the object (private vs public, etc.).
  • 🏷️ Metadata / Tags — labels to help organize, search, and bill/track usage.
  • 🧊 Storage classes — choose cost vs retrieval speed (including archival options).
  • 🛡️ Encryption — protect data at rest using AWS-managed or customer-managed keys.

3) Where S3 Fits vs EBS/EFS (Simple Comparison)

In the previous section you covered file storage via EBS and EFS. Now S3 introduces a different model: object storage.

Service What it feels like Good for
EBS 💽 Raw hard drive attached to an EC2 instance App disks, databases on EC2, low-latency block storage
EFS 🗂️ Shared network file system Shared files across multiple instances/services
S3 📦 A bucket of files (objects), accessed via API/console Uploads, backups, logs, data lakes, static site files, archival

✅ Exam mindset: If the question talks about “objects”, “buckets”, “static website hosting”, or “archiving”, think S3.

4) Typical Beginner Use Cases (with examples)

📸 Example A — User uploads for a website

If you run a website where users upload images, you can store those images in S3. Your app uploads the file to a bucket, then saves the file reference (e.g., object name) in a database.

  • App action: “Upload photo” → S3 stores the object
  • Benefit: You don’t need to manage a file server yourself

🗄️ Example B — File archival (long-term storage)

S3 supports storing files for long periods, including archival-oriented options (mentioned in the lecture). Think: compliance records, logs, historical reports.

  • Good fit: files you rarely access but must keep
  • Reason: typically lower cost storage classes for colder data

🌐 Example C — Hosting a static website

You can host a static website (HTML/CSS/JS only) in S3. “Static” means: no server-side code (no Node/PHP/Java) — just files served to the browser.

  • Upload index.html and assets (CSS/JS/images) to a bucket
  • Enable static website hosting feature on that bucket
  • Visitors load the site via the bucket’s website endpoint

5) Exam Nuggets (Quick Memory Cues)

  • 🪣 Bucket = container. 📄 Object = file in the container.
  • 📦 S3 is object storage, not a hard drive and not a traditional file system.
  • 🗄️ S3 can support archival use cases via storage class choices.
  • 🌐 S3 can host static websites (files only; no server-side compute).
