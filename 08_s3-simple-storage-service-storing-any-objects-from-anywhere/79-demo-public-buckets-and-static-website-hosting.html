🧠 Core idea (quick summary)

S3 can host files for the public internet, but it is private by default.

To publish files, you typically do two steps:

  1. ⚙️ Disable “Block all public access” (so public access is possible)
  2. 🔓 Add permissions (e.g., a bucket policy) so public access is granted

1) Making an S3 bucket public (concept + steps)

🔎 Step A: Create the bucket and allow the possibility of public access

  • Go to S3 → Create bucket.
  • Pick a globally unique name (example from lecture: aws-course-demo-website-1).
  • Pick a region (example: us-east-1).
  • Uncheck the option that blocks public access ("Block all public access").
  • Confirm that you understand the risk, then create the bucket.

📝 Important: Unchecking “Block public access” does not automatically publish your files. It only removes the guardrail so you can publish them intentionally.

⚠️ Common beginner mistake: “I unchecked Block Public Access, but my file is still private.”

That’s expected. You still need a permission rule (e.g., bucket policy) that explicitly allows public reads.

🖼️ Step B: Upload an object and test the Object URL

  • Open the bucket → Upload → add an image file (or any test file).
  • After upload, copy the Object URL and try opening it in a browser.

If the bucket is still private, the browser request is denied (because S3 has not been told to allow anonymous reads).

🔓 Step C: Add a Bucket Policy for public read-only access

Go to Permissions → Bucket policy, then add a policy that grants read-only access to anonymous users.

Beginner translation: “Let anyone on the internet download/view objects, but don’t let them upload/delete/change anything.”

Below is the typical idea of the policy shown in the lecture (replace YOUR_BUCKET_NAME with your bucket name).

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "PublicReadGetObject",
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::YOUR_BUCKET_NAME/*"
    }
  ]
}
  • Principal: "*" = anyone (anonymous included)
  • Action: s3:GetObject = read/download objects
  • Resource: .../* = applies to all objects in the bucket

Save the policy, then re-try the object URL in the browser. ✅ It should now load.

🔒 Security note: Public buckets are powerful but risky.

  • Only publish what you intentionally want public.
  • Avoid putting secrets (keys, internal reports, customer data) in public buckets.
  • In real projects, prefer controlled sharing (pre-signed URLs, CloudFront, auth) unless you truly need public files.

2) Static Website Hosting (S3 as a simple web host)

🏠 What “Static Website Hosting” means

Static website = files only (HTML, CSS, JavaScript, images). No server-side code (no Node/PHP/Python backend).

S3 can act like a simple “web server” that returns those files over HTTP.

⚙️ How to enable it

  1. Open the bucket → Properties
  2. Scroll to Static website hosting → click Edit
  3. Enable Static website hosting
  4. Choose Host a static website
  5. Set Index document to index.html
  6. Save changes

📦 Upload the website files

Upload your site files (as in the lecture):

  • index.html
  • styles.css
  • any images (e.g., the file you tested earlier)

If your objects are not publicly readable, the website may fail to load assets. Public-read permissions must align with your hosting goal.

🔗 Use the Website Endpoint URL (not the object URL)

After enabling hosting, go back to Properties → Static website hosting and copy the Bucket website endpoint URL.

That URL opens the hosted website (e.g., your index.html entry page).

📌 The endpoint is generated by AWS. You can later map a custom domain (Route 53 / DNS), which the course covers later.

🧩 Mental model: “Block Public Access” vs “Bucket Policy”

  • 🧱 Block Public Access = a safety lock. When ON, you can’t make the bucket public even if you try.
  • 🧾 Bucket Policy = the permission rule. This is what actually grants access.

Easy analogy: Block Public Access is like a master “child lock” on the door. Bucket Policy is the guest list that decides who can enter.

🧪 Example scenarios

Example 1: Public image hosting 🖼️

  • You want anyone to view an image via a URL.
  • Solution: disable Block Public Access + add public-read bucket policy for objects.

Example 2: Static portfolio site 🧑‍💻

  • You want to host a simple site with index.html + CSS + images.
  • Solution: enable Static Website Hosting + ensure public read access to site files.

📝 Exam notes (what to remember)

  • S3 buckets are private by default.
  • To make content public, you need both:
    • Allow the possibility (disable “Block public access”)
    • Grant permission (bucket policy for public read)
  • S3 can host static websites (HTML/CSS/JS) using the bucket website endpoint.
  • Custom domain mapping is possible, but not required for the basic concept.

✅ Quick checklist (hands-on)

  • ☐ Bucket name is globally unique
  • ☐ “Block public access” unchecked (only if you truly intend to publish)
  • ☐ Bucket policy grants s3:GetObject to public
  • ☐ Object URL loads in the browser
  • ☐ Static website hosting enabled
  • ☐ index.html uploaded
  • ☐ Website endpoint URL loads the site
