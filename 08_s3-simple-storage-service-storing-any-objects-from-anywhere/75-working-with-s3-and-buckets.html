🪣 AWS S3 — Working with Buckets (Reviewer / Study Guide)

Beginner-friendly notes on creating an S3 bucket, uploading files, and the key security defaults you must understand for the CLF-C02 exam.

1) What you’re learning in this lecture

  • How to find S3 in the AWS Console 🔎
  • How to create an S3 bucket and why bucket names must be globally unique 🌍
  • How to choose a region for your bucket and why it matters 📍
  • How to upload files in the console (drag-and-drop or file picker) ⬆️

Exam mindset 🧪

Remember: an S3 bucket name must be unique across all AWS accounts (not just your account). Also remember: S3 is regional (you pick a region per bucket).

2) How to create an S3 bucket (Console flow)

  1. Open the AWS Console and search for S3 🔎
  2. Click Create bucket ➕
  3. Set the bucket Name and Region 📛📍
  4. Review security and permission settings (especially public access) 🔐
  5. Click Create bucket ✅

🪣 Bucket naming (why “unique” is a big deal)

A bucket name is not only unique within your account — it must be unique across the entire AWS global namespace.

  • ✅ Good: reymond-bpims-aws-course-demo-bucket-1
  • ❌ Risky: demo-bucket (likely already taken)

Tip: Include your company name, project name, and a random suffix (numbers/date) to avoid collisions.

📍 Region selection (S3 bucket location)

You choose where the bucket lives. That determines where your files are stored.

  • ⚡ Latency: choose a region closer to your users for faster access.
  • ⚖️ Compliance: some organizations must store data in specific countries/regions.
  • 💸 Cost: pricing can vary by region, so check S3 pricing for your chosen region.
Important note 🧭

In the bucket creation screen, you pick the region for the bucket in that flow. Don’t confuse this with the general top-right region selector used in many other services.

3) Permissions & “Block Public Access” (must-know security default)

Default behavior ✅

By default, your bucket is private. Most setups start with “Block Public Access” enabled so you don’t accidentally expose files to the internet.

Why this matters: If a bucket becomes public (via policies/settings), anyone with the right URL could access your files. Sometimes that’s intended (public downloads or static website hosting), but often it’s a serious security incident. 😬

🛡️ Beginner example: Private vs Public

  • Private bucket 🔒: only approved identities can access objects (typical default).
  • Public bucket 🌐: objects can be fetched over HTTP by anyone (only enable if you truly need this).

In the console demo, copying the object URL won’t work publicly unless you intentionally make the bucket/object public via policy/config.

4) Uploading files to your bucket (Console)

Once your bucket exists, you can open it and upload files directly from the AWS Console.

  • Drag-and-drop a file into the bucket area 🖱️⬇️
  • Or click Upload and choose a file via file picker 📁

⚙️ Upload options you may see

  • Storage Class 🧊: controls cost/performance characteristics. (You’ll learn details later.)
  • Encryption 🔐: can be applied per object, and can also be enforced at the bucket level.
Beginner-friendly idea 💡

Think “Storage Class” as: how quickly you need the file and how much you want to pay. Think “Encryption” as: protecting data at rest so stored files are unreadable without proper keys.

🔗 Accessing an uploaded file

  • You can click the object in the bucket to view its details.
  • You can copy the object URL to share it.
But… ⚠️

If public access is blocked (typical default), opening that URL in a browser will fail unless the requester is authorized (e.g., signed in with permissions or using a signed URL).

🗑️ Cleaning up

If you don’t need the object anymore, you can delete it from the bucket. This matters because storage costs depend on how much you store and for how long.

5) Key takeaways (quick reviewer)

  • S3 buckets are containers for objects (files) 🪣
  • Bucket names must be globally unique 🌍
  • Each bucket belongs to a specific region 📍
  • You can upload files directly in the console (no EC2 required) ⬆️
  • “Block Public Access” helps prevent accidental exposure 🛡️
  • Object URLs don’t automatically mean “public” — permissions decide 🔐
One-sentence summary ✅

S3 is an object storage service where you create region-based buckets with globally unique names, upload files directly, and control access via strong defaults like blocking public access unless explicitly enabled.
