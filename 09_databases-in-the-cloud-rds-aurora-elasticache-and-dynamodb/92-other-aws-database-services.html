Other AWS Database Services (Quick Overview)

Beyond RDS/Aurora, ElastiCache, and DynamoDB — the “you should have heard about them” databases.

🎯 Exam mindset: This lecture is mainly recognition-based. You typically don’t need deep configuration details. Focus on: name → database type → best-fit use case.

Big Picture: Why so many database services?

  • Different apps produce different data shapes: documents, graphs, time-series, wide columns, or immutable ledgers.
  • AWS offers specialized databases so you can match the engine to the problem (performance, latency, query style, compliance).

Cheat Sheet: “Other” AWS Database Services

🧠 MemoryDB Persistent In‑Memory

Think: “Redis-like, but durable as a primary database.”

  • What it is: a persistent in-memory database (data lives in memory, but is also stored durably).
  • How it differs from ElastiCache: ElastiCache is mainly a cache layer (usually paired with another DB). MemoryDB is designed to be standalone as a primary store.
  • Use when: you need very low latency, but also need persistence (not “cache only”).
Example 💡

A gaming leaderboard or session store that must be fast like cache, but must not lose data on restart.

📄 Amazon DocumentDB Document DB

Think: “MongoDB-style documents on AWS.”

  • What it is: a document database for nested / JSON-like structures.
  • Compatibility: commonly described as MongoDB compatible (AWS’s managed alternative).
  • Use when: your data is naturally hierarchical (profiles, catalogs, content) and you prefer documents over tables.
Example 💡

Product catalog where each product has nested attributes (variants, tags, reviews, metadata).

🧱 Amazon Keyspaces Wide‑Column

Think: “Flexible columns; not strict relational schema.”

  • What it is: a wide-column database (rows can have flexible columns vs. strict SQL schemas).
  • Use when: you want scalable storage for large datasets with variable attributes per row.
Example 💡

Telemetry data where different device models send slightly different fields, but you still want structured querying by key.

🕸️ Amazon Neptune Graph DB

Think: “Relationships are first-class.”

  • What it is: a graph database for highly connected data.
  • Use when: you frequently query relationships and paths (friends-of-friends, recommendations, fraud rings).
Example 💡

Social network: users ↔ friends ↔ groups; queries like “mutual connections” or “shortest path”.

⏱️ Amazon Timestream Time‑Series

Think: “Events + timestamp, built for time-based queries.”

  • What it is: a database optimized for time-series data (timestamped measurements/events).
  • Use when: data arrives continuously (every second/minute) and you query by time windows.
Example 💡

IoT sensors sending temperature readings each second; queries like “avg temp per 5 minutes”.

📜 Amazon QLDB Immutable Ledger

Think: “Tamper-evident history of changes.”

  • What it is: a ledger database for immutable, verifiable change logs.
  • Conceptual link: similar idea to blockchain: change history is tracked and cannot be quietly altered.
  • Use when: you need an audit trail and strong integrity guarantees (compliance, financial records).
Example 💡

Track ownership transfers or transaction logs where you must prove data wasn’t edited later.

How to Answer Exam-Style Questions

✅ Pattern to memorize

  1. Identify the data shape: documents? relationships? timestamps? immutable history?
  2. Match the AWS database family: DocumentDB / Neptune / Timestream / QLDB / Keyspaces / MemoryDB
  3. Eliminate wrong answers: don’t pick a relational DB if the question screams “graph” or “time-series”.

🧪 Quick Check (Self‑Test)

  • “We need to store nested JSON user profiles, like MongoDB.” → 📄 DocumentDB
  • “We need to query relationships: recommendations, fraud rings, social graph.” → 🕸️ Neptune
  • “We collect sensor readings every second; queries are time-window based.” → ⏱️ Timestream
  • “We need a tamper-evident audit log of changes.” → 📜 QLDB
  • “We want in-memory performance, but as a primary durable database.” → 🧠 MemoryDB
  • “We need a flexible-column database for large scale.” → 🧱 Keyspaces
🔎 Tip: If the question says “AWS database overview page” or “AWS has many DB types,” the expected takeaway is usually: choose the specialized database that matches the data model (not “use RDS for everything”).
