🧩 Databases & VPCs — Public vs Private Subnets

CLF-C02 reviewer: how databases typically fit into a VPC design (web server in public subnet, database in private subnet).

📌 Topic: VPC + Subnets + Database Placement 🔐 Focus: Security & Connectivity 🧠 Level: Beginner-friendly

1) Big Idea (in one minute) ⏱️

Typical AWS setup:

  • 🌐 Web server (EC2) goes in a public subnet so it can accept requests from the internet.
  • 🗄️ Database (RDS/Aurora or self-hosted) goes in a private subnet so it is not directly reachable from the internet.
  • 🔁 The web server talks to the database using private IPs or private DNS inside the VPC.

Exam mindset: “Public app layer, private data layer.”

2) Why do we do this? (Security logic) 🔒

✅ Protect the database from direct internet access

Databases store sensitive data (users, orders, payments, etc.). Allowing the public internet to reach a database directly is risky.

Better pattern: Users talk to the web app → web app talks to DB.

✅ Enforce least privilege at the network level

Private subnets provide a strong baseline: no internet connectivity for incoming traffic to the database subnet.

You still use security groups/NACLs, but the subnet choice is the “big lock on the door.”

3) The “Common Diagram” (text version) 🗺️

This is the mental model you should remember:

Internet 🌍 | | (HTTP/HTTPS) v ┌─────────────────────────────── VPC (Your private network) ───────────────────────────────┐ | | | Public Subnet (✅ internet-facing) | | ┌──────────────────────────────┐ | | | EC2 Web Server 🖥️ | ⇄ Private IP / Private DNS ⇄ ┌───────────────────┐ | | | - accepts user requests | | Private Subnet 🔒 | | | └──────────────────────────────┘ | ┌───────────────┐ | | | | | Database 🗄️ | | | | | | (RDS/Aurora) | | | | | └───────────────┘ | | | | (no direct | | | | inbound internet)| | | └───────────────────┘ | | | └───────────────────────────────────────────────────────────────────────────────────────────┘

Key takeaway: the DB is reachable by the web server inside the VPC, but not reachable directly by random internet clients.

4) Public vs Private Subnet (simple definitions) 📚

Concept Beginner-friendly meaning
Public subnet 🌐 A subnet that can route traffic to/from the internet (commonly via an Internet Gateway + proper route table). Used for internet-facing components like a web server or load balancer.
Private subnet 🔒 A subnet without direct inbound internet reachability. Great for databases and internal services. Outbound internet access (optional) can be done via NAT Gateway.
Private IP / Private DNS 🧭 Internal identifiers used for traffic inside the VPC. Your EC2 web server uses these to connect to the database.

5) Example scenario (very practical) 🧪

Scenario: You host a website where users create accounts.

  • 👤 Users open your website in a browser → request hits your EC2 web server (public subnet).
  • 📝 The server needs to save user data → it sends a DB query to RDS/Aurora (private subnet) using private DNS/IP.
  • 🛡️ Users never connect to the database directly.

Optional: The DB server might still need to download patches/updates. Use a NAT Gateway so it can make outbound requests without becoming publicly reachable.

6) Exam cues (what to listen for) 🎯

  • ✅ “Database should not be publicly accessible” → place DB in private subnet.
  • ✅ “Web server must accept internet requests” → place web server in public subnet.
  • ✅ “App connects to DB inside VPC” → use private IP / private DNS + security group rules.
  • ✅ “DB needs outbound internet (patching)” → consider NAT Gateway.

📝 Mini-quiz: answer in your own words
  1. Why is putting a database in a private subnet a common best practice?
  2. How does a web server in a public subnet still reach a database in a private subnet?
  3. When might a private subnet resource still need a NAT Gateway?
✅ Suggested answers (open after you try)
  1. Security: it prevents direct inbound internet access to the DB layer, reducing attack surface.
  2. They communicate inside the VPC using private IP/private DNS and controlled security group rules.
  3. When the private resource needs outbound internet access (e.g., updates/patches) without allowing inbound internet traffic.

Memory hook: 🌐 Public = entry point, 🔒 Private = protected backend.
