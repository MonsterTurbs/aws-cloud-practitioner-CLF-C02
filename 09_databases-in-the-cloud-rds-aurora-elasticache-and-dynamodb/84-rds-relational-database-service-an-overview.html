📚 AWS RDS (Relational Database Service) — Reviewer / Study Guide

Beginner-friendly notes from the lecture transcript: what RDS is, how you configure it, and why it matters.

🧠 Topic: Databases in the Cloud 🗄️ Service: RDS (Managed SQL) ✅ Exam Focus: Core concepts + keywords 🖨️ Print: A4 / single-column

1) What is RDS?

✅ Definition

Amazon RDS is a managed SQL (relational) database service. You can quickly create databases using popular SQL engines (e.g., MySQL, PostgreSQL) and let AWS handle many operational tasks.

💡 “Managed” means…

AWS helps with routine database operations such as patching (optional auto minor upgrades), backups, monitoring, and high availability features like replicas (depending on configuration). You still configure key settings, but you don’t manage the underlying server directly.

2) Big picture mental model

Think of an RDS database as a database server that AWS runs for you. Under the hood, it behaves like infrastructure that lives inside your network setup:

  • 🏠 It lives in a VPC (Virtual Private Cloud).
  • 🧩 It is placed in a Subnet (public/private choices affect reachability).
  • 🛡️ It can have Security Groups (firewall rules) attached.
  • 🧠 You choose compute capacity via an instance class (similar idea to EC2 instance types).
🔎 Key idea from the lecture

Even though RDS is “managed,” it is still networked like other resources: VPC + subnet + security group decisions still matter.

3) What you choose when creating an RDS database

When you create an RDS database, you make several important choices. Here’s the beginner-friendly checklist:

3.1 Database engine + version

  • 🧩 Pick an engine (example: MySQL or PostgreSQL).
  • 🏷️ Pick a specific version (example: PostgreSQL 15.x).
  • 🔁 Optional: enable automatic minor version upgrades (patching) so AWS can apply minor updates for you.

3.2 Hardware sizing (instance class)

  • 💻 Pick an instance class (similar concept to choosing an EC2 instance type).
  • 📈 Bigger instance class generally means more CPU/RAM for handling queries and connections.

3.3 Networking (VPC, subnet, security group)

  • 🌐 Choose the VPC where the database will live.
  • 🧱 Choose the subnet (and often a subnet group) that determines where the DB can be placed.
  • 🛡️ Attach a security group to control allowed inbound/outbound traffic (firewall rules).
🧪 Simple example (conceptual)

Web app + database setup: Put your web server in a public subnet (internet-facing), but keep the database in a private subnet. Then allow DB traffic only from the web server’s security group. Result: the database is not directly reachable from the internet. ✅

3.4 Credentials + port

  • 🔐 Set login credentials (admin user + password).
  • 🔌 Decide which port is used for connections (usually defaults per engine, but it’s configurable).

3.5 High availability + replicas

  • 🧯 You can configure replication / replicas to increase availability and (depending on architecture) performance.
  • ✅ Availability benefit: if one instance goes down, another replica can keep the database available.
  • ⚡ Performance benefit (conceptual): replicas can reduce read load and may reduce latency if requests are served closer to users.

3.6 Monitoring, encryption, and backups

  • 📊 Monitoring options help you view performance/health metrics.
  • 🔒 Encryption options protect data at rest (and often in transit depending on client setup).
  • 💾 Backup configuration helps you restore if something goes wrong.

4) RDS vs self-hosting on EC2

🛠️ Self-host on EC2
  • You install DB software yourself.
  • You manage patching, backups, monitoring, failover, scaling, etc.
  • More control, more responsibility.
✅ RDS (managed)
  • AWS provides managed workflows and features.
  • You configure core settings; AWS handles much of the heavy lifting.
  • Less control, much less operational work.

6) Quick Q&A (to test your understanding)

Q1: Why do security groups matter for RDS?

A: Because they act like a firewall 🛡️—they control which sources (IP ranges or other security groups) can connect to your database.

Q2: If you want your database NOT reachable from the internet, what’s a common setup?

A: Place the DB in a private subnet and only allow inbound DB traffic from your application layer (e.g., web servers) via security groups. ✅

Q3: What does “instance class” mean in RDS?

A: It’s the hardware sizing choice (CPU/RAM profile), similar in concept to EC2 instance types. 💻

7) Common beginner mistakes (avoid these)

  • ⚠️ Putting the database in a public subnet “because it’s easier,” then accidentally exposing it.
  • ⚠️ Opening DB ports to 0.0.0.0/0 (the entire internet) when not required.
  • ⚠️ Forgetting backups or not understanding restore options.
  • ⚠️ Choosing an undersized instance class and blaming “AWS is slow” when it’s capacity related.

8) Ultra-short summary (memorize this)

🧾 20-second recap

RDS is AWS’s managed SQL database. You pick the engine/version, size it using an instance class, and place it into a VPC/subnet with a security group. You can enable features like patching, replication/replicas, monitoring, encryption, and backups to improve security, reliability, and operations.
