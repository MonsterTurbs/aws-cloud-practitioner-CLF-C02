Beginner-friendly notes from the lecture: why backups matter, how RDS handles backups, and how AWS Backup centralizes backup plans across services.

🎯 What you must understand

Core idea (exam-level)

  • ✅ Backups are critical for databases and other AWS resources (mistakes happen, failures happen).
  • ✅ Some services (like RDS) do backups automatically — you mainly configure retention.
  • ✅ If you have many resources across multiple services, AWS Backup gives you one place to define and manage backup rules.

Quick definition

Backup
A recoverable copy of data/state you can restore later (after deletion, corruption, outage, or human error).
Retention
How long backups are kept before they expire (e.g., keep daily backups for 35 days).
Centralized backups
One service and one plan to manage backups across many AWS resources.

🧠 Why backups matter in real life

  • 😬 Someone deletes a table / database accidentally.
  • ⚠️ A deployment corrupts data (bug writes wrong values).
  • 💥 A component fails (hardware or AZ disruption) and you need to restore.
  • 📋 Compliance requires keeping records for years (audits, legal retention).

Beginner example

Imagine you run a small online store. Orders are saved in a database. If the database gets corrupted, you need a backup to restore yesterday’s data and continue business.

🛠️ RDS backups (what the lecture emphasized)

Key takeaway

With RDS, backups are automatic. The key choice you typically make is how long AWS should retain them. Backups are created by AWS behind the scenes.

✅ What you configure in the RDS wizard (conceptually)

  • 🕒 Retention period: how many days to keep automated backups.
  • 📆 Backup window: when backups are preferred to run (often configured/available depending on engine/settings).
  • 🔐 Encryption (optional): protect stored data and backups.

Exam hint

If a question implies “RDS backups,” assume AWS helps heavily: it’s not “do you want backups?”, it’s usually “how long should backups be retained?”

🧰 AWS Backup (the centralized service)

What AWS Backup is

AWS Backup is a service that lets you define backup plans in one place and then assign AWS resources (like RDS databases and DynamoDB tables) to those plans.

🧩 What’s inside a “backup plan”

Plan setting What it means (simple) Example
⏱️ Backup frequency How often backups should be created. Every day at 01:00
🗓️ Retention period How long backups should be kept. Keep for 35 days
📦 Destination Where backups are stored (conceptually: a backup storage location/vault). Store in a backup vault for production
🕰️ Timeframes / windows When backups run (so they don’t collide with peak traffic). Run during off-peak hours

Beginner example

You have: 2 RDS databases (production + staging) and 3 DynamoDB tables. You create:

  • 📌 Plan A (Production): nightly backups, keep 35 days
  • 🧪 Plan B (Staging): weekly backups, keep 7 days

Then you assign the right resources to each plan.

🧷 Assigning resources to a plan

  • 🧱 You can create multiple plans (different rules for different environments/teams).
  • 🏷️ You can assign resources such as RDS instances and DynamoDB tables to those plans.
  • ♻️ You can restore backups from inside the AWS Backup service when needed.

🔎 RDS vs AWS Backup — when do you need AWS Backup?

Simple way to remember

Scenario What you typically do
Only 1–2 RDS databases ✅ RDS automated backups may be enough (configure retention).
Many resources across services (RDS + DynamoDB + more) 🗂️ Use AWS Backup to manage backup schedules/retention centrally.
Different rules per environment (Prod vs Dev) 📌 Create multiple AWS Backup plans and assign resources accordingly.

Memory anchor

🧠 RDS: “Backups happen automatically; I tune retention.”
🧠 AWS Backup: “I want one control center for backups across resources.”

🧪 Mini self-test (quick reviewer)

  1. RDS backups: Is it mainly “enable backups” or “configure retention”? (Answer: retention/config settings; backups are automatic.)
  2. What is the main advantage of AWS Backup? (Answer: centralized plans and management across resources.)
  3. Name 3 common backup plan settings. (Answer: frequency, retention, destination/time window.)
  4. Can you restore backups from AWS Backup? (Answer: yes, you can access/restore via the service.)

📝 Ultra-short summary (for last-minute review)

  • ✅ Backups are essential for databases.
  • ✅ RDS performs automatic backups; you typically configure retention.
  • ✅ AWS Backup provides centralized backup plans (frequency, retention, destination, windows) and lets you assign resources like RDS and DynamoDB.
