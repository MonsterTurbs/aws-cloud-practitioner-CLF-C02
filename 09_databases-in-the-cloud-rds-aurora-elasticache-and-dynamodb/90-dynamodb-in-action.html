📦 DynamoDB in Action — Reviewer / Study Guide (Beginner-Friendly)

Focus: How DynamoDB works in the AWS Console, how tables/items are created, and what “capacity” means for billing and exam scenarios.

Core idea (easy memory): DynamoDB is “tables-first” NoSQL. You don’t create a database server/instance. You create a table, define the primary key, then store items (records). ✅

🙂 Think of it like: Spreadsheet + ID rule, but managed, scalable, and API-driven.

1) Why DynamoDB feels different vs RDS / ElastiCache

  • 🧱 RDS: you create a database instance (managed server), choose an engine (MySQL, PostgreSQL, etc.), then create databases/tables inside it.
  • ⚡ ElastiCache: you create a cache cluster (Redis/Memcached) for fast in-memory lookups.
  • 📦 DynamoDB: you create tables directly. AWS manages the underlying infrastructure automatically.

Beginner takeaway: In DynamoDB, your “main building block” is the table, not the server.

2) DynamoDB table basics

2.1 Primary key

  • 🔑 Every item (row) must be uniquely identifiable using a primary key.
  • 🧩 At minimum you choose a Partition key (also called the hash key).
  • ➕ Optionally you add a Sort key to make a composite key (Partition + Sort).

Quick mental model:

  • Partition key = “main ID field” (e.g., ProductId)
  • Sort key = “2nd dimension” for ordering/grouping (e.g., ReleaseDate)

2.2 Schema flexibility

🧺 DynamoDB is NoSQL. Items in the same table can have different attributes (fields) — no rigid schema.

  • ✅ All items must include the key attribute(s).
  • ✅ Everything else can vary per item.

2.3 Data types

For keys, you pick a type such as:

  • 📝 String (text)
  • 🔢 Number
  • 🧾 Binary (rare for beginners)

For the exam, you mainly need to recognize that keys have a defined type.

3) DynamoDB in the AWS Console — step by step

This matches what you saw in the lecture: start on the DynamoDB service page, then create a table, then add items.

  1. 🔎 Open DynamoDB in the AWS Management Console.
  2. ➕ Click Create table.
  3. 🏷️ Enter a Table name (example: Products).
  4. 🔑 Define the Partition key (example: ProductId, type String).
  5. ➕ (Optional) Add a Sort key (example: ReleaseDate, type String).
  6. 💳 Choose a capacity mode (Provisioned or On-Demand).
  7. 🔒 (Optional) Configure encryption.
  8. ✅ Create the table and wait until status is ACTIVE.
  9. 🧾 Go to Explore table items → Create item to insert data.

Example: Creating a Product item

🛒 Table: Products, key: ProductId (String)

{
  "ProductId": "ABC",
  "Title": "A Carpet",
  "Price": 1299,
  "Category": "Home",
  "InStock": true
}

🙂 DynamoDB lets you add attributes freely. Another item might have different fields (e.g., Color, Size) and that’s fine.

Example: Mixed items in the same table

✅ Both items are valid as long as they have ProductId:

{
  "ProductId": "ABC",
  "Title": "A Carpet"
}

{
  "ProductId": "XYZ",
  "Title": "Office Chair",
  "MaxWeightKg": 120,
  "Ergonomic": true
}

4) Capacity & pricing concept (Provisioned vs On-Demand)

  • 📊 Provisioned capacity: you estimate reads/writes and pay for that capacity even if you don’t use it.
  • 🧾 On-Demand: you pay for actual reads/writes performed (great for unpredictable traffic or getting started).

Rule of thumb:

  • 🎯 Stable, predictable workload → Provisioned can be cheaper.
  • 🌊 Spiky/unknown workload → On-Demand is simpler and safer.

💡 The lecture mentions AWS pricing/free tier can change over time. Always verify current free tier limits on AWS pricing pages when doing hands-on practice.

5) Exam-focused notes (CLF-C02)

  • 🧠 DynamoDB = fully managed NoSQL key-value database service.
  • 🏗️ You typically don’t manage servers/instances. You work with tables and items.
  • 🔑 Must understand: partition key (required) and sort key (optional).
  • 💳 Capacity modes: Provisioned vs On-Demand.
  • 🛠️ Access patterns: you interact via AWS tools (Console/CLI/SDK/API), not by writing SQL like RDS.

Common trap question: “Where do you create a DynamoDB database?”

✅ You don’t. You create tables. AWS manages the underlying database infrastructure.

6) Quick check (self-review)

Q1: What is the first thing you create in DynamoDB?
A: A table (not a database instance/cluster).
Q2: What key is required?
A: The partition key.
Q3: What does “schema-less” mean in DynamoDB?
A: Items can have different attributes, but they must include the key attribute(s).
Q4: When is Provisioned often cheaper?
A: When workload (reads/writes) is stable and predictable.
Q5: How do you insert items from the Console?
A: Select table → Explore table items → Create item.

7) Mini glossary

  • 📦 Table: top-level container for DynamoDB records.
  • 🧾 Item: a single record in a table (like a row).
  • 🏷️ Attribute: a field in an item (like a column value).
  • 🔑 Partition key: required primary key component used to identify items.
  • 🧩 Sort key: optional key used with partition key to form a composite key.
  • 💳 Provisioned: pay for reserved capacity.
  • 🧾 On-Demand: pay per request (reads/writes).
