☁️ AWS Databases in the Cloud — “You’ve Got Multiple Options”

Reviewer / Study Guide (Beginner-Friendly) • CLF-C02 Focus • Single-column, A4 print-ready

Topic: Databases Big Idea: SQL vs NoSQL + Self-managed vs Managed Services: EC2, RDS, DynamoDB

1) Big Picture (What this lecture is saying) 🧠

✅ Key message:When you need a database on AWS, you choose:

  • Database type: 🧱 SQL (relational) vs 🧩 NoSQL (non-relational)
  • Hosting approach: 🛠️ Self-hosted (you manage it) vs 🤝 Managed service (AWS manages a lot)

You don’t need deep database theory for the exam—just recognize the categories and the trade-offs.

🎯 Exam mindset:Many questions are really asking: “Should I manage this myself on EC2, or use a managed service like RDS / DynamoDB?”

2) Database Types (SQL vs NoSQL) 🧱🧩

SQL (Relational) 🧱

  • Structured data (tables: rows & columns)
  • Schema-based (you define columns/types up front)
  • Great when you need: consistent structure, relationships, complex queries (joins)

Example:Online store 🛒 — tables like Users, Orders, Products with relationships.

NoSQL (Non-relational) 🧩

  • More flexible structure (often “schema-less” in practice)
  • Optimized for: high scale, simple access patterns, flexible data formats
  • Common models: key-value, document, wide-column, graph (AWS exam usually keeps this high-level)

Example:Session storage / user preferences 🎛️ — fast lookup by key (UserId → settings).

⚠️ Keep it simple:For CLF-C02, you mainly need to recognize that SQL = structured + schema, NoSQL = flexible + often better for huge scale / simple access patterns.

3) Hosting Options (Self-hosted vs Managed) 🛠️🤝

Option What you do What AWS does
Self-hosted DB on EC2 🛠️ Install DB software (e.g., MySQL), configure it, patch it, set up backups, monitoring, scaling, HA, etc. Provides compute (EC2), networking (VPC), storage (EBS/EFS), but you manage the database.
Managed DB service 🤝
(e.g., RDS, DynamoDB)		 Choose engine/settings, connect your app, manage data & access, tune some parameters. Handles much of the “heavy lifting” (maintenance tasks depend on service): backups, patching, replication/HA options, etc.

Self-hosted on EC2: What it feels like (beginner view) 🧑‍🔧

  • You launch an EC2 instance 🖥️
  • You install the DB using SSH or User Data 🧾
  • You configure: users, ports, backups, updates, storage growth, monitoring

Trade-off:Maximum control ✅ but also maximum responsibility 😅

Managed services: Why people choose them 🤝

  • Less operational burden (patching/backups handled or assisted by AWS)
  • Faster to get started ⏱️
  • Lets your team focus on the application, not DB maintenance

Trade-off:Less responsibility ✅ but also less low-level control (by design).

4) Where RDS and DynamoDB fit 🧩

RDS = Relational Database Service 🧱

  • Managed SQL databases (relational)
  • You still configure important options, but AWS helps operate the platform

DynamoDB = Managed NoSQL database 🧩

  • Designed for high scale and fast key-based access
  • Operationally managed by AWS (you focus on data model + access patterns)

📝 Quick association for the exam: “Relational/SQL” → think RDS. “NoSQL” → think DynamoDB.

5) Mini Scenarios (Choose the best option) 🧪

Scenario A: “We want full control and custom setup.” 🧰

Likely pick: Self-host on EC2 🛠️ (you manage install, patching, backups, scaling)

Scenario B: “We want AWS to manage operations; we just want to use the DB.” 🚀

Likely pick: Managed database service 🤝 (e.g., RDS for SQL)

Scenario C: “We need massive scale + simple key lookups.” ⚡

Likely pick: DynamoDB 🧩 (managed NoSQL)

6) Quick Memorize (Cheat Sheet) 🧾

  • 🧱 SQL = structured tables + schema (relational)
  • 🧩 NoSQL = flexible structure (often schema-less)
  • 🛠️ Self-hosted = install + operate yourself (commonly on EC2)
  • 🤝 Managed = AWS handles many ops tasks (e.g., RDS, DynamoDB)
  • 🎓 For CLF-C02: know the concepts & trade-offs, not deep admin commands
